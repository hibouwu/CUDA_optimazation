# 大整数约束判定修复的主集成回归

修复前dependency_bounds用lower > upper + 1e-9判定冲突。globaltimer绝对值约10^18时，加浮点容差会使整数转为浮点并丢失低位，合法相等边可被误拒，真实小逆序也可能被掩盖。C提交e6eda283改为先求lower−upper，再比较1e-9；图边与服务规则不变。

主集成接入9b003dba后，47项相关测试全部通过：大整数相等、1ns真实逆序、正负大整数平移、不定界端点，以及既有小数容差的0/5e-10/1e-9接受、2e-9拒绝。

另在执行前固定每个历史进程的第一个有效物理cluster，共150个原dual调用/150cluster，逐个比较完整节点区间：

- 940350个节点区间在绝对整数anchors与先减整数原点后的anchors下，平移还原后逐字段相同。
- 动态加载修复前696e0b5的原实现，150个绝对值检查全部误拒；同样150个减原点检查全部通过并与新版相同。
- 新版平移失败为0。原raw SHA、物理rank/工作坐标/数量核对保持；此回归仅覆盖每调用预定首cluster，不冒称重跑全部9480cluster。

以前6492800条先后关系检查直接比较整数端点，未用该浮点容差表达式，其零反转结论不受影响。完成边界见证也已先减原点，结论不变。该修复只恢复零lag整数约束应有的平移不变性，不建立硬件计时、观察资格或模型预测能力；带任意小数服务的巨大绝对时间仍应先转换为相对时间，不能把浮点运算当任意精度算术。
