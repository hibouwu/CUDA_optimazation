# 闭区间保守界的独立审查

`verify_prefix.py`不导入B的包络构造器。它以已独立核验的地址覆盖重建2268个初始需求，用请求FIFO的闭式项和未裁剪目的FIFO项核对756个包络。每个报告分段都有原始候选仿射项精确达到，并且全部原始项在该段两端不超过报告项；仿射性因此给出整个闭段的相等，而非仅采样。共1722段通过。

`verify.py`重新计算包络分段交点上的极值，验证630个初始余量/2542个断点检查，最小56.766146993ns。初始全部issue早于τ，A批服务足以填满B批到达前的空隙，每组总服务足以填满下一A批间隔，独立得到源/请求前缀完成=六倍组工作；未使用报告的清空余量倒推出这两个值。

随后显式递推g6..g15：源完成=max(上一组完成,本组最晚issue)+源组服务，请求路径同理；目的完成=max(上一组目的完成,两路径最晚到达)+144ns。逐组均早于最早理想计算时刻，余量至少83.940606305ns。非零producer间隔保留，首refill不被producer_free阻塞；组发起跨度小于τ保证订阅不失效，组间地址不交，源/请求/目的工作均小于288ns。相邻组issue不交叠，因此源和请求顺序保持组顺序，目的递推没有忽略后组插队。

这是首次TC停顿反证：在首次停顿前，compute/commit/release均遵循无停顿递推，才使用该组issue边界；队列界又保证该组赶上compute，矛盾。全部首输入issue早于最早D排队，使D不会排到尚未发出的输入之前。没有假定待证的整段执行已成功。

主线最终报告与B v4重跑一致，报告的参数、包络、全部余量及结论与本次先行快照相同，见`../main-input-path-bound-replay-v1/comparison.json`。单个verify报告仍标为部分检查，以免把某个脚本当成完整证明；两脚本、最终身份比对和上述依赖审查共同支持固定有理数模型的条件排除。
