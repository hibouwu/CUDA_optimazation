# cfg_c共同计算窗口的静态容量参考

固定tile256×128×64、K4096、两consumer WG、FP16 SS到FP32。一个CTA输出tile执行2×256×128×4096=268435456 FLOP，按m64n128k16分解为1024条跨两WG的逻辑MMA，每WG512条、每Ktile八条。实际构建SASS全部HGMMA形状为64x128x16.F32且B转置标记存在；源码/构建SHA绑定。静态分解不是把SASS文本重复块直接当动态指令数。

用同CTA、同SM中两个WG的min(FIRST)到max(MAIN)构成共同计算窗口。FIRST在各角色首MMA前、MAIN在其尾wait/release后；这样覆盖两WG对一个输出tile的全部MMA，而不是把单WG切点当整CTA服务边界。它仍包含软件与等待，非裸指令服务。

先以4096 FLOP/SM-cycle为条件容量参考，工作量/容量=65536cycle，不从本批拟合价格。740092全部4320窗口的min/median/max为65776/65943/67553cycle；相对目标分母的绝对参考误差中位0.6172%、最大2.9858%，无窗口低于参考，差值240..2017cycle。

此参考在看到开发数据后提出，不是冻结留出。4096并未在本轮证明为同卡、同组织下的服务价格或普遍延迟下界；现阶段只说明静态计算量与共同cycle窗口相容。

| 证据 | 指令/组织 | 与当前候选的缺口 |
|---|---|---|
| 历史R00-B | N128、两WG、FP16 SS、两累加链 | 另一GPU，B为K-major，提交/等待循环与目标不完全相同 |
| 历史B布局补测 | 两WG、B MN-major | N256，另一GPU |
| 当前cfg_c | N128、两WG、B MN-major、八条/每Ktile、S4 | 有完整GEMM记录，没有该条件独立同卡指令服务参考 |

不跨卡挪用旧4095.x测量，也不把此窗口当producer预填、W/E/GAP/TAIL、D可见、关键CTA或整调用完成。原观察资格失败全部保留，未做cycle→ns转换。下一步若验证候选，只需针对缺失的同卡指令形状/组织建立独立服务参考，再检查窗口内剩余依赖；不需要重跑完整GEMM矩阵。本轮没有新GPU、拟合或资格判定。
