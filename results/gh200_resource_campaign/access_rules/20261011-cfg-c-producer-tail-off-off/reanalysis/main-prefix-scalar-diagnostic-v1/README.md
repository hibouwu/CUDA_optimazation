# 最后前序event作为调用级比例的条件诊断

预先只检验一个零参数假设：同工作量前序的最后一次event时长倒数，可以代表目标各局部窗口共用的速度状态。不选择其它前序下标、滤波器、拟合系数或重新配对；完整16项前序配对变化均保留。冻结源码SHA绑定并确认timed在event同步和读取后返回，16次前序完成后才启动目标，因此前序值在目标前可获得。

使用740092两臂实际flag0的全部20进程。末次前序event直接预测该进程目标event，绝对相对误差中位0.462078%、最大2.021240%。这是已揭示开发数据上的整调用经验表现，不是新的独立留出，也没有转移为cfg_a/b或跨卡支持。

局部条件检验更宽松：使用目标两臂实际cycle差和arm0实际ns，令预测N1=N0×(C1/C0)×(prefix1/prefix0)。这显式使用了目标信息，不能称为自由预测；反向执行arm的配对也全部保留，不声称arm0已先于arm1可用。4320窗口逐项用Fraction验证预测/实测比等于观测cycle/ns比除以前序比例。

432条L系列的十对条件残差全部仍超过原64/256ns尺度之一；例如pair3两个WG首轮残差中位约755..768ns，第二轮约1151..1162ns。只是失败结构诊断，不输出“修正后通过率”、不替代原门槛、不减基线噪声。

结果区分了两种要求：最后前序event在本批能较好跟踪整调用时间，却不足以提供各轮局部cycle→ns统一比例。prefix event含整个kernel的执行工作与边界，它不是物理频率测量。下一时间接口若仅保存一个调用级scalar，无法由这项证据获得局部支持；需要另有预测前可得的窗口状态或不同且经过验证的观察方式。本轮未选择新状态函数或新增GPU采样。

后续精确共同倍率oracle界已由main-common-converter-bound-v1核验：上述末次前序代理在64/256ns尺度不足，不能推广为所有共同倍率在完整时间5%/10%尺度都不够；off/off共同倍率的最优最大相对残差最高仅0.9199%（仍读取双方目标）。状态估计可用性、表达精度和原观察资格分别保留。
