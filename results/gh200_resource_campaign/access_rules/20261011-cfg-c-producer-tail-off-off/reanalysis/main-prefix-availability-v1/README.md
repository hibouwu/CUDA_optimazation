# 前序输入可用时点与预测保存时点

核对已审查构建的原source/probes/r18.cu，SHA与source_hashes清单相同。timed在748行同步event，750行取得时长，756行返回；固定前序在931行逐次加入warm。目标于935行调用timed，936行才调用report，warmup_us在report内881行输出。

因此前序值在目标前已存在于host，但现有binary没有在目标前对外输出前序包、调用Python预测或保存数值预测。禁止把后处理入口声称为已执行的目标前数值预提交。

较短验证路径是保持binary与前序协议，先冻结确定性规则、校准和允许输入；之后取得新数据，评分仅读取前序字段并记录实际评价时点。它检验预冻结规则对新数据的条件预测，前提是规则/参数/方法不因目标结果修改。这不要求在prefix与target之间加入输出、握手或额外host停顿，也不声称数值预测提前保存。若必须数值预提交，需要改host协议并重新验证相关影响。

该边界与观测资格不同：不读目标不代表局部时间戳有效，同协议新采集也不能自行解除740091/740092失败。C正在独立审查最小有效观察证据；本文件不定义新门槛或授权新留出。
