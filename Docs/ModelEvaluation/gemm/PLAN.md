# 分层 tile 级 DAG 建模路线

更新：2026-10-10。**规划，尚未开始实施。** 本文件维护跨算子、跨硬件的模型结构路线；GH200 固定 CUTLASS 配置的 GEMM 实验与 V10 主线仍由 [access_rules/PLAN](experiments/gh200_sm90/access_rules/PLAN.md) 维护，本路线不改变其顺序。

## 1. 目标

把算子转换成按 [L0–L4](README.md#模型层级) 组织的 tile 级有向无环图（DAG），在带容量、服务率和延迟的资源上模拟事件，输出每个节点的事件时刻、关键路径周期数与完整时间。

- **输入**：编译策略已固定的算子程序。DAG 从降级后的中间表示提取，流水展开、warp specialization、layout、TMA/cp.async 选择都已确定；TileLang 是首个前端，CUTLASS 等实现也按同一接口转换。
- **输出**：各节点的发出、完成、可见、可复用事件，关键 CTA 与关键路径周期数。周期到时间的换算由独立的频率模型完成。
- **与现有模型的关系**：GH200 的 V09 候选在 L2/L3 用聚合参数递推每个 tile，L0、L1 被折叠进校准参数，输入只是条件描述，因此换 kernel 结构就要重新校准，局限见 [V09](experiments/gh200_sm90/access_rules/V09-component-validation.md)。本路线把这两层显式补出。

## 2. 五层与 DAG 的对应

| 层 | DAG 中的对象 | TileLang 对应结构 | GH200 已有参数来源 |
|---|---|---|---|
| L0 基础操作 | 叶节点：一次 TMA 请求、一组 WGMMA、一次 ld/st、一次 barrier；带服务延迟、启动间隔、在途限制 | `T.copy`、`T.gemm`、同步原语 | EXP-05–18、R00、R01 |
| L1 CTA/SM 片上 | 资源与容量：SMEM 缓冲槽、寄存器、驻留、片上共享通路 | `T.alloc_shared`、`T.alloc_fragment` | EXP-09、R03、R11、R12、R16 |
| L2 协作流水 | 子图模板：每个 Ktile 的搬运、计算、释放与 epilogue；stage 表现为缓冲槽复用边 | `T.Pipelined`、warp specialization | R13、R14、R15 |
| L3 完整 kernel | CTA 到 SM 的映射、持久调度、cluster 跨 CTA 边、整卡 L2/HBM、频率 | `T.Kernel` 的 grid 与 cluster | R08、R09、R18、R19、V 系列 |
| L4 算子图 | kernel 间依赖、融合边界、中间张量位置、kernel 间状态 | 模型算子图 | 无 |

五层是嵌套层次，不是每个节点各带一套五层模型：L0 是被模拟的叶节点，L1 是叶节点占用的片上资源，L2、L3 规定节点怎样连接并映射到 SM，L4 只在输入包含多个算子时需要。单个算子只需 L0–L3。

DAG 的边包括三类：数据依赖；缓冲槽的写后读与读后写复用；cluster 多播与 barrier 造成的跨 CTA 依赖。K 循环展开到每个 Ktile，否则无法表达搬运与计算的重叠。新算子主要新增 L0 节点类型和 L2 子图模板；换硬件时替换 `hardware/<设备>/` 中对应层的参数。

## 3. 设计约束

1. **下层代价接收上层条件。** 节点代价是操作属性与服务条件的函数，不是常数。GH200 实测中，行距代价随 grid 规模与 raster 方向变化，边界代价经 cluster barrier 传给伙伴 CTA，L2 命中取决于整卡访问顺序。L3 把竞争程度、缓存状态、频率下传给 L0/L1，必要时迭代到不动点。
2. **频率是 L3/L4 的全局状态。** 它由整卡功率、输入数值和调用历史决定。下层节点只以周期计，在 L3/L4 统一换算时间。
3. **逐层留出。** L0 节点用微基准留出，L2 子图用单 CTA 流水对照，L3 用完整 kernel，L4 用端到端。每层与最终时间分别评分，事件可与打点 trace 逐节点对照，避免误差跨层抵消。
4. **按层选择展开或抽象。** 相互作用强的部分展开到 L0 节点模拟，例如 L2 流水与缓冲复用；已验证的子图压缩为只保留吞吐、延迟与释放事件的复合节点，控制大规模算子图的规模。
5. **无计数器时的边界。** 节点流量只是逻辑请求量。流量放大与服务率下降不可区分的节点，只输出条件服务，不命名物理资源。

## 4. 扩展顺序

| 阶段 | 范围 | 新增内容 | 进入下一阶段的条件 |
|---|---|---|---|
| 1 | GH200 GEMM | 四类节点：加载、WGMMA 组、barrier、输出；在 V09 已测的 cfg_a/b/c 上复现，再测 TileLang GEMM 变体 | 冻结后留出通过；stage 响应与 cluster 伙伴耦合由 DAG 结构自然产生，不靠条件分支 |
| 2 | FlashAttention 前向 | exp、行最大值与求和等 SFU/规约节点，online softmax 子图，causal 造成的不均衡工作 | 逐节点与完整 kernel 的留出通过 |
| 3 | MoE | 路由分布作为输入，分组 GEMM，gather/scatter 与不均衡负载 | 给定路由分布下的留出通过 |
| 4 | 算子图与整模型 | L4：kernel 间 L2 与频率状态、启动开销、融合边界 | 逐 kernel 与端到端分别评分 |
| 并行 | 其他硬件 | 替换各层参数文件，例如 Thor/SM110 | 在新硬件上重新做逐层留出 |

各阶段的误差目标在冻结前写定。完整时间沿用"全组中位 ≤5%、最大 ≤10%"，分项与排序指标按该阶段用途另定；用于配置选择时，排序正确率与绝对误差分开报告。

## 5. 分工与依赖

- **前端与 DAG 生成**：由 TileLang 方向的合作者负责，输入降级后的 IR，输出符合 [统一接口](model/interfaces.md) 事件约定的 DAG。
- **节点代价、资源参数与 trace**：由本仓库提供。GH200 的参数来自 `experiments/gh200_sm90/` 的微基准，验证数据使用逐 tile 打点记录；cfg_a/b/c 的现有数据作为阶段 1 的第一个验收集。
- **外部条件**：计数器权限能使流量相关节点从条件服务变为可归因的服务，但不是阶段 1 的前提。
