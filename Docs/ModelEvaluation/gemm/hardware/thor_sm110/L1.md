## 资源与参数

### 计算资源引用

计算操作的硬件参数引用 [L0](L0.md#计算资源)，不另列一份吞吐上限。

### 存储与缓存容量

| 项目 | 值 | 来源 |
|---|---|---|
| L1/纹理缓存与 SMEM 统一容量 | 256 KiB/SM，由 L1 与 SMEM 分配使用 | [计算能力 11.0 规格][cuda-spec] |
| SMEM 最大容量 | 228 KiB/SM | [CC 11.0 官方规格][cuda-spec]；[NCU 设备属性][device-ncu]一致 |
| 每 CTA 的 SMEM 上限 | 默认 48 KiB；显式 opt-in 后最多 227 KiB | [CC 11.0 官方规格及脚注][cuda-spec]；[NCU 设备属性][device-ncu]一致 |
| SMEM bank 数 | 32 | [CUDA 架构规格][cuda-spec] |
| TMEM 单次分配上限 | 512 列；按 128 lanes × 32 bit/列计为 256 KiB | [PTX 分配规则][tmem-alloc]、[TMEM 组织][tmem-spec] |
| 寄存器容量 | 65536 个 32-bit 寄存器/SM，即 256 KiB/SM | [CC 11.0 官方规格][cuda-spec]；[NCU 设备属性][device-ncu]一致 |

- L1 与 SMEM 共用 256 KiB/SM，不能再叠加 228 KiB SMEM。
- SMEM carveout 可选 0、8、16、32、64、100、132、164、196、228 KiB；增大 SMEM 分配会减少 L1 可用空间。[CUDA 规格][cuda-spec]
- 每 CTA 使用超过 48 KiB SMEM 时，需要动态分配并显式 opt-in；227 KiB 已是用户可用上限，无需再扣除 1 KiB 系统保留量。

#### TMEM 分配

按 PTX ISA 9.0 的 `tcgen05.alloc` 规则，适用于 `sm_110a`：

| 参数 | 规定 |
|---|---|
| 分配单位 | 32 列，每列同时分配全部 128 lanes；对应 16 KiB |
| 单次分配列数 | 32、64、128、256、512，即 16、32、64、128、256 KiB |
| 分配线程 | `cta_group::1` 由 CTA 内一个完整 warp 执行；`cta_group::2` 由两个 peer CTA 各一个 warp 共同执行 |
| 空间不足 | `tcgen05.alloc` 阻塞，直到可分配 |
| 连续分配 | 同一 CTA 按执行顺序发起的后一次分配列数不能大于前一次 |
| 释放 | kernel 退出前须显式 `tcgen05.dealloc`；放弃分配许可后不可再次分配 |

来源：[Tensor Memory Allocation][tmem-spec]、[分配与释放指令][tmem-alloc]。256 KiB 在这里表示单次分配上限；PTX 的 512 列 × 128 行结构说明显式标注 `sm_100a/sm_100f`，不据此另行断言 Thor 的每 SM 物理总容量或多 CTA 可同时分配的总量。

### 带宽与数据搬运

| 访问路径 | 方向或参数来源 | 本层描述的量 |
|---|---|---|
| 线程读取 SMEM | SMEM → 寄存器 | 字节数、访问宽度、有效带宽与 bank conflict |
| 线程写入 SMEM | 寄存器 → SMEM | 字节数、访问宽度、有效带宽与 bank conflict |
| 计算指令取数 | 引用 [L0 数据供给需求](L0.md#数据供给需求) | 继承已计入的访问需求；本层补充同时访问时的竞争 |
| `tcgen05.ld` 读回 | TMEM → 寄存器 | 读回宽度、参与 warp 数、延迟与有效带宽 |

各路径使用 [L0 数据搬运操作](L0.md#数据搬运操作) 的事件定义；本层保留片上资源参数，并根据线程/数据映射推导访问需求。各路径记录独立访问与同时访问的条件。线程 SMEM load/store 带宽不能替代 Tensor Core 取数或 TMA 写入 SMEM 的带宽。

结果写入 SMEM 仅在输出接口要求时计入。指令用法见 [PTX 辅助函数][ptx] 与 [多级流水线实现][pipeline]；具体 tile、对齐与布局选择写入对应方案。

#### 历史 SMEM 带宽

以下为各自 NCU 验证记录配套的 app 计时结果，单位均为 B/cycle/GPU；不是 Tensor Core/外存汇总中的 10 次重复中位数。

| 资源 | 访问方式 | 实测值 | NCU 模型峰值／估计 |
|---|---|---:|---:|
| SMEM 标量读取 | `ld.shared.u32`，stride 1，无 bank conflict | 1056.451 | 约 2572⁵ |
| SMEM 标量写入 | `st.shared.u32`，stride 1，无 bank conflict | 821.227 | 约 2567⁵ |
| SMEM 向量读取 | 本地 `uint4`，16 B/线程 | 2400.191 | — |
| SMEM 向量写入 | 本地 `uint4`，16 B/线程 | 2173.339 | — |

5. [SMEM 标量 NCU 记录][smem-ncu]：分别由 `1056.451 / 41.07%` 和 `821.227 / 31.99%` 估计，利用率来自 shared LSU wavefront；没有直接的 SMEM 字节计数，因此仅作为该访问方式的粗略估计。

向量结果来自 [local-read/local-write 记录][smem-vector]。这些 SMEM 测量针对线程的 load/store，不替代 TMA 写入或 Tensor Core 读取 SMEM 的带宽。

#### 历史 TMEM 读回带宽

来自同一份 [10 次重复中位数汇总][rates]。单 SM 与整卡值分别标明；目前没有同口径的可靠理论上限。

| 路径 | 测量条件 | 单位 | 实测 | 理论上限 |
|---|---|---|---:|---:|
| TMEM → 寄存器 | x8，1 个读回 warp/CTA | B/cycle/GPU | 435.576 | — |
| TMEM → 寄存器 | x8，4 个读回 warp/CTA | B/cycle/GPU | 12551.327 | — |
| TMEM → 寄存器 | x16，1 个读回 warp/CTA | B/cycle/GPU | 853.003 | — |
| TMEM → 寄存器 | x16，4 个读回 warp/CTA | B/cycle/GPU | 21758.994 | — |

TMEM 测试为 128 线程/CTA、1 CTA/SM、20 SM 聚合，详见 [读回测量条件][tmem-contract]。

以上整卡聚合值保留原始统计范围，不能直接作为单 SM 同时执行不同服务时的带宽。

### 驻留与指令发射

线程、warp、CTA 与寄存器上限采用 [CUDA 13.1 的 CC 11.0 规格][cuda-spec]，与已有 [NCU 设备属性][device-ncu]交叉核对；每 CTA 系统保留 SMEM 来自该设备记录。CTA 即 CUDA thread block。官方表中的 K/KB 为 1024 单位，本文写为 KiB。

| 参数 | 上限或粒度 |
|---|---:|
| 每 warp 线程数 | 32 |
| 每 CTA 线程数 | 1024 |
| 每 SM 驻留线程数 | 1536 |
| 每 SM 驻留 warp 数 | 48 |
| 每 SM 驻留 CTA 数 | 24 |
| 每线程寄存器数 | 255 个 32-bit 寄存器 |
| 每 CTA 寄存器数 | 65536 个 32-bit 寄存器 |
| 每 CTA 系统保留 SMEM | 1 KiB |

实际驻留数同时受线程数、寄存器和 SMEM 占用限制；使用 TMEM 的方案还受其分配约束限制，单次分配上限不能代替多 CTA 总容量。这些上限不能保证同时达到。

warp 调度、访存发射及辅助指令的有效服务与共享关系仍待确定；操作需求按 [L1 发射接口](../../model/L1.md#驻留与指令发射)给定。

### 同步约束

| 同步机制 | 关联对象 | 本层约束 |
|---|---|---|
| CTA barrier | 参与同步的线程 | 到达条件与等待时间 |
| `mbarrier` / 异步完成通知 | 输入缓冲、搬运与消费者 | 使用输入前等待搬运完成；复用缓冲前等待消费者完成 |
| 异步 MMA 完成等待 | 累加状态与计算结果 | 引用 L0 完成事件，确定读回和存储复用时刻 |

软件缓冲及同步状态占用上述存储资源，不单独增加容量。TMA 路径见 [L0](L0.md#数据搬运操作)，全局路径参数见 [L2](L2.md#带宽与数据搬运)；输入供给与缓冲复用的组合关系见 [L2 通用模型](../../model/L2.md#流水线状态与同步约束)。

## 待确定参数

| 参数 | 当前缺口 |
|---|---|
| TMEM 多 CTA 并发容量 | 上述官方分配规则已明确；Thor 每 SM 可供多个 CTA 同时分配的总量仍需进一步依据 |
| 条件化服务参数 | 待确定指定指令、访问形状与并发条件下的延迟、启动间隔及共享服务限制；方案专用的组合拟合参数保存在方案侧 |

其中 TMA 完成时间由其 L0 服务、L2 流水线状态及 L3 共享条件共同确定；本层只补充片上缓冲、计算和读回的约束。
