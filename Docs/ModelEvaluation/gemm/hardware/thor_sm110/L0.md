## 资源与参数

### 计算资源

| 计算路径 | 适用条件 | 服务参数与状态 |
|---|---|---|
| CUDA Core：FMA | 指定精度的标量或向量计算 | 计算量、完成延迟、启动间隔、依赖链吞吐量；待确定 |
| Tensor Core：`tcgen05.mma` | 按精度、MMA 形状与操作数布局区分，结果进入 TMEM | 历史整卡吞吐见下表；指令延迟、启动间隔待确定 |

指令用法见 [PTX 辅助函数][ptx] 与 [多级流水线实现][pipeline]；具体 tile、对齐与布局选择写入对应方案。

#### 官方计算规格

核对日期：2026-09-30；产品规格针对 T5000，输入类型依据 CUDA 13.1 的 CC 11.0 表。

| 项目 | 官方值 | 用于模型时的口径 |
|---|---|---|
| CUDA Core 数量 | 2560 | 整个 T5000 GPU 的产品数量；不是指令延迟或单 warp 服务率 |
| Tensor Core 代际 | 第五代 | 所支持的指令形式仍需按 SM110 ISA 选择 |
| AI 计算性能 | 2070 TFLOP/s，FP4 Sparse | 官网产品标称；不能用作稠密 FP32/FP16 GEMM 的吞吐量 |
| Tensor Core 输入类型 | TF32、BF16、FP16、FP8、FP6、FP4、INT8 | 架构级能力集合；不同指令的形状、布局、缩放与累加限制另查 ISA；该表不列 FP64 Tensor Core |

来源：[T5000 产品规格][product]、[CUDA 计算能力表 33][cuda-spec]。本次查阅的[官方原生算术吞吐表][arithmetic]未列 CC 11.0 专栏，因此不套用 CC 10.x/12.x 的每 SM 算术速率。产品核心数量与 FP4 标称值不能补齐 FMA 延迟、启动间隔或并发服务参数。

#### 历史计算吞吐

下表为仓库历史微基准的 10 次外部重复测量中位数，来自 2026 年 8 月采集汇总。每周期值按实测速率除以 1.575 GHz 的 SM 核心时钟归一化，均为整卡值；kFLOP 表示 1000 次浮点运算。

| 资源 | 测量条件 | 单位（整卡） | 实测 | 理论／条件上限 |
|---|---|---|---:|---:|
| FP16 Tensor Core | MMA 形状 M128N64，纯计算 | kFLOP/cycle | 108.590 | 164.127¹ |
| FP16 Tensor Core | MMA 形状 M128N128，纯计算 | kFLOP/cycle | 130.712 | 164.127¹ |
| FP16 Tensor Core | MMA 形状 M128N256，纯计算 | kFLOP/cycle | 131.130 | 164.127¹ |

1. FP16：沿用[资源总表][rates]中由稀疏 FP16 规格按 2:1 换算的稠密条件上限，再按 1.575 GHz 归一化。这是整卡计算上限，不表示每种 MMA 形状都能达到。

整卡纯计算结果保留其原始统计范围，不能直接作为单 CTA 或单 SM 的服务参数。其余精度见 [性能与带宽资源总表][rates]。

### 数据搬运操作

| 操作 | 路径与输入 | 服务边界及参数 |
|---|---|---|
| `ld.global` / `st.global` | GMEM 与寄存器；访问宽度、对齐、线程地址和缓存策略 | 发射、事务需求及对应消费者可用/存储完成条件；逻辑字节不直接等于外存流量 |
| `ld.shared` / `st.shared` | SMEM 与寄存器；线程映射、宽度、布局 | 完成延迟、启动间隔、广播与 bank 冲突条件；实际服务参数引用 L1 |
| `cp.async` | GMEM → SMEM；线程级异步复制 | 发出、分组与完成等待分别描述；线程可见性与 CTA 合作所需同步须满足所选语义 |
| TMA | 所选 bulk/tensor 搬运形式、方向、形状、stride 与完成机制 | 请求发出与数据可用分别建模，记录各路径需求、在途条件及缓冲释放依据；不假定固定每请求延迟 |
| TMEM 搬运（按需） | 所选 `tcgen05.ld` / `tcgen05.st` / `tcgen05.cp` 形式与合法端点 | 按指令确认参与范围、方向、形状和完成条件；不与 MMA 自身取数或其他通路混用服务率 |

片上路径参数见 [L1](L1.md#带宽与数据搬运)，全局存储与搬运参数见 [L2](L2.md#带宽与数据搬运)；完成事件采用 [L0 通用定义](../../model/L0.md#数据搬运操作)。

### 同步与完成通知操作

| 操作 | 输入条件 | 本层输出与上层责任 |
|---|---|---|
| CTA / warp barrier | 参与线程与到达事件 | 状态及发射/通知成本；最后参与者尚未到达导致的等待由组合模型推导 |
| `mbarrier` | 所选指令要求的参与/事务状态及异步完成事件 | 状态更新与满足条件的事件；不能用发出时刻替代完成 |
| 异步 copy/MMA 提交与等待 | 指令组、在途限制、依赖的完成事件 | 描述合法完成语义及控制需求；轮询或等待的实际指令需求按方案另计 |
| fence（按需） | 指定作用范围与访存顺序 | 规定顺序/可见性关系，不自动表示所有异步操作完成 |

### 数据供给需求

| 供给路径 | 方向 | 需求与边界 |
|---|---|---|
| 寄存器操作数供给 | 寄存器 → 计算指令 | 按指令形式记录操作数需求、供给条件 |
| SMEM 操作数供给 | SMEM → 所选 MMA 指令 | 记录每次计算取数需求，不等同于线程 SMEM load 带宽 |
| TMEM 操作数与累加访问 | TMEM ↔ 所选 TCGen05 计算指令 | 按指令形式记录读写需求；不等同于 `tcgen05.ld` 读回 |

TCGen05 累加器使用 TMEM，分配规则见 [L1](L1.md#tmem-分配)；搬运端点、同步状态和其他临时值按实际存储位置计量。

### 发射与依赖约束

| 约束对象 | 需要描述的量 | 组合时的条件 |
|---|---|---|
| 指令发射 | 发射开销、持续启动间隔 | 注明 warp、warpgroup、SM 或整卡统计范围 |
| 累加依赖 | 依赖链延迟、独立链数量 | 区分依赖链与独立指令流 |
| 异步计算 | 允许的在途计算、完成事件与等待条件 | 只在所选指令路径使用时计入；未核实的限制保留待确定 |

地址计算、类型转换和循环控制按 [L0 辅助操作](../../model/L0.md#辅助计算与控制操作)定义需求；本设备相应延迟、启动间隔及与其他操作的共享关系仍待确定。

## 待确定参数

各操作在指定形状、路径和并发条件下的完成延迟、启动间隔、在途限制及联合服务仍待确定。已有历史吞吐量保留原统计范围，不能单独推导所有这些参数，也不能默认不同操作的独立速率可同时达到。
