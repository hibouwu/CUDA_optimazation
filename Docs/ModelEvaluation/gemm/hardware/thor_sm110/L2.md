## 资源与参数

### 计算资源引用

计算与片上资源引用 [L0](L0.md) 和 [L1](L1.md)；mainloop、epilogue 及缓冲状态关系统一见 [L2 通用模型](../../model/L2.md)。

### 存储与缓存容量

产品规格按 2026-09-30 官网 T5000 栏记录。LPDDR5X 容量与带宽保留官方 GB/GB/s 单位，不能直接当成 CUDA 可分配字节数；L2 cache 容量仍引用本地设备记录。

| 存储资源 | 容量与范围 | 来源 |
|---|---|---|
| 外存 | 128 GB、256-bit LPDDR5X，整机共享 | [产品规格][product] |
| L2 cache | 32 MiB，GPU 共享 | [设备记录][device] |
| 各 SM 的硬件 L1 cache | 引用统一空间与 carveout 约束，不另加容量 | [L1 存储与缓存容量](L1.md#存储与缓存容量) |

矩阵和工作区是上述存储的占用对象；分别记录工作集大小、初始缓存状态、命中与复用，普通 global 与 TMA 路径分别描述。

Thor 的外存是整机共享的 LPDDR5X。GMEM 是访问空间，不能把所有 global 请求都算作实际 LPDDR 流量；旧模型中的 `hbm.*` 名称不表示 Thor 配有 HBM。

### 带宽与数据搬运

本节保存全局路径的资源参数；操作语义与完成事件统一见 [L0 数据搬运操作](L0.md#数据搬运操作)。按[资源 ID 与计账约定](../../model/interfaces.md#3-共享资源)引用参数，资源共享范围不因本层调用次数而复制。

| 访问路径 | 范围与方向 | 服务参数及约束 |
|---|---|---|
| LPDDR5X 访问 | 外存读写；多 SM 共享 | 实际外存流量、延迟、读写混合带宽 |
| L2 cache 访问 | 多 SM 共享的缓存通路 | 实际流量、命中条件、读写联合限制 |
| 普通 global load/store | GMEM ↔ 寄存器，按缓存策略区分 | 访存合并、缓存命中、指令发射与数据服务；输入输出分别计量 |
| TMA 搬运 | 按所选指令的方向区分；片上端引用 L1 | payload、stride、对齐、描述符、布局、延迟及在途请求条件 |
| cluster / DSM 通路（按需） | 协作 CTA 间跨 SM 访问 | 仅使用该通路时增加流量、带宽与完成依赖 |

| 规格项 | 值 | 来源 |
|---|---|---|
| 外存标称带宽 | 273 GB/s，整机共享 LPDDR5X 的产品标称带宽；非 GPU 保证有效带宽 | [产品规格][product] |

#### 全局访问路径

| 路径 | 主要约束 |
|---|---|
| 普通 global load → L1/L2 → 寄存器 | `.ca` 允许 L1 缓存；`.cg` 绕过 L1 |
| TMA → SMEM | 搬运形状、地址对齐、描述符和 SMEM 布局必须匹配 |

指令用法见 [PTX 辅助函数][ptx] 与 [多级流水线实现][pipeline]；具体 tile、对齐与布局选择写入对应方案。

#### 历史外存与 L2 cache 带宽

下表为仓库历史微基准的 10 次外部重复测量中位数，来自 2026 年 8 月采集汇总。每周期值按实测速率除以 1.575 GHz 的 SM 核心时钟归一化，均为整卡值。

| 资源 | 测量条件 | 单位（整卡） | 实测 | 理论／条件上限 |
|---|---|---|---:|---:|
| 外存读取 | 独立读取测试 | B/cycle | 161.008 | 受下列读写总带宽约束 |
| 外存写入 | 独立写入测试 | B/cycle | 127.719 | 受下列读写总带宽约束 |
| 外存读写合计 | 产品规格 | B/cycle | — | 173.333² |
| L2 读取 | L2 热工作集，独立读取 | B/cycle | 955.626 | 1024³ |
| L2 写入 | L2 热工作集，独立写入 | B/cycle | 346.296 | 512³ |

2. 外存：273 GB/s ÷ 1.575 GHz = 173.333 B/cycle，约束读写流量之和。
3. L2：由 NCU 吞吐与利用率反推，计算见“L2 cache 峰值的反推”。

独立读、写速率不保证同时达到；其余精度和读写混合比例的测量见 [性能与带宽资源总表][rates]。

#### 历史硬件 L1 cache 访问带宽

以下为各自 NCU 验证记录配套的 app 计时结果，单位均为 B/cycle/GPU；不是 Tensor Core/外存汇总中的 10 次重复中位数。

| 资源 | 访问方式 | 实测值 | NCU 模型峰值／估计 |
|---|---|---:|---:|
| L1 命中读取 | `ld.global.ca.v4.u32`，32 KiB/CTA，预热 | 2535.199 | 约 10240⁴ |
| L1TEX store 路径 | `st.global.wb.v4.u32` | 434.349 | 约 10240⁴ |

4. [L1 NCU 记录][l1-ncu]：读取峰值由 `2564.800 / 25.05% ≈ 10240` 反推；写路径由 `450.970 / 4.40% ≈ 10240` 反推。写路径包含向 L2 的流量，不是纯 L1 cache 写端口带宽。

硬件 L1 cache 的容量分配约束见 [L1 片上容量](L1.md)；本节记录 global 访问路径上的缓存服务，不表示 TMA 必经硬件 L1 cache。

#### 历史 TMA 带宽

来自同一份 [10 次重复中位数汇总][rates]。单 SM 与整卡值分别标明；目前没有同口径的可靠理论上限。

| 路径 | 测量条件 | 单位 | 实测 | 理论上限 |
|---|---|---|---:|---:|
| TMA → SMEM | 热数据，`tma.smem_ingress.per_sm` | B/cycle/SM | 122.772 | — |
| 外存 → TMA → SMEM | 冷数据，`tma.hbm` | B/cycle/GPU | 117.784 | — |

TMA 两行对应已有 tc5a 搬运测试，不能直接外推到任意 payload、stride 和在途请求数，详见 [TMA 测量条件][tma-contract]。

#### L2 cache 峰值的反推

[NCU 记录][ncu] 中，每 sector 为 32 B；使用读、写各自的 `lts__t_sectors_op_read/write.sum.per_cycle_elapsed` 和 `pct_of_peak_sustained_elapsed`：

\[
B_{\mathrm{peak}}=\frac{\text{sector/cycle}\times32}{\text{峰值利用率}/100}.
\]

| 方向 | sector/cycle | 峰值利用率 | 反推峰值（B/cycle/GPU） |
|---|---:|---:|---:|
| 读 | 29.83 | 93.22% | 约 1024 |
| 写 | 7.32 | 45.73% | 约 512 |

写方向采用 45.73%，不是综合 LTS throughput 的 48.29%。反推值有计数器舍入误差，表示 NCU 模型峰值；不表示读写可同时达到各自峰值。
