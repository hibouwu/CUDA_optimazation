## Cluster 驻留与调度

| 项目 | 已确认规则 | GH200 当前参数状态 |
|---|---|---|
| 协作范围 | cluster 内 CTA 保证在同一个 GPC 内共同调度 | 不等于任意空闲 SM 可自由拼成 cluster |
| 可移植 cluster 大小 | CUDA 定义最多 8 个 CTA；较小设备或 MIG 配置可能更低 | 对给定 kernel/launch 配置用 `cudaOccupancyMaxPotentialClusterSize` 核对 |
| 非可移植大小 | 必须得到设备支持并按要求 opt-in | 不把 Hopper 指南中 H100 的 16 CTA 直接作为当前 GH200 的已核实能力 |
| 实际驻留 cluster 数 | 受 kernel 的线程、寄存器、SMEM、cluster 形状及设备资源分布约束 | 采用 `cudaOccupancyMaxActiveClusters` 的目标配置结果；不能仅算 `SM数/cluster大小` |
| grid 形状 | 启用 cluster 的 grid 仍以 CTA 计数，各维须满足对应 cluster 维度的整除要求 | 与问题矩阵尺寸、边界 tile 和输出任务数分开 |

依据：[CUDA Thread Block Clusters][clusters]、[occupancy API][occupancy-api]、[Hopper 指南][hopper]。这些是单 GPU 内部约束，Batched / Grouped 与 Distributed 的暂缓状态不排除它们。

## 运行与服务参数的使用

| 项目 | 当前记录 | 对模型的限制 |
|---|---|---|
| 设备规模 | 已有归档为 132 SM | 本次任务可用范围仍是输入，不能假定任何并发作业独占全部 SM |
| 时钟口径 | 复测的局部周期来自 `clock64`；旧整卡结果还使用 1.98 GHz 参考频率 | 参考频率不代表锁频；不同 SM 的时钟时间戳不能直接相减 |
| 计算复测 | 代表配置的经验率见 [L0](L0.md#已有复测的条件化计算服务) | 全 GPU 试验中的平均 SM 覆盖周期服务率不是整卡完成时间预测 |
| 调度与共享 | 已有 grid/CTA 和 cluster 的资源约束 | 任务分派成本、尾波与 mainloop/epilogue 竞争仍按实际方案建立关系 |

来源：[微基准测试审查][audit]。计时前的分配、host 描述符准备和 API 调用按问题边界处理；kernel 内初始化、同步、排空和必要释放仍属于执行需求。当前未采集 cluster、TMA 供给或完整 GEMM 的组合服务参数。

## 待确定参数

已有归档报告 132 SM，L1 的架构驻留上限与 L2 的产品容量/带宽已补齐。具体 kernel 的可用 SM、cluster 上限及驻留、占用与调度条件，以及 L0–L2 服务参数的并发适用域仍需确定。
