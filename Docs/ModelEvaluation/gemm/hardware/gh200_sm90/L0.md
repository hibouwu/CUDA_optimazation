# GH200/SM90：L0 基础操作参数与指令约束

[硬件入口](README.md) · [L0 通用模型](../../model/L0.md) · [统一接口](../../model/interfaces.md)

新增约束核对日期：2026-09-30。指令规则固定引用 PTX ISA 8.8，并按 `sm_90` / `sm_90a` 的 Target ISA Notes 筛选；新版 PTX 中仅供 Blackwell 使用的形式不纳入。

## 资源与参数

### 计算资源

| 计算路径 | 适用条件 | 服务参数与状态 |
|---|---|---|
| CUDA Core：FMA | 指定精度的标量或向量计算 | 官方吞吐上限见下表；完成延迟、启动间隔及依赖链有效服务仍待确定 |
| Tensor Core：`mma.sync` | 32 线程 warp；A/B 与累加片段在寄存器 | 已有部分配置的经验服务率；裸指令延迟与启动间隔待确定 |
| Tensor Core：`wgmma.mma_async` | 128 线程 warpgroup；B 来自 SMEM，A 按形式来自 SMEM 或寄存器；累加器在寄存器 | 已有部分配置的经验服务率；异步完成、提交与等待规则见下文 |

#### 官方单 GPU 计算规格

核对日期：2026-09-30；采用 GH200 数据表第 4 页的单 GH200 栏，保留原表舍入。TFLOP/s 与 TOPS 不混用。

| 计算路径 | 稠密产品值 | 稀疏产品值 | 单位 |
|---|---:|---:|---|
| FP32 CUDA Core | 67 | — | TFLOP/s |
| FP64 CUDA Core | 34 | — | TFLOP/s |
| FP64 Tensor Core | 67 | — | TFLOP/s |
| TF32 Tensor Core | 494 | 989 | TFLOP/s |
| FP16 / BF16 Tensor Core | 990 | 1979 | TFLOP/s |
| FP8 Tensor Core | 1979 | 3958 | TFLOP/s |
| INT8 Tensor Core | 1979 | 3958 | TOPS |

以上为[官方产品算力][datasheet]，稀疏列带原表 sparsity 条件，不能用于本目录默认的稠密 GEMM。它们不描述某一种 MMA 形状、warpgroup 或实际运行频率下的持续服务。

| CC 9.0 原生算术路径 | 官方理论吞吐 | 按 FMA=2 FLOP 换算 |
|---|---|---|
| FP32 add / mul / FMA | 128 个标量结果/cycle/SM | FMA 为 256 FLOP/cycle/SM |
| FP64 add / mul / FMA | 64 个标量结果/cycle/SM | FMA 为 128 FLOP/cycle/SM |

来源：[CUDA Best Practices 表 5][arithmetic]。这是满负载理论吞吐；不能把 128 个标量结果误读为 128 条 warp 指令，也不能由该值推出单条指令延迟。整卡预测仍需考虑实际可用 SM 与 L3 调度。

CC 9.0 的 Tensor Core 输入能力集合为 FP64、TF32、BF16、FP16、FP8、INT8；不包含 FP6/FP4，具体 MMA/WGMMA 形式的类型、布局和累加限制另按 ISA 判断。[CUDA 计算能力表 33][cuda-spec]

#### 计算路径的参与范围

| 路径 | SM90 上的使用约束 | 参数解释 |
|---|---|---|
| FMA | 逐线程执行；标量与 `f16x2` / `bf16x2` 等打包形式分别计数 | 线程运算数、warp 指令数及有效 FLOP 分开 |
| `mma.sync.aligned` | 整个 warp 一致执行；形状、精度及片段映射须匹配 | `wmma.mma` 不另算一套 Tensor Core 资源 |
| `wgmma.mma_async` | `sm_90a`；四个连续 warp 构成 warpgroup，起始 warp 编号为 4 的倍数 | 不把一个 warpgroup 当成完整 SM；没有 FP64 WGMMA，FP64 矩阵路径使用合法 `mma.sync` 形式 |

依据：[MMA][mma]、[WGMMA][wgmma-isa]。普通寄存器访问与异步 WGMMA 使用之间遵守 `wgmma.fence` 和完成等待；SMEM 经普通 store 写入后供异步路径消费，还须满足跨 proxy 的可见性条件。两类 fence 不互相替代。

#### 已有复测的条件化计算服务

来源为 2026-09-30 ROMEO `romeo-a057` 的[审查复测][audit-report]和[结构化统计][audit-summary]，本次仅核对并引用归档，未重新运行 GPU。CUDA 12.9，7 个预先指定配置、3 个循环长度、12 轮交错采样；下表选取 65536 轮循环的中位数。

FMA/MMA 配置为 256 线程、8 条独立累加链、每链每轮 16 次操作；WGMMA 为 128 线程、2 条累加链、每轮每链 16 条 MMA 后 commit。后者每个 group 有 32 条 MMA，wait 参数表示保留的未完成 group 条件，不是 group 内指令条数。WGMMA A/B 在 SMEM 中按测试布局反复使用，没有 GMEM 供给或 TMA 流水。

| 配置 ID / 指令 | 单 CTA：FLOP/clock64 cycle | 全 GPU 负载：FLOP/SM 覆盖周期 |
|---|---:|---:|
| `f32_c8_q16_t256_p0`<br>FP32 FMA | 245.448 | 247.807 |
| `f64_c8_q16_t256_p0`<br>FP64 FMA | 124.830 | 127.214 |
| `f16x2_c8_q16_t256_p0`<br>FP16×2 FMA | 250.136 | 254.307 |
| `mma_f16_c8_q16_t256_p0`<br>FP16→FP32 MMA，M16N8K16 | 2712.990 | 2712.992 |
| `wgmma_f16_c2_q16_t128_p0`<br>FP16→FP32 WGMMA，M64N64K16，wait 0 | 3892.570 | 4095.895 |
| `wgmma_f16_c2_q16_t128_p3`<br>同形 WGMMA，wait 3，预热例外 | 4095.937 | 4095.521 |
| `wgmma_f16_c2_q16_t128_p7`<br>同形 WGMMA，wait 7 | 4095.937 | 4095.521 |

全 GPU grid 为 `SM 数 × min(4, occupancy API 的 CTA/SM 上限)`。第二列是单 CTA 本地计时；第三列为总工作量除以各 SM 覆盖区间长度之和，包含区间内空隙，**不是整卡 makespan 吞吐量**，不能乘以 132 当作已测整卡峰值。原始配置、占用和逐 CTA 记录见[复测源码][audit-source]与统计。

计时包含循环控制、必要提交/等待、末尾归约、SMEM 捕获及 CTA barrier，排除输入初始化和最终 GMEM 输出；不是纯指令完成延迟或独立发射端口间隔。正式性能输入为固定简单值，另做的非均匀输入验证不等于已经测量其性能。

证据限制随参数保留：wait 3 的完整 kernel 时间预热未在 30 次内达到 CV≤1%；NCU 返回 `ERR_NVGPUCTRPERM`，没有动态指令计数；12 轮来自同一次进程与资源分配。未复测的精度、形状与初始短链结果仍为探索性材料，详见[测试审查][audit]。这些经验值仅适用于相应计算供给与并发条件；L1 中计算自身已包含的取数与竞争不再重复计费。

### 数据搬运操作

| 操作 | 路径与输入 | 服务边界及参数 |
|---|---|---|
| `ld.global` / `st.global` | GMEM 与寄存器；访问宽度、对齐、线程地址和缓存策略 | 发射、事务需求及对应消费者可用/存储完成条件；逻辑字节不直接等于外存流量 |
| `ld.shared` / `st.shared` | SMEM 与寄存器；线程映射、宽度、布局 | 完成延迟、启动间隔、广播与 bank 冲突条件；实际服务参数引用 L1 |
| `ld.local` / `st.local` | 寄存器 ↔ 线程私有 local 地址空间 | 溢出、栈或局部数组产生的需求；复用缓存/外存资源，容量归属见 [L1](L1.md#寄存器分配与溢出) |
| `ldmatrix` / `stmatrix` | SMEM ↔ warp 的寄存器片段 | SM90 的 `.m8n8`、`.b16`、`.x1/.x2/.x4`；整 warp 一致执行、行地址按 16 B 对齐；不套用 Blackwell 的 `.b8` 等扩展 |
| `shfl.sync` | warp 内寄存器数据交换 | 按参与 mask、源 lane 与依赖计量；属于片上指令服务，不增加 SMEM 容量或外存带宽 |
| `ld.param` / `ld.const`（按需） | kernel 参数、标量或只读元数据 | 记录实际参数访问与缓存路径；不能将描述符视为零成本数据 |
| `cp.async` | GMEM → SMEM；线程级异步复制 | 发出、分组与完成等待分别描述；线程可见性与 CTA 合作所需同步须满足所选语义 |
| TMA | 所选 bulk/tensor 搬运形式、方向、形状、stride 与完成机制 | 请求发出与数据可用分别建模，记录各路径需求、在途条件及缓冲释放依据；不假定固定每请求延迟 |

矩阵搬运依据：[ldmatrix][ldmatrix]、[stmatrix][stmatrix]；warp 内交换依据：[shfl.sync][shfl]。按实际选择的形式记录请求，不能把普通 SMEM load 的速率直接赋给所有矩阵搬运指令。

片上路径参数见 [L1](L1.md#带宽与数据搬运)，全局存储与搬运参数见 [L2](L2.md#带宽与数据搬运)；完成事件采用 [L0 通用定义](../../model/L0.md#数据搬运操作)。

### 同步与完成通知操作

| 操作 | 输入条件 | 本层输出与上层责任 |
|---|---|---|
| CTA / warp barrier | 参与线程与到达事件 | 状态及发射/通知成本；最后参与者尚未到达导致的等待由组合模型推导 |
| `mbarrier` | 所选指令要求的参与/事务状态及异步完成事件 | 状态更新与满足条件的事件；不能用发出时刻替代完成 |
| 异步 copy/MMA 提交与等待 | 指令组、在途限制、依赖的完成事件 | 描述合法完成语义及控制需求；轮询或等待的实际指令需求按方案另计 |
| fence（按需） | 指定作用范围与访存顺序 | 规定顺序/可见性关系，不自动表示所有异步操作完成 |

### 数据供给需求

| 供给路径 | 方向 | 需求与边界 |
|---|---|---|
| 寄存器操作数供给 | 寄存器 → 计算指令 | 按指令形式记录操作数需求、供给条件 |
| SMEM 操作数供给 | SMEM → 所选 MMA 指令 | 记录每次计算取数需求，不等同于线程 SMEM load 带宽 |

WGMMA 的 A 操作数来源按指令形式区分；本架构不引入 Thor 的 TMEM。

### 发射与依赖约束

| 约束对象 | 需要描述的量 | 组合时的条件 |
|---|---|---|
| 指令发射 | 发射开销、持续启动间隔 | 注明 warp、warpgroup、SM 或整卡统计范围 |
| 累加依赖 | 依赖链延迟、独立链数量 | 区分依赖链与独立指令流 |
| WGMMA 提交与完成等待 | 允许的在途计算、完成事件与等待条件 | 只在所选指令路径使用时计入；未核实的限制保留待确定 |

### 异步分组、完成与在途条件

| 路径 | 已确认的完成规则 | 约束归属 |
|---|---|---|
| `cp.async` | `.ca` 单线程复制 4/8/16 B，`.cg` 为 16 B；按线程 commit/wait，`wait_group 0` 等此前已提交组完成 | 组内操作不自动互相排序；跨线程消费仍需满足相应同步 |
| TMA 输入到 SMEM | 使用匹配的 `mbarrier` 到达计数与事务完成条件 | 必须等到消费者可见才能使用；缓冲数量不等于硬件在途请求数 |
| TMA 输出到 GMEM | bulk async-group 的普通 wait 等完整操作；`.read` 只等描述符及源数据读取 | `.read` 可用于判断源缓冲复用，不能代替目标写入完成 |
| WGMMA | `commit_group` 按 warpgroup 分组；`wait_group N` 等至最多 N 个最近组未完成 | 读取累加器或改写受影响输入前须等待对应组；`.sync` 不表示异步 MMA 已完成 |

依据：[cp.async][cp-async]、[cp.async wait][cp-wait]、[bulk wait][bulk-wait]、[WGMMA wait][wgmma-wait]。物理队列容量、单组请求上限与持续启动间隔在当前证据中尚未完整确定，不能从 wait 的取值、软件 stage 数或一次测试推成硬件槽数；保留为有作用范围的在途服务参数。

普通 SMEM 读写与异步代理之间采用匹配的 `fence.proxy.async` 规则；WGMMA 寄存器访问采用 `wgmma.fence` 规则。fence 建立顺序，不自动替代对应操作的完成等待。[WGMMA 异步代理][wgmma-proxy]

### 辅助计算、归约与原子操作

| 操作类别 | 需求与共享资源 | 当前参数状态 |
|---|---|---|
| 地址、索引、谓词与分支 | 整数/逻辑执行、寄存器、发射服务 | 合法操作按 SM90 ISA；与 FMA/MMA 的联合服务待确定 |
| 转换、缩放及结果处理 | `cvt`、标量算术、打包/解包；必要时 warp 数据交换 | 精度与舍入由问题及方案约束，不能一律按 FMA 峰值换算 |
| `atom` / `red`（按需） | 实际 global/shared 通路、原子更新和同址串行化 | Split-K 或任务计数器使用时单独计量；不等同于普通 store 带宽 |

操作数供给与片上路径参数继续引用下层资源表；辅助运算是否与其他指令共享执行能力按目标路径确定。

## 待确定参数

已补齐本次涉及的指令路径、提交/等待语义和代表配置经验服务率。纯完成延迟、独立启动间隔、物理在途容量、其他形状及混合操作的联合服务仍待确定；不能用表中吞吐率的倒数统一代替这些参数。
