# GEMM 设计与性能建模

当前阶段：问题定义与通用数学建模。已有 L0–L4 接口与一个限定执行组织的 FP32 时间模型，通用预测关系和实际硬件服务参数仍待完善，具体优化方案尚未选定。

当前基础问题范围：**单 GPU 的 Single GEMM**。Batched / Grouped 暂不考虑，Distributed GEMM 暂不实现；具体标记见[审查范围](modeling_review.md#当前范围与暂缓项)。`problem.md` 保留完整候选域。

## 模型层级

以下层级用于 Thor 和 GH200 的性能建模；L0–L4 是模型层级，与硬件 L1/L2 cache 无关。

| 模型层级 | 定义 | 输入与输出边界 | 主要回答的问题 |
|---|---|---|---|
| [**L0：基础操作服务**](model/L0.md) | 计算、数据搬运、同步和辅助操作的基本服务 | 所需输入与状态满足条件 → 操作约定的完成、可见或释放事件 | 资源需求、完成延迟、启动间隔、在途与依赖限制，以及服务适用条件 |
| [**L1：CTA / SM 片上计算能力**](model/L1.md) | 给定片上数据供给、计算组织与资源配置，建立单 CTA 执行模型及单 SM 上驻留 CTA 的并发服务模型 | 输入块在 SMEM 就绪 → 结果在约定片上位置就绪；明确 CTA 或 SM 范围及驻留配置 | 单 CTA 的完成时间与吞吐量；单 SM 在指定驻留配置下的计算吞吐能力，以及缓冲、同步和资源竞争的限制 |
| [**L2：协作流水线（Collective）**](model/L2.md) | 一组协作线程的数据搬运、计算与同步；分别描述 mainloop 和 epilogue | mainloop：所需 GMEM 输入与初始累加状态满足条件 → 所分配 K 范围的累加结果就绪；epilogue：累加结果及所需输入就绪 → 当前输出 tile 可用 | 分块供给、缓冲复用、启动、稳态、排空及条件化阶段时间 |
| [**L3：完整 kernel / GEMM**](model/L3.md) | 组合协作阶段，并组织所有工作 tile 与 CTA/cluster 的执行 | 输入在 GMEM → 完整输出在 GMEM | 阶段组合、缓存复用、共享带宽、任务分配、波次、负载不均衡和完整完成时间 |
| [**L4：算子图执行**](model/L4.md) | 多个算子的依赖、数据传递与调度 | 算子图输入就绪 → 算子图输出完成 | 融合是否减少数据传输，额外调度和资源占用是否抵消收益；MegaKernel 是一种实现方案 |

CTA 是工作单元，SM 是承载工作单元的硬件资源。L1 分别描述单 CTA 与指定驻留配置下的单 SM 能力；两者不能直接等同。L0 的操作可由上层直接引用，不要求逐层调用。

## 文件职责

| 位置 | 维护内容 |
|---|---|
| `problem.md`、`workloads.yaml` | 问题定义与具体实例；保留旧模型的 2048³ FP16→FP32 实例作为参考 |
| `model/interfaces.md` | 操作、资源、事件、计账与时间下界的共同约定 |
| `model/L0.md`–`L4.md` | 各层边界、接口、通用约束与时间组合关系 |
| `hardware/<设备>/README.md`、`L0.md`–`L3.md` | 设备条件、分类资源参数、架构约束与证据；按实际新增内容分层 |
| `schemes/<方案>.md` | 适用范围、配置、工作量、资源使用、事件关系与方案推导；教学参数和硬件事实分开 |
| `experiments/<设备>/` | 实验条件、接受条件、实测分析与 run 归档入口 |
| [建模审查](modeling_review.md) | 当前缺口、处理状态与下一步推导事项 |

同一硬件资源只定义一次，上层引用其参数；L4 当前没有独立新增的硬件参数。具体 tile、缓冲数和任务映射由方案给定，通用模型不固定 tc5a 等候选的选择。

[GH200 实验入口](experiments/gh200_sm90/README.md)已保存旧计算测量复审、资源微基准和后续测量顺序。预测保留问题、方案、硬件和运行条件；实验记录实际条件与观测，原始 run 由实验文档链接，不把实测写成通用规则。
