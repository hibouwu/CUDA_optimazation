# 剩余六个实验：按家族批量执行

每个实验以完整家族为运行单位。一次准备源码、一次提交，脚本连续完成设备查询、必要短验证、自身校准、预热、正式采样和结果保存。普通配置之间不等待人工签录。独立源码审查在提交前完成；独立结果审查在采样结束、释放 GPU 后完成。

S00–S22 和 A/B/C 继续作为覆盖、来源和验收记录，不再把它们拆成需要人逐项推进的运行任务。原矩阵、十进程采样、预热与稳定性判据不变。

## 一次执行的内部顺序

1. 提交前完成源码、配置、参考、实际命令与报告入口准备。目标编译及其机器码检查尽量在 CPU 作业完成，不占着 GPU 开发。
2. 申请一个 `short` 单 GPU 作业，默认最多三小时。核实际设备、工具链、资源和当前配额；全矩阵短验证采用最大、边界、常规点的顺序，已有适用证据直接引用。
3. 固定配置和自身校准长度，脚本按原随机顺序执行每配置十个独立进程。有界预热和稳定性判定在内部自动完成；只对未稳定项追加第二、第三批，保留全部样本。
4. 每点保存完整必要输出并立即独立按冻结规则检查。常规通过自动继续；数值或计量错误停止相关实验，保存已完成点。能力不支持、容量超限记为明确终态，不尝试非法启动。
5. 采样结束立即释放 GPU。普通 CPU 检查、归档传输、图表和教学说明在 GPU 作业之外连续完成，读者只看最终报告。
6. 最后一次独立 C 审查核实际证据及报告；通过后发布合格参数。审查不重新测 GPU，除非发现使原数据失效的具体错误。

## 存储与完成状态

完整 raw 在节点本地逐点处理，无损归档后保存到持久位置；完整证据仍保留，不能用 checksum 或 error_count 替代。共享源码、编译结果和参考只保存一份，新实验不再逐点复制整套源码。旧归档不改写；实现此存储调整时只审查发生变化的引用和归档逻辑。

提交前预算覆盖整个实验的部署、归档、峰值临时空间、已存在预留和最多三批。压缩比估计用于预计存储，不能当成可靠上界。若整个实验预算不足，先解决存储问题，不再让运行器测完一点后才因配额失败。

一次执行目标是正常条件下一次作业跑完整矩阵，不承诺所有环境都能在三小时结束。作业余时不足、真实配额变化或进程错误时保存检查点；同一入口从经过核验的未完成项继续，不要求用户逐点选批次。设备变化不能把不同条件的性能样本混合成一个参数。

脚本输出分别说明：采样完成、自动重算通过、独立审查通过。GPU 作业 `COMPLETED` 不自动等于整个实验通过。

每个实验一个结果入口，包含 `REPORT.md`、结果 CSV、图、结构化条件参数和复现命令。正文至少手算一条真实样本；完整机器日志、哈希、历史修复和审查记录留在可链接归档，不堆到主文。

优先顺序为 S15 收尾，随后 S08、S16、S17、S19、S20。CPU 准备可以穿插，GPU 测量保持串行。不新增长期对话、统一调度框架或另一份目标正文。
