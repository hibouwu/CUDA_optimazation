主要模型量为 `complete_loop_cycles_per_iteration=C/N`，其中 C 是同一 CTA 的 `clock64` 起止整数之差。附列逻辑请求数 Q 与 `Q/C`，保留请求单位；转换、整数递推和原子更新不改称 FLOP。完整窗口包含原循环控制、反馈、最终结果输出及原完成同步，不命名为裸指令延迟。capacity 的 SMEM 初始化及 drain 保持在该内部窗口之外；它们仍可能进入更外层 CUDA event。

## 长度选择

| 条件 | 值或规则 |
|---|---|
| host 接受域 | 整数 `1..65536`，不含 bool、浮点和 0 |
| 正式冻结域 | 整数 `128..65536` |
| pilot 长度 | 4096 |
| pilot 内部窗口 | `P=stop_ns-start_ns>=1000 ns` |
| 目标内部窗口 | 20,000,000 ns，软目标 |
| 正式内部窗口 | 每条实际测量至少 10,000 ns，硬下限 |
| 周期条件 | 起止为 u64 整数，结束大于开始；起止 SMID 为相同的实际 u32 |

先核 pilot 的完整数值、计时与完成事件，再仅使用其内部 `globaltimer` 区间 P 计算：

\[
N=\min(65536,\max(128,\lfloor4096\times20\,000\,000/P\rfloor)).
\]

使用整数乘法和整数除法，不通过 event 毫秒或浮点四舍五入选择 N。保存 pilot 的原始区间、事件值、周期、输出及收据，以及取整前商、是否夹紧、最终 N、规则版本和设备/二进制身份。已有共享校准接口如何承载这些字段仍需另行 source-B 核实，不能把候选纯公式当已注册入口。

N 在完整 B 后冻结；十进程、复测批次和 resume 不重新校准。改变 N、二进制或规则必须新运行身份。长度未达到目标但实际窗口至少 10 μs、计量与稳定性均成立时，可交付该条件下的短窗口结果。每样本保存 `soft_target_met=(P_actual>=20000000)`，汇总保存实际窗口最小/最大值及达标数；不能把 10 μs 下限通过写成已达到 20 ms，也不能把目标时长当分母。

例如 pilot 内部窗口为 2,000 ns，则未夹紧商为 40,960,000，N 夹紧到 65,536；假设实际正式窗口只有 32,000 ns，它可以通过硬窗口，但必须标明 `soft_target_met=false`。若实际仅有 8,000 ns，则计量未准入，不能导出服务参数。

## CUDA event 的外层检查

begin event、同一 kernel、end event 在同一默认 stream 按顺序记录，end event 同步成功后才读取结果。每次取证都保留内部区间、event 毫秒、起止整数时间戳、两个 SMID 和完成状态。

S18 的保守接受规则为：event 值是有限正数，换成纳秒后 `event_ns>=P_actual`；不要求接近或固定比率，不设 event 的额外占比上限。保存两者及差值，避免把初始化、drain 或启动项计入内部循环。现有公共函数的检查继续生效，S18 的额外规则只放本家族 host/审查层，不修改通用计量函数。

这是实验自定的保守一致性筛查，不是严格误差证明。CUDA 12.9.1 官方说明 event 分辨率约为 0.5 μs，并提醒异步记录与其他 stream 工作可能影响区间；这不提供 ±0.5 μs 的最坏误差上界。[官方 Event API](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-runtime-api/group__CUDART__EVENT.html)

若外层规则不通过，保留原始值，状态为计量未准入；不能据此宣称 GPU 数值错误或用假定的 0.5 μs 修正结果。pilot、预热和正式测量均检查正周期、同 SM 和 event 外层关系；10 μs 下限用于选定 N 的正式测量，pilot 用 1 μs 下限。正式窗口下限或其他条件不成立时，不临时改变协议或丢弃异常样本。

## 长域参考与完整检查

原 B3 的 1/2/5 次短检查不证明 65,536 次循环的长期结果。source-B 至少验证全部 27 个配置、长度 `{1,127,128,4096,65536}`、seed `{0,3,4294967295}` 的 host 参考与独立 CPU 参考一致，并覆盖每线程/流/数组位置、u32/u64 回绕、低 32-bit 反馈、两方向转换和原子同址/独立地址。更长参考可采用已验证的闭式/仿射快速计算，但不能改变 device 函数或算法语义；先用直接递推在有限长度与边界验证闭式。

同址原子每轮增量仍为 507，线程级请求数为 `128N`；已审 warp 聚合的原生更新数是静态路径条件，不是硬件计数器观察。转换输入仍为可精确编码的 1024 个有限模式。local 逻辑字节为 `threads×words×N×8`，不含初始化/排空或编译器额外 spill，也不等于物理 HBM 流量。

每次启动重新初始化输入、输出、保护区和控制状态，完成后完整回读并比较全部值。允许在同一进程缓存不可变 expected，键至少含 case、N、seed 与布局条件；不得缓存实际结果，不能跳过预热或正式启动的比较。B4 从已有 pilot 与选定 N 的最终试运行各保全一次完整输出供独立重算，不额外启动 kernel 取证；随后正式进程可以不逐次落盘完整数组，但保留全部计时、检查数量、错误及实际资源记录。

## 原正式协议保持

十次独立进程、固定种子随机顺序、8–30 次有界预热与最后 5 个窗口 CV≤2%、正式样本 CV>5% 需复测及最多三批保持。预热沿已有内部纳秒窗口规则，不声称长期热稳态；CV 采用样本标准差除均值。服务主度量的统计用 `C/N`，附列 `Q/C` 的统计；发布时两者均须明确各自 CV，任一 CV>5% 均按同一有界复测/保全规则处理，不改阈值。

单进程、编译和作业预算沿现有协议，三小时分配不扩大单点超时。完整 B 必须独立绑定 pilot、冻结 N、长期输出、实际完整机器码与资源、计量接受结果。C 才处理全部正式样本、稳定性、图表和条件参数；未达到硬窗口、错误参考、未完成/未清理或不稳定的点不能作为合格标量参数导出。
