# S18 驻留约束与辅助操作（待 A 审查）

本实验覆盖线程、寄存器、SMEM 与 carveout 的代表条件，以及 local/spill、地址运算、转换、原子更新和 `setmaxnreg`。有限矩阵为 [28 个配置](../../../../../microbench/gh200_resource_campaign/contracts/auxiliary_scope_v1.draft.json)，不增加全组合扫描。当前只有设计与可行性源码，尚无已接受测量值。

## 一个最小例子

`add_u64_streams4` 使用一个 128 线程 CTA，每线程维护 4 个独立 u64 状态。执行 5 次迭代时，目标加法请求量为

\[
W=128\times4\times5=2560\quad\text{次 u64 加法请求}.
\]

完成周期使用同一 CTA 的停止 `clock64` 减开始 `clock64`。请求率为 `2560 / elapsed_cycles`。循环控制、开始同步、最终结果写出和完成同步均在声明的计时边界内；该值不能直接命名为裸指令延迟或硬件峰值。正式报告须用一条实际原始记录替换此配置算例，当前不填写预测或模拟测量值。

## 配置与操作定义

所有状态来自运行时生成的非均匀输入，必须完整输出到 host 并独立核对。具体整数初值、增量、转换反馈和原子初值由配置文件的 `integer_semantics`、`operations` 唯一定义；实现与独立参考必须消费这份有限约定，不能自行选择另一递推。整数运算按指定字宽取模。每个配置的输出数组按 CTA、线程、word/stream 排序，禁止仅用一个 checksum 代替数值证据。

- **capacity：** 初始化每线程 32/64/128 个 u32；每次迭代逐 word 执行 `x = 1664525*x + 1013904223`（模 2^32），循环末输出所有 word。live 数量是源码请求，不等于物理寄存器数。线程数、SMEM 和 carveout 坐标按矩阵逐一改变。动态 SMEM 在开始时间戳前按线程跨步分工初始化并同步，循环内不访问该 payload；停止时间戳后按同一分工完整读出到独立 global 输出。这样计时循环仅改变资源占用，SMEM 初始化和读取不混入寄存器更新服务。实际启动的动态 SMEM 字节数仍须核对。
- **显式 local：** 每线程 volatile u32 数组 32/128 word，初始化后每次迭代对每个 word 执行相同整数递推。逻辑每次更新包含 4 B 读和 4 B 写；必须证明对应访问仍在实际循环内。初始化、最终排空的请求量单列，不纳入循环有效字节。
- **spill pressure：** 与 capacity 使用相同的 live 状态与递推，在单独编译单元请求寄存器上限 32。只有真实 ptxas/SASS 证明循环内 spill 的点才能作为 spill 条件使用。未产生预期 spill 属于探针条件未实现，须修复或补足证据，不能标成设备不支持。编译器提高寄存器下限等诊断需原样保留。
- **`add.u64`：** 每个 stream 的运行时初值为 x，增量 c 由 seed、线程和 stream 确定且非零；每次迭代 `x = x + c`（模 2^64）。1/4 个 stream 之间不互相依赖。
- **`mad.wide.u32`：** 每个 stream 执行 `r = uint64(x)*a + c`（模 2^64），其中 a 为运行时奇数、c 为 u64；下一次 x 为 r 的低 32 位。反馈截断和循环成本包含在服务测量中。原始输出保留最后的完整 r。
- **f32→f16：** 状态 q 为 0..1023，每轮用运行时盐及迭代号更新 q，再构造精确的 `1 + q/1024` float 位型，只执行目标 `cvt.rn.f16.f32`。下一轮的 q 取上一结果的低 10 位。最终输出 half 位型。
- **f16→f32：** 用相同有限分数域构造 `0x3c00 | q`，只执行目标 `cvt.f32.f16`；从 float 输出的分数位恢复 q 并反馈。最终输出 float 位型。两个转换方向分别测量，不把往返时间除二。
- **原子：** 每轮每线程对目标 u32 加 `1 + (thread_id % 7)`，不消费返回值；请求 relaxed 顺序，global 使用 gpu scope、shared 使用 cta scope，实际 ATOM/RED lowering 单独记录。同址输出一个 word，独立地址输出全部 128 word。初值依 seed 和地址生成；独立 CPU 参考直接计算初值加全部增量之和（模 2^32），不依赖执行顺序。shared 最终结果须由线程写入 global 并完成 CTA 同步后停止计时。
- **`setmaxnreg`：** 使用现有独立 PTX 可行性候选。必须在实际编译资源、完整寄存器使用及 live 范围审查后才能执行；`.maxnreg 64` 本身不足以证明初始实际资源。dec 前结束高寄存器 live 范围，inc 后先初始化再使用新寄存器。每个阶段保留全部 128×60 个 u32 输出，候选路径及 SHA 已绑定配置。仅一个 CTA，全部四个 warp 执行同一调整序列；inc 可能等待寄存器供给，超时须按执行失败调查，不能记为能力不支持。不扩展成寄存器重分配成本扫描。

## 计时与计量

性能探针每进程只选择一个配置。先完成输入准备、资源查询与启动可行性检查。CTA 线程 0 记录开始 globaltimer 和 `clock64`，全 CTA 同步后进入循环；所有线程将最终状态写出并同步后，线程 0 记录停止周期与 globaltimer。开始/结束 SMID 必须一致；不同 SM 的 `clock64` 不能相减。

S18 的上述服务配置固定一个 CTA，以避免把整卡调度引入指令/辅助服务参数。capacity 的 occupancy 查询和资源上限分析单列，当前不声称测得全 GPU 吞吐或实际驻留。外层 CUDA event 覆盖整个 kernel，用于时间范围交叉检查，不能代替 CTA 周期。

短验证采用既有三组配对 `(iterations, seed) = (1,0), (2,3), (5,4294967295)`。每个配置验证全部线程、状态、输出及资源记录，不能只验证代表点后直接正式采样。正式长度经校准确定，使用既有有界预热、10 次独立进程及最多三批协议；校准长度域和目标时间在 B 的实际计时可行性确认后冻结。

请求量分别记录：整数递推/地址/转换目标次数、逻辑 local 读写字节和原子更新数。FP16 转换不计为浮点 FMA，也不使用 FLOP 单位。工作量由独立审查器从配置、线程数和迭代数重算。

## 正确性与接受条件

A 独立审查通过后冻结本约定和配置矩阵，再完成探针实现及目标编译。B 必须具备以下证据：

1. 非均匀 CPU 参考覆盖零、高位、模溢出和所有参与线程；两个转换方向分别逐位核对整个 1024 分数域。
2. 对实际目标检查完整 SASS、计时循环、依赖链、输出消费及寄存器/SMEM/local/spill。编译选项、requested live 和实际资源分别保存。
3. 所有适用配置的短 GPU 完整数值验证通过。超资源情况须在启动前由实际查询明确拒绝；API 错误和实现错误不能归入能力不支持。
4. 完成事件和计时边界与约定一致；在低分辨率 globaltimer 下不能凭零差值产生无穷服务率。短正确性成功本身不授予性能参数资格。
5. 正式样本的原始结果、单位、统计和条件能离线重算；未稳定或证据不全的配置不导出合格标量参数。
