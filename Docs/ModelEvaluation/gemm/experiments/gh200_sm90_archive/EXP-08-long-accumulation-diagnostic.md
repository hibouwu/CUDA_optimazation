# S08 长累加数值诊断

A 草案，尚未执行。原短诊断在同一 WGMMA case 的均匀/非均匀输入、1/2 轮上精确通过，旧 preflight 只保存了数值 mismatch，没有失败阶段和完整输出。本实验保留原 kernel、原配置和原输入，只增加一次完整输出观测，定位长累加行为。

## 唯一坐标

`wgmma_e4m3_g1_one_cta`，1 CTA、128 线程、8192 轮、seed=3、A=B=1/16、两个独立累加链、每链每轮16条 M64N64K32 WGMMA、D初值0。执行一次 target kernel，无预热、pilot 或性能采样。

沿用现有 `lp_wgmma_e4m3_g1`，包装翻译单元只重命名旧 host main 后包含旧源，不重写设备函数。编译后必须逐指令对比既有短诊断的完整目标 SASS，并核对资源；有变化先审查，不凭相同函数名声称等价。

## 保存什么

一次 launch 产生 8192 个 double（设备从 FP32 累加器转换而来），按 `((thread×2+chain)×32+fragment)` 排序。全部保存索引、十进制值及对应 FP32 的32位位模式，不用前8个差异或直方图代替完整数组。输出与stamp先填0xff；CUDA完成后检查全部输出有限、FP32往返一致、每个stamp字段被覆盖。

数学比较值为 `8192×16×32×(1/16)^2=16384`。这次比较用于描述差异，**不预先认定长 FP8 硬件累加必须精确等于该值**。有限但不同的输出会作为诊断证据保留，不能因此授予或否决实现的完整数值资格，也不能直接放宽原容差。CUDA错误、未覆盖输出、非有限值或不匹配的编译身份仍拒绝。

进程保留原始计时字段用于执行记录，但不计算 FLOP/cycle 或导出性能。该 profile 超出早期短检查的64轮上限，因此是独立长诊断，不计作 family B3。

## 执行与后续判断

沿用 Slurm、两类锁、进程登记和清理；一次诊断进程最多120秒，编译最多180秒。完整源依赖、参考 SASS、环境和审查哈希先冻结。结果审查从所有输出独立重算差异数、极值、位模式及分布。

若单次长输入出现有限差异，先检查差异是否具有一致性，再另定有界长度对照；若精确通过，则后续另审原三个 launch 的顺序对照。当前合同不会自动展开这些复测，也不修改正式 workload、替换输入或重跑其他已通过的家族。
