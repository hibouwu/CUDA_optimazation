# S14：同一 GPU 分配内的验证与正式采样

状态：候选约定，尚未授予执行资格。本修订服务于 [GOAL.md](GOAL.md) 的单 GPU 长分配规则；原 S14 范围、历史归档和已签审查保留。

## 实验边界

本次交付对象仍是 TMA 无 tensor-map 的 1D bulk 双向服务，payload 为 1/4/8/16/32/64 KiB，分别采用单 CTA 和全 GPU 范围，共 24 个正式配置。新设备上的短验证使用正式探针实际调用的 `capture=false` 分支，每配置执行现有 `formal_final_1_2_33_v1`，外部入口 seed=3，三次实际启动的 `(iterations, internal_seed)` 分别为 `(1, 0)`、`(2, 3)`、`(33, 4294967295)`，共 72 次启动；完整输出按原非均匀参考验证。

历史的 84 次原路径验证和 72 次正式路径短验证仍属于其原设备。前者中的 `capture=true` 与 source-read release 诊断保留原来的数值、完成事件和适用范围；本修订不会把它们写成在新 GPU 上运行过，也不会删除它们在 S14 覆盖中的位置。本次正式输出只声称实际执行的双向完整运输服务，不从未执行的 source-read release 分支导出新设备参数。

## 新分配上的条件

- 新建独立运行目录，以实际 job ID、GPU UUID、主机、设备属性、工具链、源码和二进制身份记录本次执行，不续写旧 GPU 的运行记录。
- 首次修订在设备、工具链和配置条件的比较中只允许物理 UUID 改变；其他影响配置的字段须满足明确的等价检查。job ID、主机、分区时限和本次归档目录属于新执行的来源字段，分别记录其实际值，不要求与旧分配逐字相等；这不豁免工具、源码及二进制内容身份检查。若出现差异，保存事实并拒绝受影响的沿用，不能从旧记录填充新观察值。
- 复用已审 kernel 与参考；核对 18 个相关目标的完整机器码及实际源码依赖。公共作业时限适配单独引用已审增量，不据此认为旧工作树的所有文件仍与历史签名相同。
- 在新二进制与实际设备上取得各配置的资源、occupancy API 和网格事实，核对其与短验证及后续正式执行一致。API 给出的驻留上限不作为实际同时驻留的测量结果。

## 同一分配内的顺序

| 步骤 | 必须具备的证据 | 允许的下一步 |
|---|---|---|
| 源码准备 | 新约定、最小执行路径、CPU 接口检查及独立源码审查通过 | 申请 `short` 三小时单 GPU 分配，执行能力查询和 24 配置短验证 |
| 新设备短验证 | 72 次启动的完整输出、数值重算、实际机器码/资源、计时与清理记录；未实施者签署准确文件身份 | 现有 preflight 的长度校准、预热和计量检查 |
| 完整 B | 新设备 preflight 实际结果及冻结长度等计量依据；未实施者完成完整 B 审查 | 在同一 GPU 上按原协议执行正式采样 |
| C 与交付 | 全部原始样本、稳定性判定、独立统计、图表和条件参数 | 发布正式结果与中文说明；CPU 分析不继续占用 GPU |

两处在线结果审查分别最多等待十分钟，且必须给下一项运行和清理留出作业时间。等待期间不得提前执行未获准阶段。审查拒绝、等待超时、剩余时间不足或设备身份变化时，保存检查点并退出；不得自动换卡后继续沿用本次准入。观察连接中断时先确认原作业和已有记录，不因观察超时重复提交。

在线审查由事先安排的独立审查者完成，运行器只验证其结论、文件绑定与适用范围，不能自行生成通过签名。旧审查复用只限原结论覆盖且身份未变化的部分。若本次分配无法完成，不将候选源码、短验证或 preflight 计为正式性能参数。

## 计量与保全

原正式协议的十次独立进程、随机顺序、有界预热、稳定性判据、最多三批与全样本保留要求不变；各进程可在同一次 Slurm 分配内启动。单进程和编译超时不随三小时作业时限放宽，已有更短的家族限时继续适用。

启动前及批次间按实际配额、下一点输出规模和预留空间检查存储条件。完整原始输出、每点终态和实际环境必须保留；数据传输或离线分析失败不作为重新采样的理由。新的正式参数只绑定本次实际测量条件，不与历史 GPU 的样本自动合并。
