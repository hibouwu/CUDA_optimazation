# EXP-08 补充：FP8 MMA 的实际编译降低

状态：A 修订草案，待独立审查。旧 [EXP-08](EXP-08-low-precision.md) 和合同保留，以便解释首次设计与实际编译证据的差异；本修订尚未授予 GPU 数值或正式采样资格。

## 实际发现

ROMEO 作业 730178 使用 CUDA 12.9、`sm_90a` 编译了 32 个代表点的探针。所选 FP8 `mma.sync.m16n8k32` 在每个外层循环中，实际包含 12 条 FP8→FP16 转换、两条 `HMMA.16816.F32` 和 128 条 `FADD`。重复的 A×B 被复用，没有为源码中的 32 条逻辑 MMA 各执行一次完整矩阵乘积。

这一观察只约束当前输入复用方式、编译器和归档二进制。它不证明所有 GH200 编译器和输入条件都采用相同降低。对应 WGMMA FP8 点在归档中可见 `QGMMA.64x64x32.F32` 及显式的 A/B 编码，需要独立核对；不能拿它的指令格式套到同步 MMA 上。

## 计量修订

保留所有原有配置、数值输入、线程范围和循环长度，只修改八个 `mma.sync` FP8 点的解释与接受条件：

| 量 | 每 warp 每外层循环的数值 | 用途 |
|---|---:|---|
| 逻辑 MMA 工作 | `32×2×16×8×32 = 262,144 FLOP` | 描述 PTX 级任务完成量 |
| 实际矩阵乘加工作 | `2×2×16×8×16 = 8,192 FLOP` | 对应实际两条 HMMA 的需求 |
| 实际 SIMT 加法 | `128×32 = 4,096 次加法` | 对应各 lane 执行的 FADD |
| 转换 | 12 条 warp 级转换指令 | 单独保留，不计成乘加 FLOP |

主结果的显示单位增加 `logical_` 前缀，并保存实际指令需求向量。不能用 262,144 作为“实际 Tensor Core 执行了这么多 FLOP”的证据，也不能据此导出原生 FP8 核的标量吞吐。

这八个点设为 `exportable=false`，仍需完成数值检查、正式采样、独立复算和实验说明，其结果属于给定条件下的编译序列服务。其余 24 个 INT8 或 WGMMA 代表点保持原约定，并各自接受实际指令类型、形状及循环计数检查。

## 实现与复核要求

新合同为 [low_precision_lowering_v3.json](../../../../../microbench/gh200_resource_campaign/contracts/low_precision_lowering_v3.json)，绑定父合同与真实 SASS 哈希。原始编译归档位于 `results/gh200_resource_campaign/20261001-resource-suite-v2/implementation/target-compile-v3/diagnostics/low_precision/`。

审查器必须核对完整转换、HMMA 和 FADD 序列的类型、形状、计数与循环位置；不能把规则放宽成“存在 HMMA 就通过”。WGMMA 编译器寄存器边界的修复可能改变寄存器编号或合法调度，须在新二进制上重新检查，不能移用旧编译资格。

不额外加入人为 volatile 加载，也不关闭优化来强迫得到期望数量的矩阵指令；这些做法会改变供给和调度条件，应另立实验，而不在本轮偷偷改变条件。

正式数据仍待新 A 通过、B 实施和真实 GPU 正确性验证。本补充没有把实现或计量错误改名为硬件不支持，也没有减少原计划的代表点数量。
