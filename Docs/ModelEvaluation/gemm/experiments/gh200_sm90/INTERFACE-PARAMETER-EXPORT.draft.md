# 条件化参数导出约定（草案）

导出对象是一条已审查实验配置的服务观测：给定指令、数据类型、依赖关系、线程与 CTA 范围、循环长度、缓冲、完成事件及设备条件，给出对应单位下的样本统计。它不自动代表硬件峰值，也不把固定长度速率解释成裸指令延迟或每 tile 增量。

## 输入与资格

输入是完整运行归档和绑定其哈希的独立 C 审查。每次导出同时检查 `COMPLETE`、C 审查、`measurement_manifest.json`、`summary.json`、`run_spec.json`、冻结 contract、snapshot、设备、二进制、SASS 和原始样本。必须使用该运行冻结的审查器重放；当前源码不能替换冻结依赖。

历史 summary 中 `measurement_evidence_pending_C_review` 是受审前冻结状态。只在匹配的 C 审查和 COMPLETE、封存后重放共同证明资格时采用结果，不能改写 summary 标签后假定通过。输入清单工具只核对完成记录与配置集合，尚不完成原始数据重放，不授参数资格。

标量导出同时要求：实际正式运行、数值和计量检查通过、独立 C 通过、全部约定样本存在、统计稳定、配置允许导出。空计时控制、不稳定、被否决、未完成或缺少关键证据的配置只进入排除清单；不得以另一配置的值补齐。NCU 无权限不排除已经被其他证据证明的逻辑请求服务率，但排除依赖计数器的物理 HBM 流量、缓存命中及引擎忙周期参数。

## 每条参数记录

| 字段 | 必须保存的内容 |
|---|---|
| 身份 | schema 版本、suite、family、run ID、case ID、完整条件对象的哈希 |
| 条件 | 冻结 case；校准后实际 case（如存在）；输入分布、精度、形状、布局、依赖链、参与者、循环长度、stage、请求数、工作集、计时和完成边界 |
| 设备与资源 | 实际 GPU UUID、架构、工具链与驱动；实际启动网格和资源记录的引用及哈希。occupancy 上限与观测 SM 覆盖分别保存 |
| 数值 | 原单位、原 clock 域和执行范围；原样本统计 median/mean/min/max/CV/n，以及所有批次；不选择最佳批次 |
| 证据 | COMPLETE、独立 C、重放收据、源代码快照、contract、raw、进程收据、设备、binary、SASS 的相对路径和 SHA256 |
| 限制 | cache/物理流量证据状态、权限缺口、固定长度或拟合的范围、不能支持的外推 |

默认观测值采用全部合格批次合并的中位数，同时保留其他统计。固定长度测量记录 `observation_kind=fixed_length_service_rate`；已另经审查的拟合记录才可采用启动项或每 tile 增量。不同 UUID、工具链、输入或配置不自动合并。

例如 `async_copy/formal-b3-v2` 的 `ca_w4_stages1_one_cta` 原单位是 `B_transport/clock64_cycle/CTA`。条件包含 128 线程、8192 轮、每线程每轮 8 次 4 B 请求、stage=1，以及跨线程消费和最终完成边界。这个观测不能直接作为 GMEM→SMEM 裸搬运带宽，也不能乘以 SM 数冒充整卡 HBM 带宽。

## 输出与恢复

输出为 `parameters.json`、`excluded.json`、`sources.json` 和一份中文说明；输出目录必须不存在。验证完成后再原子发布完整目录，任何错误不留下看似完成的参数集。所有引用相对输入归档根解析，换目录重放不依赖原工作目录。依赖或源数据改变时建立新的导出身份，保留旧输出。

首批覆盖六个已完成正式家族；后续家族在各自 C 通过后沿用同一入口。六类现有输入共 279 个稳定 payload 候选、8 个稳定计时控制、2 个其他状态；这些数量来自完成记录和配置清单检查，尚不是本导出器授予的参数资格。

## 验收

先独立 A 审查本约定，再实施导出器并独立 B 审查。负例至少包括损坏 raw、缺样本、错误单位或 scope、错误 C/COMPLETE 哈希、未完成运行、错误冻结依赖、不稳定配置、空控制及被篡改校准长度。完整归档复制到另一目录后，导出内容和来源身份必须相同。每个导出值能追溯到原始记录及独立重算，排除清单完整保留不能导出的配置。
