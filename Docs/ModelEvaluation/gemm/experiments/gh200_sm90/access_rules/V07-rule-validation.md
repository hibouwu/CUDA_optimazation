## 模型实际使用了什么

沿用V06的cooperative/pingpong事件递推，在当前卡重新校准初始供给、主循环、epilogue、交接、CTA尾差候选和频率规则。CTA尾差仍在none/常量/比例/tile数线性四种形式中按校准留一误差选；此次三个配置均选择none。该选择不意味着最慢CTA没有离散，而是当前拟合没有取得稳定可迁移的额外项。

R18边界规则使用相同物理tile的窗口差，首/后tile和边界、伙伴、同列/同行类别分别处理；两个K点冻结为插值假设，只在Ktile 16–128内使用，不导出硬件斜率。轻量修复组使用自己短/长K的匹配对照。增量沿cooperative依赖传播一次，不把窗口平均cycle/Ktile再加到旧截距上。

12个边界目标有一类首轮`other`位置没有直接R18支持：它们不与本轮已观察的边界位于同一列/行，冻结模型对该项使用零附加值，并在`boundary_unknown_cells`明确保留。完整时间通过没有补上该局部机制证据。

全部目标为swizzle1，具体stride、shape与配置在预测文件的row中冻结。cfg_a/c的部分边界有效比例不同于校准组；这是本次迁移检验的一部分。cfg_b覆盖近单波、多波、输出规模与尾部分布，未把R19的swizzle8补齐变化当成通用缓存系数。

### 冻结递推怎样手算

令`fm/me/ep/ed`分别为首次MMA、主循环结束、epilogue许可与调用返回。cooperative按下式递推：

```text
fm[0] = P0 + S
me[j] = fm[j] + l0 + l1*Kt + (j==0 ? dL0 : 0) + Δ[j]
ep[j] = me[j] + w
ed[j] = ep[j] + (j==0 ? E0 : E)
fm[j+1] = ed[j] + h
C_CTA = max(ed) + Etail + X
```

pingpong的MMA起点改为`max(me[j−1]+gm, ed[j−2]+h)`，不存在的前项不参与；epilogue许可为`max(me[j]+w, ed[j−1]+we)`。输出工作E在与另一consumer主循环重叠时按校准比例r推进，其余时间按1推进。r是该执行组织的服务参数，不是物理端口常数。

`cfg_a_aligned_k1536`有14×15=210个tile，78个CTA处理2个、54个处理1个，Kt=24。冻结参数给出供给5262.25、首/后主循环12764.25/12722.7865、两次许可各140.6683、首/后输出2401.25/2161.1395、一次交接819.7178、末尾504 cycle，X=0、Δ=0。相加得到`C_max=36,916.7305 cycle`。该形状的冻结频率解为1.7690302 GHz、固定项4.6800005 μs：

```text
T = F + C_max/(1000*f_GHz)
  = 4.6800005 + 36916.7305/(1000*1.7690302)
  = 25.5483441 μs
```

这里的f由当前卡校准规则求解，不是事后代入该留出点的实测频率。另一个明确例子是cfg_a整块越界首tile伙伴的插值：两个合格窗口差1936 cycle（Kt16）和21776（Kt128）给出`Δ=-898.2857+177.142857*Kt`；Kt96时为16107.4286 cycle，只添加一次。负截距属于有限区间的插值描述，不是负硬件延迟；局部规则是否适用于留出条件，仍看下面的分项结果。

## 分项与关键CTA定位

分项统计对象明确固定：供给、主循环和末次epilogue/尾段，比较冻结模型所选CTA的预测与该同一CTA的实测；关键CTA最大周期量另与所有CTA的最大时长比较。这样不会在测量后换一个CTA使分项看起来更好。交接h沿用校准的事件定义，单独比较。

| 量 | 定量计分例数 | 绝对误差中位/最大 | 判定 |
|---|---:|---:|---|
| 最大CTA周期量 | 24 | 1.58% / 8.71% | 通过10%/20% |
| 初始供给 | 24 | 12.03% / 45.92% | 未通过 |
| 主循环累计窗口 | 24 | 1.47% / 16.57% | 通过 |
| 末次epilogue调用窗口 | 24 | 12.44% / 46.82% | 未通过 |
| 交接h（≥512cycle） | 17 | 0.19% / 4.64% | 该子集通过 |
| 末尾短段 | 0（24例均<512cycle） | 保存原始周期误差 | 按原始差值与事件关系检查，不作百分比判定 |

供给失配的具体例子：`cfg_b_near_short`预测5334.125、实测3655.5 cycle，多1678.625，即45.92%。输出失配：`cfg_c_partial_odd_k6144`预测4651.964、实测3168.5，多1483.464 cycle，即46.82%。把跨校准形状的统一供给/输出常数用于具体关键CTA和边界，尚未通过分项迁移验证。

24个末尾短段按原始差值和事件关系保留。例如cfg_c若干条件预测536.375、实测267 cycle，差269.375；不能因为绝对时间短就判为模型正确。另7例没有观察到h约束绑定的事件：近单波的两个pingpong形状没有第三个tile，其余5例由前一tile的MMA约束占主导，未暴露同一consumer前次epilogue返回的h窗口。它们标为`not_observed`，不能当作h=0或低误差通过，也不与17个可观察窗口混算“全部通过”。

还发现独立的CTA定位限制：`cfg_a_oob_k6144`中，冻结选择的CTA12实测时长，比真正最长CTA的时长中位数短23,255 cycle，约17.28%；`cfg_a_partial_odd_k6144`也约17.28%。这不是仅凭CTA编号不同否定模型，而是所选CTA时长有实质差距。最长clock64窗口和globaltimer最晚退出CTA的计数分别保存。最大周期量接近仍可能伴随局部窗口高估、关键CTA选错，不能把总时间达标解释成整个事件图已闭合。

## 事后诊断：总时间为何接近（离线，不改判定）

只用 V07 已有进程与 R18 归档，无新测量。[脚本](../../../../../../microbench/gh200_resource_campaign/access_rules/analyze_v07_posthoc.py)，[结果](../../../../../../results/gh200_resource_campaign/access_rules/20261008-V07-job737122-v1/reanalysis/posthoc-v1/posthoc.json)。

**1. 共同偏长主要来自打点开销。** 模型的 F、C、f 全部取自打点（stamped）进程，评分却对 plain 进程。打点进程比 plain 慢，中位 1.6%、最大 4.8%，约 1 µs。在打点进程内，事件时间减去 CTA 窗口为 cfg_a 4.3–4.8、cfg_b 3.8–4.1、cfg_c 4.7 µs，与冻结 F（4.68/4.06/4.66）一致，F 本身没有错。

| 比较对象 | \|e\| 中位 / 最大 | 偏长例数 |
|---|---|---:|
| V07 冻结预测 vs plain（正式判定） | 3.06% / 8.71% | 20/24 |
| 同一预测 vs stamped | 1.89% / 6.77% | 14/24 |
| F 改用校准 plain 进程（3.15/3.10/3.50 µs）vs plain | 1.87% / 4.33% | 13/24 |

第三行只用校准数据，但修正方式是看到 V07 后选的，不能当作通过。按校准留一选择时，cfg_a 不采用这一修正：大形状校准点的 plain 时间反而短于打点窗口（如 `c7_large` −3.9 µs），打点开销随形状变化，不是常数；见下方“只用 V07 校准数据的修正候选”。

**2. 普通 CTA 偏长，最慢 CTA 的超出量未建模，二者相抵。** 在拥有最多 tile 的 CTA 中，模型对中位 CTA 偏长 2.35%（19/24）；实测最慢 CTA 比中位 CTA 长 1.56%（24/24 为正），而冻结的尾差项选了“无”。例如 `cfg_a_aligned_k1536`：普通 CTA 预测偏长 4.63%，最慢 CTA 多出 2.85%，关键周期误差只剩 +1.73%。

普通 CTA 偏长的主要来源是供给和末次输出取了校准常数，而这两项随条件变化：

- 供给 S（producer 首次取得工作→首 MMA）：输入可在两次 warm 调用之间留在 L2 的小形状最短。cfg_a 足迹 22–24 MiB 时 S≈1630–1700，53–57 MiB 时≈2110–2220，多波大形状校准点为 2590–2780 cycle。校准集多为满波大形状，留出集多为 T=2 的小形状，所以供给被系统高估。
- 末次输出：cfg_a 的 8 个留出例全部实测 1922 cycle，校准常数 2161；校准中只有长 K 的 `c6_longk` 为 1919，其余 2058–2225。末次 epilogue 与同时输出的 CTA 数有关，单一常数不能覆盖。

**3. cfg_a 边界：变慢的不是边界 tile 所在的 CTA。** 两例关键 CTA 选错，原因不是递推，而是 R18 增量加在了错误的 CTA 上。`cfg_a_oob_k6144` 第 0 轮主循环相对中位数的变化：

| CTA（SM） | 第 0 轮 tile (mi,ni) | 类别 | 主循环变化 |
|---|---|---|---:|
| 36/37（28/29） | (8/9, 2) | 内部 | +43% |
| 20/21（12/13） | (6/7, 1) | 内部 | +43% |
| 68/69（60/61） | (12/13, 4) | 边界 cluster | +43% |
| 12/13（4/5） | (12/13, 0) | 边界 cluster（冻结所选） | −1% |

变化分成几个离散档（约 +43%、+23%、+20%、+8%、+4%、0、−3%），同一位置在 10 个进程、K=1536/6144 和 oob/partial_odd 之间都重复；`partial_even` 在同样位置也变慢，但只有 +3%~+8%；对齐形状全部为 0。R18（M=1408/1376）中最慢的一档（+32%~+35%）在另一组 SM（2/3、14/15、50/51、62/63、92/93、104/105），同样混有边界 cluster 和内部 cluster。因此这不是固定的慢 SM，而是第 0 轮各 cluster 之间的相互作用，由形状决定；“哪个 CTA 最慢”和“慢多少”都不能从边界 tile 的位置推出。最慢一档在 V07 的 K=6144 为 +43%（约 232 cycle/Ktile），R18 K=8192 为 +33%（约 169 cycle/Ktile），幅度也不随 K 线性迁移。

这两例总时间仍接近，是因为关键周期偏短 4–6%，与打点开销和频率解偏低（约 +3.5%）相抵。

**对模型的含义。** (1) F 应按 plain 计时校准，或把打点开销单列；(2) 供给和末次输出需要随 L2 驻留和同时输出的 CTA 数变化，至少校准集要覆盖单波、小足迹形状；(3) 关键 CTA 需要“最慢 CTA 超出量”这一项，cfg_a 边界形状下该项远大于普通形状；(4) R18 的按 tile 加增量规则不能定位最慢 CTA，cfg_a 边界效应需要按“整个第 0 轮受影响”的方式建模，机制未隔离。
