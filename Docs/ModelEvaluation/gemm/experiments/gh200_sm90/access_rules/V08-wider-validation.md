## 失败原因（测后诊断，不改判定）

按 tile 拆开 stamped 记录：

1. **未对齐行距 / 尾部（h03）。** 2400×3000×1000 的 A、B、D 行距为 2000、6000、12000 B，都不是 128 B 的倍数，K、N 也有尾部。有效 tile 的主循环：cfg_b 为预测的 1.61–1.73 倍，cfg_a 为 1.12–1.37 倍，cfg_c 为 0.90 倍（不变慢）。校准中没有这类形状。后续对照表明原因是 A、B 行距，不是尾部（见下节）。
2. **补齐 tile 的代价不稳定（h07、h10）。** 实测补齐 tile 相对有效 tile：cfg_a 在 h07 为 +46%（沿 M）、+50%（沿 N），在 h10 只有 +10%；校准 g7 给的是 +39%、+76%。每 Ktile 的额外 cycle 在 75–250 之间变化，单个校准形状给出的比值不能迁移。h10 因此偏长 11%～14%，cfg_b 的 h07 偏短 13%。
3. **cfg_b 大足迹长 K（h06）。** 3584²×20480（足迹 329 MiB）的后续 tile 主循环 633 cycle/Ktile，模型 513；同形状 cfg_a 为 513，正好相符。cfg_b 是 cluster 1×1，没有 B 多播，每个 CTA 从 L2 取的数据比 cfg_a 多；后续对照中同类形状 cfg_b 为 525–571 cycle/Ktile，cfg_a 513–523，cfg_c 与理论值 1024 相差 1% 内（见下节）。
4. **频率在很长窗口上偏低。** h06 窗口约 650 µs，超过校准最长的约 410 µs；三个配置的频率解都低 6%–7%，cfg_a、cfg_c 因此偏长约 5%。
5. **cfg_c 单 tile 的 epilogue 随同时输出的 CTA 数变化。** T=1 时模型用 E0≈5784 cycle（校准中所有 CTA 同时写出的情形），而 h08、h09 实测约 4040，偏长 37%～43%。校准中的 g1、g3 也只有约 4040。输出窗口受同时写出的数据量限制，V08 只对 T≥2 的末 tile 试过这一形式。

尾部本身和 D 行距几乎无影响；A、B 的行距不是 128 B 倍数时 cfg_b 明显变慢，cfg_a 次之，cfg_c 不变。

**按每 SM 的操作数供给解释。** 每个 Ktile 的计算为 512 cycle（cfg_c 为 1024）。按 cluster 多播只读一次计算，每 SM 每 Ktile 从 L2 取的字节：cfg_a 24 KB（A 16 KB + B 16 KB/2），cfg_b 32 KB，cfg_c 32 KB/1024 cycle。对应需求 48、64、32 B/cycle/SM。实际交付的“对齐字节”：

| 条件 | cfg_a | cfg_b | cfg_c |
|---|---|---|---|
| 对齐、L2 内 | 48（计算限） | 64（计算限） | 32 |
| 大足迹（105–260 MiB）长 K | 47.0–47.9 | 57.3–63.7 | 31.8–32.0 |
| 一个操作数行距未对齐 | 45.2–47.6 | 46.1–56.7 | 32.0 |

cfg_c 需求最低，从不受限；cfg_b 需求最高，最先受限。推断：主循环受“计算”与“每 SM 操作数供给”两者中较慢者限制；未对齐行距让同样的有效字节需要更多传输，大足迹让 L2 命中下降，都降低可交付的供给。本组数据还不能把“未对齐的放大倍数”与“供给上限”分开定值（无 NCU 计数）。

**swizzle=8 的补齐 tile。** 三个形状（只沿 M、只沿 N、两向补齐）× K 1024/4096。补齐使 T 增加 0–3，总时间比 swizzle=1 多 25%–80%（cfg_b 的 3072×3072 是 8 的整数倍 tile，不需要补齐，+0.6%/−2.4%）。补齐 tile 相对有效 tile 的额外 cycle/Ktile：cfg_a 47–384，cfg_b 399–443，cfg_c 78–631，且随 K 增大（cfg_a 沿 N：K=1024 时 190，K=4096 时 384）。沿 M 补齐的 tile 整块 A 在矩阵外，沿 N 补齐的整块 B 在矩阵外，但仍完整执行主循环（越界部分由 TMA 填零）；它的代价不是常数比值，V08 的 ρ 不能迁移。

## 记录的偏差

- 留出采样在第 5 轮被一个 11 µs 小形状（cfg_b_h09 stamped）的预热稳定性检查（末 5 次 CV ≤ 2%）连续三次拦下而中止。用单独的续跑入口 `resume_v08.py`（不改冻结源码和预测）把这一类失败的重试上限从 2 提到 5 后完成；该进程在第 3 次重试通过。所有 1080 个留出进程数值正确。
- 5 个校准条件因 stamped 扰动或 CV 超过 5% 不参与区间拟合（cfg_a c3、g1、b2176×1536×8192，cfg_c c3、g2），仍参与时间换算。

- 复算检查：用 `source-fit/` 重跑拟合与评分，评分结果与正式结果逐项相同；拟合参数中频率规则与冻结值有约 1e-5 的相对差。原因是沿用自 V06 的 DRAM 字节估计按集合遍历顺序更新 LRU，而该顺序随 Python 哈希种子变化；换不同种子时 36 个预测与冻结值的最大相对差为 2.5e-4，不影响判定。仓库代码已改为排序遍历。
