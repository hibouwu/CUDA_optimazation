# 预测、测量与验证细则

<a id="prediction-boundary"></a>

## 预测输入与支持范围

运行前预测只用程序与静态条件、参考卡冻结参数和声明的调用协议。静态条件包括 cfg、tile/cluster、stage、grid、调度、M/N/K、行距、分配、输入 map、swizzle/raster、输入模式与 seed。源码、二进制和设备身份记录在对应 manifest。

主线参考卡为 romeo-a057 / GPU-43269fbc。每个进程加载模块后，仅运行目标自身的自适应暖机，末 5 次 CV≤2% 后计时一次，与 V09 相同。目标、暖机和前序调用的计时、频率、trace 只用于诊断，不进入正式预测。缺匹配桥接的 ends/dual 数据不能默认合并；其他卡的绝对参数不能直接迁入。

支持范围在冻结前按校准覆盖声明。非 128 B 对齐行距、非默认 stage 与原拒绝项保持不支持；范围外条件照常记录并单列，不改写原轮次成绩。V09 可用于开发，重算 V09 不能称新留出通过。

<a id="measurement-checks"></a>

## 按待测量量决定停止条件

**使目标测量无效的检查失败，停止相应条件或用途；其他差异记录并限制用途。** 停止整个批次只用于影响全批目标窗口的共同故障。结果缺项、失败样本和原因都保留，不删行包装为通过。每次任务在测量前声明下面哪些检查适用及其数值界限；具体故障恢复沿用获批任务的预算。

| 测量用途 | 直接影响有效性，失败时停止相应用途 | 记录或限制其他用途，不能单独据此否定目标窗口 |
|---|---|---|
| 内核内的局部 L | 窗口端点、完成等待、trace ABI、SASS 与依赖正确；同 SM 周期相减成立；结果正确、记录完整；相关局部参照与计时换算满足预定稳定性要求 | event−内核包络变化先限制旧完整时间转换。单独漂移不证明 L 无效；保留有效局部开发数据，参数是否可转移仍需相关参照与协议桥接 |
| 单 CTA LDS/STS | 循环内目标数量与宽度、地址合法性、参与线程、实际依赖、消费者及资源正确；空窗口／消费控制、同期负对照、桥接与波动满足本任务要求 | 完整 GEMM 的 event-extra 不作为本任务停止条件；没有内部计数器时，时间模型不能升级为实测事务或唯一端口解释 |
| 完整 GEMM 时间 | 正确性、plain 时间、频率换算、内核包络及 event-extra 均在目标中；相应参照异常会阻碍旧参数迁移或完整评分 | 局部数据有效不代表完整时间转换兼容；相关局部数据可保留供开发，完整用途另行标记 |

噪声或桥接失败时，先判断影响的是单个条件、局部参数迁移还是全批协议。保留“尚未分辨”状态，不以开发数据可用宣称参数已验证。正确性与必需同步、合法地址和指令身份始终检查。

741159 按原 0.5 µs event-extra 门槛停止的记录保持原样，540 个开发槽位仍是未执行。上述划分用于未来任务；修改未来检查不增加作业预算、不使旧参照变成通过。

## 计时与数据

- 基线和变体在同一分配、同一卡、同批次交错运行。旧数据作趋势参考；合并拟合需要匹配协议桥接。记录 UUID、SMID、工具、SASS、资源和实际调用序列。
- clock64 只在同一 SM 内相减，globaltimer 用于跨 SM；短窗口保留空窗口、重复长度、分辨率和消费端点。plain、ends、wide、dual 分别维护边界。
- 正确性在计时外单独检查，保留 ISA 要求的参与、同步与依赖。初始化、预热、轮换、计时前探针及输出会改变状态，工作集小于 L2 不是命中的证明。
- 没有计数器时，不同时拟合无法区分的流量放大与带宽下降，不从时间拟合推断唯一内部事务、端口或缓存路径。其他架构的资料只用于提出假设，不提供 GH200 常数。

<a id="model-interface"></a>

## 模型与代码

沿用 [model/interfaces](../../../model/interfaces.md)：输入说明指令、地址、参与范围与事先可知的状态；模型说明需求、共享资源、占用与释放，以及 eligible、issue、complete、visible、release 中哪些事件能预测。在途需求不超过容量，开始须满足依赖、资源可用与实际发射约束；只有资源和顺序确定后才能简化为 max 递推。参数无法分别识别时保留候选解释。

局部 L、供给 S、输出 E 可作比较基线；改成显式组件时去掉已有聚合收费。周期与纳秒按同一作用域换算，最长周期 CTA 与最晚退出 CTA 分开判断。经验字节率是条件估计，不能替代启动、排空、依赖或返回成本。

新对照先由公开资料或物理推理写出可区分的预测，再选最少条件；优先用已有反例淘汰形式。代码优先复用原入口和实际重复逻辑，旧一次性脚本保留复现用途，不为每个问题建立新框架或镜像测试。

<a id="validation"></a>

## 留出与采用

每条机制规则先用未参与拟合的新组织检验；旧数据只作开发或回归。指标和容许误差在冻结前按分辨率确定，同时报告相对误差、绝对周期／时间误差和粒度。已测、开发关系、独立留出通过、用于组合预测分别记录。

<a id="order"></a>

V10 先有候选和新条件；必要校准完成后冻结参数、全部预测、协议、支持范围与指标，回传最终预测和 manifest 的 SHA，由用户确认该版本后采留出。预测或参数改变需重新确认。采样后不回调同轮参数；V10 之后不自动启动 V11。

<a id="full-validation"></a>

V10 留出按校准覆盖选择，至少六个新的 M×N 基形，涵盖 square、tall-skinny、short-wide 与不同波次；各 cfg 都有新形状。支持范围内覆盖未训练的短／中／长 K、新的 128 B 对齐行距、边界方向及 swizzle、输出并发与尾波；使用 dyadic 和新 seed 的随机有限 FP16，随机正确性在计时外检查。少量范围外行距、stage、K 单列不支持。

完整时间全组绝对相对误差中位数 ≤5%、最大 ≤10%。冻结后数值错误、超时、无预测或精度失败都留在预列组中。供给、输出、分项及关键 CTA 按冻结前各自写定的局部标准判断，不能被总时间覆盖；全组与跨卡要求单独记状态。

组合检查由 [V01](V01-validation.md) 和新完整 GEMM 轮次承担：比较初始供给、稳态、最后主循环、输出及偏差方向；核对 CTA 工作数、预测终点、最大局部周期和最晚退出者；分别报告包络、CUDA event、频率和换算周期的误差。

## 维护与交付

最多并行一个主线和一个机制任务，各有边界、预算和终点；主集成串行维护公共文件。新研究或超预算作业另经用户批准，不能自动扩展。实际分工、设备和状态见 [EXECUTION](EXECUTION.md)。

正文先写发现、关键数字、限制和下一问题；会话、授权、构建／二进制／协议 SHA、分配与传输证明放对应 manifest 或执行记录。保留原数据、失败和冻结文件；不改已有只读归档。证据写回原实验页，详细推导写入对应 reanalysis；现行公式见 [MODEL-CANDIDATES](MODEL-CANDIDATES.md)，通过独立留出的规则才进入 [RULES](RULES.md)。
