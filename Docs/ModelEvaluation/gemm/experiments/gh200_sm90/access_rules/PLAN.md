# 当前计划：GH200 GEMM 时间预测的剩余误差

更新：2026-10-08。

## 现状

预测为 T = F + κ·C/f，C 为逐 CTA 事件递推的最大 CTA 周期。[V08](V08-wider-validation.md) 在同一张 GH200（GPU-099dda56）上的 36 个新留出条件：总时间中位 2.61%、最大 35.34%，未达标；其中 swizzle=1、A/B 行距为 128 B 倍数、K ≤ 16384 的 21 个为 1.90% / 6.04%。跨卡未验证。

已完成：

- [V07 事后诊断](V07-rule-validation.md#事后诊断总时间为何接近离线不改判定)：V07 的 20/24 偏长主要来自打点开销；普通 CTA 偏长与最慢 CTA 超出量相抵；cfg_a 边界的最慢 CTA 不是边界 tile 所在 CTA。
- V08：ends 低扰动计时（扰动中位 0.88%）；L2 驱逐对照（供给 S 随 L2 驻留变化）；末 tile epilogue 单独取值；cfg_a 边界增量按列数；按校准留一选择各项；冻结后测 36 个新形状。
- V08 后续对照：尾部与 D 行距无影响；A/B 行距未对齐、swizzle 补齐 tile、大足迹长 K 三类失败都与每 SM 操作数供给相符。

## 剩余误差

| 项 | 证据 | 影响 |
|---|---|---|
| 操作数供给上限 | 每 SM 需求：cfg_b 64 B/cycle，未对齐行距时只交付 46–57，大足迹 57–64；cfg_a 48，降到 45–47；cfg_c 32，不受限 | h03 −35%、h06 −14%；未对齐行距在实际负载中常见 |
| swizzle 补齐 tile | 额外 47–631 cycle/Ktile，随 K、方向、配置变化 | h07、h10 偏差 8%–14% |
| 输出窗口 | cfg_c 单 tile epilogue 在全部 CTA 同时写出时约 5800 cycle，部分 CTA 时约 4040 | 小形状偏长约 5% |
| 频率 | 窗口超过校准最长（约 410 µs）时频率解低 6%–7% | 很长的调用偏长约 5% |
| 供给 S | 中位误差 7.7%，最大 27%；L2 驻留是主要因素，足迹不能完全解释 | 主要影响短调用 |

## 下一步：V09

1. **主循环加供给上限。** 每 Ktile 主循环取 max(计算，操作数字节 × 放大倍数 / 每 SM 供给)。字节按配置和多播计算；放大倍数按 A、B 行距是否为 128 B 倍数取；供给上限随 L2 命中（足迹、工作集）变化。先用 V08 与后续对照的数据离线拟合，同时解释三种配置才进入模型。
2. **补齐 tile。** 不再用常数比值；检查补齐 tile 能否同样用供给上限解释其随 K 增大的代价。解释不了则把 swizzle 补齐列为模型范围外，并在预测中报告补齐 tile 数。
3. **输出窗口。** epilogue 取 max(单 CTA 时间，同时写出字节 / 写回带宽)，同时写出的 CTA 数由调度直接算出。
4. **校准补点。** 未对齐 A、B 行距 × 三配置 × 2 个 K；窗口 > 600 µs 的条件各一个；补齐形状再加两个。
5. **验证。** 重新冻结，在同一张卡上测新的留出集，目标不变（中位 ≤5%、最大 ≤10%）；V07、V08 的留出点不再用于判定。之后单独做跨卡：先只用原参数预测，再看哪些项需要在新卡重新校准。

物理 RF 端口、缓存命中率、所有访问路径达到 Thor 分析深度不属于当前目标；需要时另立目标。
