# GH200 规则补测计划（V04 失效项）

2026-10-07。状态：采样与验收交付完成，保留明确负结果和观察范围限制；V05迁移未整体通过，分项结论见[实验与结果](README.md)。

## 1. 目标

[V04](V04-config-transfer.md) 把 V02 的模型迁移到 cfg_a/b/c 时，有四处具体失效。本轮只补这四处，然后用 V05 检验迁移是否成立。

| 失效 | V04 证据 | 本轮实验 |
|---|---|---|
| cfg_b 在 2600×3000×2000 主循环 788 cycle/Ktile（正常约 512） | 推测 B 行距 6000 B 只按 16 B 对齐，未做对照 | R10 |
| 单 SM 供给上限：按 R05-D 的 55 B/cycle 判为供给受限，实测约 64 | R05-D 的消费者不做计算，与真实 WGMMA 消费不同 | R13 |
| 小 tile 每个 tile 有约 1500 cycle 不随输出字节缩小 | E 实测 3370–3860 cycle，其中输出 store 约 2000 | R15 |
| pingpong 短 K 时每 tile 多 900–1400 cycle | epilogue 只在长 K 被另一组主循环覆盖 | R14 |

- 设备与工具链：ROMEO 单 GH200、CUDA 12.9、`sm_90a`、CUTLASS v3.9.2、`-DNDEBUG`。
- 完整 GEMM：FP16 输入、FP32 累加与输出，α=1、β=0。
- 配置沿用 V04：基准 128×256×64 cooperative、cluster 2×1、4 stage；cfg_a 128×128×64 cooperative、cluster 2×1；cfg_b 128×128×64 pingpong、cluster 1×1；cfg_c 256×128×64 cooperative、cluster 1×2。
- 默认 63 个资源条件，V05 另 18 个验证条件。

## 2. 实验

| 组 | 矩阵 | 数量 | 计量与判读 |
|---|---|---:|---|
| R10 行距 | 2600×3000×2000，cfg_a/b/c × `ldb` = 3000/3008/3072（B 行距 6000/6016/6144 B） | 9 | 记录主循环 cycle/Ktile 与完整时间；按实际 stride 初始化、检查，记录 padding 哨兵。若 6016/6144 恢复而 6000 变慢，说明行起点对齐是原因 |
| R13 供给与退役 | 输入 tile 32/48 KiB（128×128×64、128×256×64）× stage 1/2/4 × 消费者：等待后直接释放 / 64 条依赖 FFMA / 真实 WGMMA | 18 | 每序列 32 个 Ktile，同形状统一预留 4 槽。记录发出、等待返回、消费完成、槽释放、下次补发；报告每 SM 的 B/cycle，与 55、64、48（满速需求）比较 |
| R15 输出服务 | FP32 输出 64/128 KiB；单缓冲：寄存器→SMEM、只 TMA 写、完整输出、单独后台 WGMMA、串行、并发（12）；双缓冲：完整输出及两种组合（6） | 18 | 按实际累加器片段映射，16 KiB 分块；每块配 16 条独立后台 WGMMA。区分整理、源读完、源释放与完整写回，`.read` 不算写回完成 |
| R14 tile 交接 | 基准、cfg_a、cfg_b × K = 128/512/4096 × 每 CTA 1/8 个输出 tile；grid 限 4 CTA，M=256 | 18 | 逐 tile、按角色记录获得工作、首个 MMA、主循环结束、epilogue 许可、源释放、下一 tile 开始；记录所有 tile，不只最后一个 |

每组先跑一对代表点，确认能分辨目标差异，再跑全矩阵。

## 3. V05：迁移验证

用 R10/R13/R14/R15 修订后的规则，对 cfg_a/b/c 各预测下列 6 个尺寸，共 18 点：

| M×N×K | 用途 |
|---|---|
| 1280×1536×1536 | 不满一波 |
| 2304×4096×256 | 短 K、多波 |
| 4096×5120×1024 | 中等 K、多波 |
| 5120×7168×3072 | 较大输出 |
| 1024×3584×12288 | 长 K |
| 2696×3336×1544 | M/N/K 尾部，A/B/D 行距补到 128 B 对齐 |

- 冻结前检查"配置＋尺寸＋布局"没有在旧实验或本轮校准中出现过；冲突时 M 每次加 128，取第一个未用的组合。
- 任何 V05 测量之前冻结：工作分配、各阶段周期、重叠关系、参数来源、预测文件 SHA256 与时间，文件设为只读。
- 判定：关键 CTA 与主要阶段（供给、主循环、输出、交接）的周期误差各自中位数 ≤10%、最大 ≤20%，分项判定，不允许误差互相抵消。小于 512 cycle 的阶段先看事件顺序。微秒预测单列；测后代入实测频率只作诊断。
- 未通过时指出失配的关系，不用同批数据回拟合后称为通过。

## 4. 执行与验收

- **执行**：每组一个 agent，按 R10 → R13 → R15 → R14 → V05 推进；CPU 准备、源码与 SASS 分析可以并行，GPU 采样串行。同一个 GH200 节点上不并行采样（V03 与 V04 并行时频率可能互扰）。
- **代码**：每组 `run_rXX.py`、`analyze_rXX.py`、`probes/rXX.cu`，新代码可读、行宽约 100。只新增一个共用的 `probes/gaps_common.hpp`，提供显式 `lda/ldb/ldd`（以元素计）、padding 哨兵与检查；不建新的运行框架。
- **结果**：`results/gh200_resource_campaign/access_rules/<YYYYMMDD>-<组>-job<id>/`，含 `source/`（编译时版本，之后不替换）、`build/`（命令、SASS、资源、二进制哈希）、`samples/`、`cases.csv`、`summary.json`。改分析用新子目录，改测量源码用新运行目录。
- **采样**：单 CTA 3 个进程，CV>1% 或配对差接近噪声时补到 10；整卡、完整 kernel 与 V05 为 10 个。预热 8–30 次，末 5 次 CV≤2%。配对相邻、顺序随机。plain 测服务率，trace 成对核对扰动，超过 5% 时缩小打点范围。
- **验收**：SASS 中目标指令与动态次数正确、输出经 CPU 校验、样本稳定、数值与已知物理量级相符。不同 GPU UUID 的样本不共同拟合。
- **文档**：每组一页 `RXX-*.md`（问题、矩阵、计量、结果、可用规则与限制、复现），开始实施时再建。

## 5. 条件扩展（默认不做）

| 项目 | 启用条件 |
|---|---|
| R02 寄存器供给与结果流 | 主循环、epilogue、RS 取数或 FP8 提升出现现有规则解释不了的稳定差别 |
| R11 混合发射（FFMA+IMAD.WIDE、LDS+CVT、WGMMA+IMAD） | V05 的某个阶段失配，且 SASS 显示该阶段有这些指令混合 |
| R12 SMEM 多路竞争（TMA 写、WGMMA 取数、STS） | R15 的"输出＋后台 WGMMA"出现 R13/R15 解释不了的差别 |
| R16 驻留与寄存器配额 | 选定方案每 SM 驻留 2 个以上 CTA，或依赖 `setmaxnreg` 的重分配成本 |
| R10 的补齐与缓存准备 | 行距之外仍有布局或缓存相关的未解释差别 |
