## 原实验如何继续

已有 EXP-05–20、R00–R19、B01 和 V 系列是后续工作的主体；EXP-04、R04、R07、R17 已按维护位置并入其他页面，原页保留跳转。下面的每项都指定原文档与代码入口，沿用原实验编号，在原实验中补充条件、分析和结论。25 类机制只是问题划分，不是 25 个新实验；m01–m25 仅保留为报告跳转锚点。

- **文档**：同类结果追加到原实验页的扩展小节，写明日期、适用条件、旧结果与新增证据的关系。不另建重复的实验页，也不把原结果改写成新测结果。
- **代码**：优先给原 runner、配置和 probe 增加模式或参数，保持原模式可复现。已有实现不足时，在同一实验目录补必要实现，不另建一套并行运行框架。冻结源码副本只读，扩展在维护中的源码上进行。
- **数据**：原数据先离线复用；缺少对照时补测到以原实验编号命名的新 run-id。新运行单独保存源码与结果，避免覆盖旧证据；它仍属于原实验。
- **归属**：跨机制问题按原实验职责拆分，例如 R18 负责边界路径、R19 负责关键 CTA，两者相互引用，不重复保存一份结论。地址翻译等尚无独立测量的子题先纳入 B01；当前没有预设必须另开编号的项目。
- **合并**：合并的是维护位置，不把不同协议的数值合成一条规则。迁出的内容连同失败记录、修订原因和原始证据链接一起迁移，原页保留跳转；原始归档、代码和冻结记录不变。
- **验证**：局部留出写回对应原实验。中间层组合验证由 [V01](V01-validation.md) 承担，完整 GEMM 的新验证轮次从 V09 起独立编号；二者沿用现有验证代码，各自独立冻结与统计。V07、V08 的冻结预测和成绩保留，测后修模不算原轮通过。

## 1. 主线：消除 V08 的失败项

[V08](V08-wider-validation.md) 的 36 个新留出条件为 2.61% / 35.34%，整体未达标。失败集中在 A/B 行距未按 128 B 对齐、swizzle=8 的整 cluster 补齐 tile、cfg_b 大足迹长 K、超过校准范围的长窗口频率，以及 cfg_c 单 tile 输出。下表五步直接决定完整预测能否改善，优先于第 4–7 节的独立机制项。第 4–7 节的局部探针为主线提供解释和留出，主线不等待它们全部完成。

| 步骤 | 负责页 | 先做什么 | 输出与限制 |
|---|---|---|---|
| 1. 有效供给 | [R13](R13-async-retirement.md) | 离线检验“每 Ktile 主循环取计算与供给中较慢者”，数据为 V08 后续对照 84 个条件中可比的主循环记录和 V08 校准 | 有条件的有效供给函数；不能从现有计时同时定出物理供给上限和请求放大倍数 |
| 2. 补齐 tile | [R18](R18-cluster-boundary.md) | 检查补齐 tile 随 K 增大的额外代价能否由步骤 1 的供给函数解释 | 解释不了则把 swizzle 补齐列为模型范围外，预测中报告补齐 tile 数 |
| 3. 输出窗口 | [R15](R15-output-service.md) | 先用 [已有 CUTLASS 观测](R15-output-service.md#cutlass-epilogue) 离线检验：epilogue 取单 CTA 时间与同时写出字节所需服务时间中的较大者，同时写出的 CTA 数由调度直接算出 | 最后一个 tile 与中间 tile 分开；窗口终点不等于全局写完成 |

### 有效供给函数

- **离线检验。** 每 SM 每 Ktile 的需求按 cluster 多播只读一次计算：cfg_a 24 KB、cfg_b 32 KB、cfg_c 32 KB/1024 cycle，即 48、64、32 B/cycle/SM。可交付供给作为配置、A/B 行距余数、足迹或 L2 驻留和多播的条件函数拟合。启动、排空、有限 stage 和 OOB 不放进同一个稳态 max：启动归首段供给 S，排空与有限 stage 归 [TMA 在途扩展](#m14)，OOB 归步骤 2。候选形式须同时解释三个配置才进入模型。
- **行距补测。** 在 [R10](#m13) 补 A 行距与 cfg_a，K 取两点，条件见该节。
- **多播对照。** 分别做两种配对：一种保持每 SM 消费的 payload 相同，另一种保持 L2 源端读取量相同。二者回答不同问题，不互相替代。
- **活动 SM 扫描。** 用 `hw_info.sm_count` 限制持久 grid，V03 已用过这种方式。实际活动 SM 数由 SMID 与执行窗口重叠确认，不按 grid 推定。扫描同时改变频率、缓存重用和全卡需求，因此按 cycle 比较并单独记录频率；它帮助区分本地与共享瓶颈，单凭一条曲线不能唯一归因。
- **计数器。** 取得权限后才尝试把放大倍数与供给上限分开；否则只输出条件服务和相对变化，见第 3 节。

### 校准补点与新完整验证

- 补点：未对齐 A、B 行距 × 三配置 × 2 个 K；窗口超过 600 µs 的条件，每个配置各一个；补齐形状再加两个；输入数值三档的代表条件。
- 新一轮完整验证从 V09 起独立编号，规则确定后重新冻结，在同一张卡上测新留出；覆盖组织见[第 9 节](#full-validation)。之后单独做跨卡：先只用原参数预测，再看哪些项需要在新卡重新校准。

## 2. 研究范围与要输出的规则

覆盖 GH200 / SM90a 单 GPU 计算路径：指令与寄存器服务、warp 调度、资源驻留、异步运输与计算、存储层次、跨 SM 共享、CTA/cluster 工作分配，以及周期到完整时间的换算。以当前 CUDA 12.9.41、CUTLASS 3.9.2 为基线；编译器版本、输入精度和执行组织作为规则条件记录。其他架构的论文用于提出候选解释，不直接提供 GH200 常数。

本轮有两个相互连接的目标：

- **独立机制模型**：给定指令、地址、布局、参与线程与前序状态，预测服务时间、消费者可用时刻、资源释放时刻及竞争造成的变化。RF、调度、缓存等研究不以“先证明影响当前 GEMM”作为启动条件。
- **组合预测**：把经过局部验证的规则接入事件模型，解释并预测实际 GEMM 的供给、主循环、输出、关键 CTA 和完整时间；不能用总时间接近掩盖分项错误。

“覆盖全面”指每类影响计算路径的机制都有现有依据、可区分的假设、最小实验和验证方式。它不要求遍历整个 ISA、所有变量的笛卡尔积，也不承诺仅凭计时恢复唯一的物理实现。图形流水线、多 GPU NVLink、Grace–Hopper C2C 和统一内存迁移不属于此处的首轮范围；地址翻译实验使用 GPU 本地分配并排除迁移。若以后研究这些路径，另列工作负载和模型边界。

<a id="model-interface"></a>

### 共同的模型接口

沿用 [model/interfaces](../../../model/interfaces.md) 的操作与事件定义。每条规则应说明：

1. 输入条件：指令及实际 SASS 操作数、访问尺寸和地址、参与范围、缓存/在途/寄存器状态。
2. 需求如何形成：指令数、字节覆盖、事务或服务批次；测不到内部事务时保留可观测的请求单位。
3. 使用哪个共享资源、占用多少、何时释放；共享范围可能是 warp、子分区、CTA、SM、cluster 或整卡。
4. eligible、issue、complete、visible(consumer)、release(object) 中哪些事件可预测，哪些只测到外部窗口。
5. 参数范围、不能区分的候选解释，以及未参与拟合的组织方式上的误差。

对有限资源使用占用约束：在时刻 t 尚未释放的对象需求总和不能超过容量。对共享服务使用各路径的需求与服务率关系。依赖允许的最早开始、资源可用和实际发射都必须满足；仅在资源和执行顺序已确定时，才能将它们简化为一个 max 递推。只有带宽是相同作用域、相同需求口径下的有效服务率上界时，字节/带宽才构成相应下界；用经验带宽得到的是条件估计。两者都不能代替启动、排空、返回与依赖等待。

现有聚合主循环 L、供给 S、输出 E 可以继续作比较基线。某一阶段改用显式组件后，必须去掉该阶段已包含的聚合代价，避免重复收费。

## 3. 所有实验共用的条件

- 先读对应旧数据与探针，能离线判定的先判定。需要新增测量时，基线和变体在同一分配、同一卡、同批次交错运行；旧 run 可作趋势参考，不能替代同期基线。记录 GPU UUID、编译工具、SASS、资源与实际运行条件。
- 指令服务先用短、可数、结果可检查的片段。固定动态指令数、依赖链、循环与计时代码；报告 ptxas 寄存器、SMEM、spill 和实际 SASS 差异。不同汇编版本“声明同样多寄存器”仍不足以说明寄存器映射相同。
- 正确性检查使用能区分寄存器、线程和 tile 的非均匀数据，单独执行，避免把校验本身放入目标窗口。始终保留 ISA 要求的同步与依赖控制；改变合法间隔后出现错误，说明该条件无效，不能从错误阈值推导物理就绪时刻。
- clock64 报告本 SM 的周期；globaltimer 报告跨 SM 的时间。对短窗口先测量本机计时粒度与固定开销，再决定重复长度。plain、少量端点记录和细粒度打点分别比较；计数器单独采集，不与正常计时混用。
- 声称测量 visible/complete 的结束时钟，必须受实际消费者或对应 ISA 完成等待约束，并核对最终 SASS；仅在窗口外保存正确结果，不证明窗口已覆盖结果就绪。时钟读取和记录本身会占用寄存器与发射资源，需要匹配开销对照。
- 每个最小对照先做一个小批次，依据波动扩大重复次数；保留中位数、离散程度和原始样本。差异未超过同期噪声时，报告“在此精度内未分辨”，不写成没有该机制。
- 对齐、参与线程、地址生存期和同步遵守 [PTX 8.8](https://docs.nvidia.com/cuda/archive/12.9.1/parallel-thread-execution/index.html) 与 [tensor-map API](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-driver-api/group__CUDA__TENSOR__MEMORY.html)。部分 active mask 只用于允许这样执行的普通 ALU/LD/ST；ldmatrix、stmatrix、WGMMA、setmaxnreg 按各自规定的 warp/warpgroup 一致参与。
- 缓存准备记录实际访问序列：初始化、预热、轮换、计时前探针及输出写入都可能改变状态。“工作集小于 L2”或“池大于两倍 L2”是实验条件，不是命中/未命中的证明。
- 计数器的 request、sector、wavefront、物理字节按其所在层解释；普通 L1TEX 计量不能直接替代 TMA 内部请求。计数器不可用时仍可建立条件时间模型，但不同时拟合无法区分的“流量放大”和“带宽下降”。
- **计数器权限**：[2026-09-30 诊断](../../../../../../microbench/gh200_l0/results/20260930-counter-access/README.md)已记录 RmProfilingAdminOnly=1，普通与独占作业都不能直接使用 NCU；R16 在 V08 所用的卡上再次得到 `ERR_NVGPUCTRPERM`。申请权限是“物理流量分解”类目标的准备工作，例如请求放大、L2/DRAM 物理流量，不是整个计划的前置门槛。取得权限后仍要确认指标覆盖目标路径并能隔离其他流量。管理员授权的联系由用户/ROMEO 账户持有人负责，具体待办见[执行规范](EXECUTION.md#counter-access)。拿不到时，这类目标改为条件服务、相对变化和并发规模响应，供给研究照常进行。
- **跨卡共同参照**：每张参与校准或验证的卡先跑一小组共同参照：负载下的调用内频率、对齐行距下的每 SM 供给、大工作集读请求速率、event 与内核包络之差。它们用于判断差异来源和哪些参数需要重标定。旧数据能否换算须有同协议的桥接验证；RF 服务、缓存行为、TMA 等待与主机侧时间不一定服从同一比例。缺少匹配条件的旧数据不进入同一拟合，大工作集读速率在没有流量证据时也不改称物理 HBM 带宽。
- **输入数值**：GEMM 探针输入是 `probes/r00_common.hpp` 中 17 级二进分数的正确性见证，不是任意数据。涉及功耗、频率或完整时间的结论注明输入条件；数值对照见 [R09 扩展](#m25)。
- 只补原实验所缺的局部探针和分析；下文“扩展位置”是结果写回的位置，不只是参考文献。旧实验正文可以追加新批次，原冻结记录、源码快照、旧 run 和归档保持原样，不重新分配实验编号。

## 4. 指令、寄存器与执行资源

<a id="m01"></a>
### R01 扩展 — 依赖解除与结果可用时刻

**扩展位置。** [R01](R01-readiness.md) 的依赖与就绪小节；扩展 [run_r01.py](../../../../../../microbench/gh200_resource_campaign/access_rules/run_r01.py) 和 [r01.cu](../../../../../../microbench/gh200_resource_campaign/access_rules/probes/r01.cu)，复用原依赖链与独立流参照。

**已有依据与缺口。** [R01](R01-readiness.md) 测过依赖链和独立流；其中 FFMA 4.265625 cycles/step 含有限展开与控制成本，4.00 是外推值。缺的是按生产者、消费者和操作数位置组织的可用性规则。

- **假设与最小对照**：固定一个 warp 和寄存器帧，先比较 FFMA→FFMA 的 A/B/C 消费位置，再做 LDS→FFMA、地址计算→LDG、LDSM→mma.sync。对每对指令插入 0、短、中、长独立工作，出现转折后只细扫附近。每种间隔都有相同动态工作量的独立参照。
- **观察与排除**：分别记录输出正确性、链的总周期和独立流启动间隔。RAW、WAR、WAW 分开；控制字段、scoreboard 等待和时钟指令自身开销一并检查。安全调度下得到的是该执行条件中的可用时刻或上界，不能据此直接命名 RF 物理写入时刻。
- **规则与留出**：输出“生产者类型×消费者类型×源位置×控制条件”的就绪关系。留出未拟合的链长、消费位置组合和独立工作组织；检验按关系组合的预测，而非只复现单条链。

<a id="m02"></a>
### R02 扩展 — 寄存器读服务与源映射

**扩展位置。** [R02](R02-register-service.md) 的源读取/固定寄存器帧小节；沿用 [run_r02_source_frame.py](../../../../../../microbench/gh200_resource_campaign/access_rules/run_r02_source_frame.py)、[run_r02.py](../../../../../../microbench/gh200_resource_campaign/access_rules/run_r02.py) 和 [r02.cu](../../../../../../microbench/gh200_resource_campaign/access_rules/probes/r02.cu)，增加源映射对照。

**已有依据与缺口。** [R02](R02-register-service.md) 在同为 40 个寄存器的版本中发现轮换源慢 5.26%；两个分支的物理 GPR/UR、reuse 与调度仍有差别，尚不能归因于某个读端口或 bank。

- **假设与最小对照**：同一 opcode、逻辑链数、源值、动态指令数与控制字段下，比较基准源编号、交换 A/B、整体平移编号，以及从结果中发现的候选冲突组。先用 GPR；UR、立即数另作一条轴。比较“两源为同一寄存器”与“两寄存器持有相同值”，区分请求去重和数据值影响。
- **隔离方式**：先选一条依赖链，再选八条独立链；分别辨认可用延迟和持续服务。源编号、目标编号、代码位置分阶段改变，不能一起改。若使用汇编修改，先验证选定 SM90a 指令的原样往返、反汇编、数值与基线计时；CuAssembler 的公开支持列表不能替代这个验证。工具不支持时采用编译器生成的匹配对照，并缩小因果结论。
- **规则与留出**：输出源类型、源位置、寄存器映射和并发条件下的服务等价类；有独立证据时再提出 bank/端口映射。留出另一组物理编号和不同逻辑链排列，检验规则是否只记住了一个片段。

<a id="m03"></a>
### R02 扩展 — reuse 状态、寄存器缓存与失效

**扩展位置。** [R02](R02-register-service.md) 同一源服务研究中的 reuse 小节；复用上一项的固定帧、运行入口和 SASS 记录，增加复用/失效模式，不另开 RF-cache 实验。

**问题。** 同一寄存器再次作为源时，服务是否依赖 reuse 提示、距离、源槽位、其他访问和中间写入？硬件是否真的存在某种缓存，只作为候选解释。

- **最小对照**：在[源映射扩展](#m02)的可控片段上，比较 reuse 提示开/关与近、中、远三种复用距离。用填充指令保持静态长度与总工作相近，分别改变“不同源寄存器数量”和“距上次使用的指令数”。随后仅加入同源位置或异源位置的干扰。
- **失效与共享范围**：比较重写同一寄存器为新值、重写其他寄存器和不重写；校验消费者确实读取新版本。再加入另一个 warp 的干扰，区分 warp 私有状态与更广的共享服务。不能把另一个 warp 引起的发射竞争直接算作缓存逐出。
- **规则与留出**：候选状态至少区分 warp、源槽位、寄存器编号、值版本及近期历史。报告命中/失效候选关系或仅报告可重现的 reuse 收益。留出新的交替源序列和 write→reuse 序列；距离转折不能单独确定物理容量。

### R02 扩展 — 结果返回、写回竞争与旁路

**扩展位置。** [R02](R02-register-service.md) 已有保留结果、消费尾部和混合返回小节；在原 r02.cu / run_r02.py 中补相位与目的映射对照。

**问题。** 两条生产路径同时完成时，消费者是否被额外延后；这种延后来自发射、源读取、结果返回，还是依赖转发？

- **最小对照**：先做 FFMA 与整数运算，再加入 LDS 返回。各路径先测单独服务；通过独立前缀改变其预计完成的相位，比较早到、近同时、晚到三种组织。固定源映射、目的寄存器数、地址与缓存准备；每条路径都有立即消费和延迟消费版本。
- **分辨步骤**：先看各路径的可用时刻，再看总窗口。只有源读取与发射的差异已排除，才把目的映射扫描用于检验返回端竞争。改变返回结果数量与改变依赖距离分开；LDS 地址变化造成的供给差不能冒充返回端口效应。
- **规则与留出**：输出“完成路径×相位×消费者”的可用延迟或共享服务约束。计时不能直接看见 RF 物理落盘，旁路与提前写回若等价则同时保留。留出另一种相位和三流组合，检验两流推断能否组合。

### R06 扩展 — ready warp 选择与 SM 子分区

**扩展位置。** [R06](R06-issue-residency.md) 的 warp 发射扫描；扩展 [run_r06.py](../../../../../../microbench/gh200_resource_campaign/access_rules/run_r06.py) 与 [r06.cu](../../../../../../microbench/gh200_resource_campaign/access_rules/probes/r06.cu)，由 warp 数扫描补到 warp 身份与 ready 集合。

- **最小对照**：固定含八个 warp 的 CTA 和资源占用，每次只使指定 warp 执行目标工作，其余按合法同步协议保持安静。先测八个单 warp，再测 warp 0 与其他七个的配对；根据结果选三组不含 warp 0 的配对，检查是否形成稳定等价类。

### R16 扩展 — setmaxnreg 配额与 warpgroup 交接

**扩展位置。** [R16](R16-residency-quota.md) 已有动态配额小节；在 [r16_quota.cu](../../../../../../microbench/gh200_resource_campaign/access_rules/probes/r16_quota.cu) 与 [run_r16.py](../../../../../../microbench/gh200_resource_campaign/access_rules/run_r16.py) 中增加两次释放和申请次序。

**已有依据。** [R16](R16-residency-quota.md) 显示申请等待随 producer 释放时序变化，但一次 .inc 的窗口包含同步、重试和记录开销，不是固定硬件成本。

- **最小对照**：复用 384-thread、每线程初始 168 寄存器的组织。producer 从 168 降至 104，每个 128-thread warpgroup 释放 8192 个寄存器，足够一个 consumer 从 168 增至 232；再从 104 降至 40，释放另一份。与 producer 一次降至 40 的版本比较，交换两组 consumer 的申请先后。
- **观察与合法性**：给第二次释放设置有限、必定结束的延迟，避免永久等待；记录两次 .dec 前后与每个 warpgroup 的 .inc 起止。同一 warpgroup 按规范一致执行，申请值满足指令取值、粒度与 CTA 配额可满足条件，初始 168 不是 consumer 的申请上限。.dec 后不得使用已归还的寄存器，新获得寄存器先初始化，逐阶段核对 SASS 活跃范围。.dec 归还 CTA 内的配额池，不能解释为给其他 CTA 释放 SM 寄存器。
- **规则与留出**：输出 CTA 内配额余额、申请可满足时刻和实测申请选择/等待关系；静态 CTA 驻留由[驻留扩展](#m08)单独处理。留出另一种合法配额切分与释放交错，不由一个 144.5-cycle 样本建立通用 .inc 常数。

### R03 / EXP-18 扩展 — 普通 global/local LSU 请求

**扩展位置。** 普通 global 请求扩展写回 [R03](R03-access-demand.md) 原“普通 global 地址需求”小节，沿用 run_r03.py，复用 [memory_baseline.cu](../../../../../../microbench/gh200_resource_campaign/probes/memory_baseline.cu) 的 global 访问与检查逻辑；local 子项写回 EXP-18，使用其原探针。R03 的原条件扩展改按本计划补齐，不另开 LSU 实验。

- **最小对照**：先测 32 lane、每 lane 4 B 的 LDG，连续地址相对 32 B 边界的偏移为 0/4 B，对应覆盖四/五个 32 B sector；再保持相同 sector 集合仅置换 lane。另做广播读、连续/稀疏 active mask。写入使用互异目标地址，排除非原子同址写竞争。

- **规则与留出**：地址集合给出 sector 覆盖下界，缓存/合并/重放另加状态；不把覆盖字节直接算成 HBM 字节。留出 lane 置换、宽度和 mask 的组合，并检查请求量预测与时间预测是否分别成立。

### R03 扩展 — SMEM 标量、向量与矩阵访问

**扩展位置。** [R03](R03-access-demand.md) 的片上访问并发小节；扩展 [r03.cu](../../../../../../microbench/gh200_resource_campaign/access_rules/probes/r03.cu) / run_r03.py 的布局与冲突条件。EXP-09/10 的已有结果直接引用，片上并发规则只在 R03 写一份。

**已有依据。** [EXP-09](../EXP-09-smem.md)、[EXP-10](../EXP-10-ldmatrix-shfl.md)、[R03](R03-access-demand.md) 已有步长、广播与宽访问；尚缺把正常拆批和额外冲突分开的布局规则。

### EXP-15 / R10 扩展 — TMA 描述符、布局与请求形成

**扩展位置。** 纯 tensor-map 几何扩展写入 [EXP-15](../EXP-15-tma-2d.md)，复用 [tma_tensor_2d.cu](../../../../../../microbench/gh200_resource_campaign/probes/tma_tensor_2d.cu)；真实 GEMM pitch 扩展写入 [R10](R10-layout-cache.md)，扩展 [run_r10.py](../../../../../../microbench/gh200_resource_campaign/access_rules/run_r10.py) / [r10.cu](../../../../../../microbench/gh200_resource_campaign/access_rules/probes/r10.cu)。两者分别回答请求与实际内核的对应问题。

**已有依据。** [EXP-14](../EXP-14-tma-1d.md)、[EXP-15](../EXP-15-tma-2d.md)、[R10](R10-layout-cache.md) 与 [V08](V08-wider-validation.md) 已显示形状、行距与配置敏感性；仍未分离请求量变化和持续服务变化。

- **最小对照**：先做纯 TMA，固定合法的 16 KiB payload、请求数、issuer、buffer 和完成协议。分开改变合法行距余数、基址偏移和等面积 box 的长宽；swizzle、interleave、L2 promotion 只在各自合法的描述符组合内单独比较。输入与输出方向分开。每组明确改变了哪些地址，而不仅记录逻辑字节。
- **观测与归因**：同时看发出窗口和完成窗口；有计数器时比较相关层的 sector/字节和时间。地址相同却时延变化与物理流量增长是不同解释。程序限制的在途数量固定，不表示已观察到相同的硬件内部 occupancy。
- **实际 GEMM 对照**：当前拟定条件为 M×N=2304×3072、swizzle=1，与 V08 后续对照相同。先在 cfg_b、K=1024 上扫 B 行距 6144+{0,16,32,64,128} B，看余数的形状；再对 A、B 各取 16 B 与 64 B 两个余数，在 cfg_a/b/c 与 K=1024/4096 上测，A 行距为 2K+余数 B。V08 后续对照已有 16 B 余数的 A、B 点和对齐参照（见 [R10](R10-layout-cache.md#v08-stride)），先离线复用，不重复采样。其余行距、grid、输入、分配容量和缓存准备相同，按最大 stride 预留并按实际 stride 初始化。128 B 是性能轴，合法性按具体 tensor-map 规则判断。结果供[主线](#mainline)拟合有效供给函数。
- **规则与留出**：有证据时分离请求放大与服务率；否则只拟合布局下的条件服务。用未拟合的 box 比例、合法 stride 余数和另一种 tile 验证，不能将 cfg_b 的倍率套给 cfg_a/c。

### EXP-16 / R13 扩展 — TMA 在途请求、启动与排空

- **最小路径对照**：在同一物理 tile 列表上比较有效非零、有效零、部分 OOB、整 tile OOB、整 cluster OOB；先纯 TMA，再固定消费者，最后实际 GEMM。grid、输出 mask、stride、资源和调度顺序保持一致，tensor-map 有效边界与逻辑 GEMM 大小分开控制。
- **当前拟定配对**：cfg_b、2304×4096×4096、swizzle=8，补齐区由越界填零/有效地址显式零两种方式提供。缓冲按补齐大小预留，只扩大 GEMM 的 M/N 不算配对。基础差异重复后再补 N 向 4096×2304 和 K=1024，最多 2 方向×2 K×2 路径八个条件；N 向 B/D pitch 按补齐宽度设置。不要同时改 cluster/multicast。
- **补齐 tile 与供给**：按[主线](#mainline)步骤 2，先检验 V08 后续对照中补齐 tile 随 K 增大的代价能否由有效供给函数解释，再决定上面配对的范围。
- **调度与尾部**：记录实际 persistent 调度器分给每个 CTA 的 tile 与轮次，比较不足一波、接近整波、超出一波和一个慢 CTA 的条件。对同位置同轮次比较启动、稳态、末次窗口，检查 OOB 是否还改变邻居服务。最长本地 clock64 时间和 globaltimer 最晚退出者分别统计，两者不必相同。
- **硬件派发**：CUDA 保证 cluster 内线程块在同一个 GPC 上协同调度。先离线分析 V07/V08 中 cfg_a、cfg_c 打点记录的逐 CTA 入口 globaltimer 与 SMID，再结合 `cudaOccupancyMaxActiveClusters` 与实测入口/退出分布。[R19](R19-critical-cta-tail.md#other-critical-cta) 只测了 cfg_b、cluster 1×1，可用于排查 CTA 派发，不足以识别多 CTA cluster 的放置规律；SMID 的数值区间也不能当作 GPC 编号。新留出包含新的 cluster 形状前，先完成这一项。
- **规则与留出**：需求由真实工作列表计算，边界路径增量只收费一次；输出每 CTA 的起止、末次输出和全局 makespan。留出新 M/N 比例、边界方向/比例、K 和 swizzle 组织；两点 K 线性拟合只能是候选，整 cluster 未支持时直接标明。

### R09 扩展 — 频率、时间换算与观测扰动

**扩展位置。** [R09](R09-inkernel-clock-stages.md) 的调用内计时、频率和分段，原 R07 的频率与固定项、原 EXP-04 的计时空窗口已并入该页；首 tile 供给 S 的分解也写在这里。分析由 C 负责，进入 V09 的正式长窗口、三档输入与时间换算使用[管理者维护的公共 cfg_a/b/c 框架](EXECUTION.md#shared-gemm)。[r09_run.py](../../../../../../microbench/gh200_resource_campaign/access_rules/r09_run.py) / [r09_probe.cu](../../../../../../microbench/gh200_resource_campaign/access_rules/probes/r09_probe.cu) 的 128×256×64、4 stage 配置只作机制对照，常数不能直接移入 cfg_a/b/c。

**已有依据。** R09 测得调用内频率明显低于调用后探针。[原 R07](R09-inkernel-clock-stages.md#r07) 与 [V03](V03-clock-rule.md) 显示满载持续时降频原因只有 SW Power Cap，模组功率限制为 680 W。V08 中窗口超过校准最长的约 410 µs 时，频率解低 6%–7%。V03 还留下三个未解问题：32 个 SM、模组功率未封顶时调用内频率仍约 1.82 GHz；NVML 报告的时钟比 clock64/globaltimer 换算值高 0.1–0.2 GHz；event 与内核包络之差在不同卡/节点上为 3.9–6 µs。汇总见 [R09](R09-inkernel-clock-stages.md#other-clock-evidence)。

- **最小对照**：同一工作比较 plain、低扰动端点记录和必要的细粒度记录，核对资源与代码变化；短、中、长运行窗口分别测试，长窗口补到超过 600 µs，与[主线](#mainline)的校准补点共用；再改变前序暖机历史。同步采集允许的时钟/功耗状态，先沿用现有配置，不把硬件频率/功耗设置变更混入本轮。
- **输入数值与功耗**：固定 kernel、地址、布局与暖机协议，比较现有 17 级见证、全零和固定种子的随机有限 FP16 三档，同时测周期、完整时间、调用内频率和持续负载功耗。现有数值检查要求误差为零，随机输入改用容差检查，并在计时调用之外单独执行。外部依据只说明功率会随输入变化：[Horace He 2024](https://www.thonking.ai/p/strangely-matrix-multiplications) 的实测在 A100 上，H100 部分是推论；[Gregersen 等，SC-W 2024](https://conferences.computer.org/sc-wpub/pdfs/SC-W2024-6oZmigAQfgJ1GhPL0yE3pS/555400b872/555400b872.pdf) 在 H100 80GB HBM3 上复现了 FP16 GEMM 功率随输入变化的趋势，但测的是功率，不是时间或频率。功率差在封顶时是否转成频率差，需要在本卡直接测。全零输入也影响 R18 有效零与越界零的比较，两者结论按输入条件分开记录。
- **V03 的三个未解问题**：约 1.82 GHz 是观测平台，不是已识别的硬件时钟上限；在少量 SM、模组功率未封顶时，比较 WGMMA、FFMA 和仅 TMA 三种负载的调用内频率。NVML 时钟与窗口频率在同一持续负载内同时采样比较。event 与内核包络之差保持 R09 的“主机可见间隙”定义：它包含发射到首个 CTA 入口、最后 CTA 退出到 event 完成，以及其间可能未完成的全局写入，不能全部归因于主机 launch 开销。
- **首 tile 供给 S**：V08 的 S 从 producer 首次取得工作到首 MMA，R09 的预填从 CTA 入口开始；先对齐两者的起止事件，落在 S 起点之前的描述符准备不能事后算进 S。三个候选分别对照：tensor map 描述符首次取用与 prefetch、指令前端冷启动、上一次调用留下的 L2 状态。最后一项先复用 V08 的驱逐对照，驱逐后 S 增加 450–1300 cycle。不把三者合称一个冷启动常数。
- **时间分解**：核对 clock64/globaltimer 单位和本机粒度，记录同 SM 采样间隔与跨 SM 起止。完整 CUDA event 时间、全局内核包络和异步最终 drain 分开。空 kernel 的 launch 开销只作参照，不替代 GEMM 固定项；外部 F 不能吸收未建模的可变输出或错误 C_max。
- **规则与留出**：对相同执行图分别检查周期预测、周期到时间换算、端点到完整完成的剩余项；共同偏高从这些残差中归因。留出另一种持续时间、冷热历史与读写组成。跨卡时重测计时与频率状态，再检验服务规则是否可迁移，不能仅换 SM 数和峰值参数。

## 9. 原实验中的局部验证与完整验证扩展

### 每条机制规则先有自己的留出

“换一个点”不一定能检验机制。留出优先改变组织：新寄存器映射、新复用/写入序列、新 ready warp 集合、新请求打包、新访问顺序、新竞争比例或新输出并发。先预列条件与预测，再采样；参数冻结后不利用这些结果回调同一轮预测。旧 R/EXP/V 数据可作开发或回归，不能改称新的留出。

局部验证同时报告数值正确性、有效条件数、预测的事件/服务时间、带符号偏差与绝对误差。启动间隔、短延迟、带宽、完成时刻分别比较；误差接近计时粒度时使用绝对周期/时间和测量区间，不统一套一个百分比。每个实验在冻结前按其分辨率写定容许误差；如需区分的两种候选预测相差还小于噪声，应先延长窗口或改对照，不通过放宽误差宣布规则成立。

若有多个物理解释均通过，输出最小可预测的条件关系，并列未区分部分。局部结果即使暂未接入 GEMM，也可作为独立机制成果保留；“已测”“已建立条件规则”“已通过新组织验证”“已用于组合预测”是不同事实，不使用其中一个替代其他状态。

### 组合验证检查误差是否抵消

中间层组合由 [V01](V01-validation.md) 承担：沿用其单 CTA 的 TMA→WGMMA→输出组合与 EXP-19/20 的框架，先用两路径片段验证共享服务，再用真实 mainloop/epilogue。V01 原冻结批次保留，新批次单独冻结。完整 GEMM 在 V09 起的新轮次中验证。各层都需要同时比较：

- 初始供给、稳态迭代、最后一次主循环与输出的时间及偏差方向。
- 每个 CTA 的工作数、预测终点与实测终点；最大局部周期 CTA、最晚全局退出 CTA 与二者差距。
- 全局包络、CUDA event 完整时间及二者之间已解释和未解释的部分。
- 相同变更前后的速度排序、瓶颈位置及不支持的条件。总时间通过不覆盖局部失败。

通过成对移除/替换模型项，检查同一效应是否同时进入供给、缓存流量、频率、边界倍率或固定项。测试阶段只分析已冻结预测；利用失败修模后，下一轮更换留出集合。

### 新完整验证轮次的覆盖组织

V09 起的完整验证按下面的分层方案选例；自动校准/冻结、用户确认指定预测 SHA、释放后重获参考卡及留出采样，按[执行规范](EXECUTION.md#v09-freeze)分段进行。只在 cfg_b 上多取几例、cfg_a/c 各取少数几例的组织不足以覆盖本轮机制范围。**具体 M/N/K 和资源表在规则确定后、采样前填写并冻结；目前不把任何待选条件算作已完成。**

| 留出层 | 必须覆盖的变化 | 防止重复覆盖同一基形的方法 |
|---|---|---|
| 基础几何 | square、tall-skinny、short-wide；不足/接近/超出一整波 | 至少六个不同 M×N 基形；同基形只改边界不计为新的几何覆盖 |
| K 与迭代状态 | 短循环、稳定长循环、原校准范围外的 K | 明确哪些是插值、外推；超出范围但尚未支持的点仍报告状态 |
| 地址与缓存 | 合法不同 pitch/offset、重复/轮换、不同重访顺序 | 新地址组织不得仅重复校准中的同一个余数与工作集组合 |
| 流水与边界 | 新合法 stage、partial/whole-tile/whole-cluster OOB、swizzle | 固定物理工作对照与真实工作量改变分别选例 |
| 输出与关键 CTA | 单 tile、多 tile、输出并发变化、一个慢 CTA/尾波 | 核对最后完成者，不只核对平均 CTA 时间 |
| 配置迁移 | cfg_a/b/c 及至少一种未用于拟合的合法执行组织 | 新组织需核验编译资源；不能把同一配置换尺寸当跨配置迁移 |
| 输入数值 | 现有 17 级见证与固定种子的随机有限 FP16 | 随机输入的正确性用容差在计时调用外单独检查；频率规则若含输入项，两类输入都要有留出 |

每个可支持的覆盖项至少有一个新条件，允许一个条件覆盖多项，但要显式记录其归属；不能把 V07/V08 的 24/36 例换个名称代替。测试规模由这些缺口和局部验证决定，最终预列完整表后一次冻结，而非边测边补最好看的样本。机制专属留出独立存在，不强求每条机制都在 GEMM 中制造一个显著效应。

完整时间目标仍是冻结前列定的支持范围内，全组绝对相对误差中位数 ≤5%、最大 ≤10%。测后数值错误、超时、模型未能给出预测或精度失败都保留在原预列组中，不能剔除后称全组通过；范围外探索条件事先另列，并报告不支持原因。打点扰动使分项不可判时，保留已有效测得的 plain 时间。供给、输出与 CTA 定位按各自观测定义和冻结的局部标准判断，不能只报告总时间；任何测后适用子集只能另列。新卡先跑第 3 节的共同参照；新卡验证分开列出“只重标定时间换算”和“重新拟合服务参数”的结果，后者不能证明无校准迁移。
