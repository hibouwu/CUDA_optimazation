## 1. 目标与预测边界

目标是在运行之前，给定程序、执行组织和下表允许的条件，预测 GH200 上 cfg_a/b/c 的完整时间，并解释配置变化为什么改变时间。

| 类别 | V10 允许作为预测输入 | 说明 |
|---|---|---|
| 静态执行与数值 | GPU UUID、二进制与源码身份；cfg、tile/cluster、stage、grid、软件调度；M/N/K、行距、分配、输入 map、swizzle、raster；输入模式与 seed | 声明格式见 [R09 时间输入合同](R09-inkernel-clock-stages.md#time-input-contract) |
| 冻结参数 | 参考卡 romeo-a057 / GPU-43269fbc 上的校准拟合结果 | 不混用其他卡的绝对参数；参考卡不可用时须在新卡上完整重新校准 |
| 调用协议 | 每个进程加载模块后，目标自身自适应暖机至末 5 次 CV≤2%，再计时一次；之前不运行其他负载 | 与 V09 相同；其他前序历史不在支持范围内 |
| 参照条件 | 留出采样前复测预列参照，只作卡状态门槛，超限即停 | 不作为预测输入 |

**不允许作为输入：** 目标条件或其暖机调用的任何计时、频率或 trace，以及同一进程中前序调用的实测值。使用这些量的"状态条件预测"是另一类问题：R09 已有前序 event 基线，可以继续研究，但单独报告，不进入 V10 评分。

**V10 的支持范围等于校准覆盖的范围。** 范围外的条件照常测量并报告，标为不支持，不计入成绩。

## 2. 主线合同：长 K 时钟与事件组合修正

**本合同已结束：缺一个必要测量，GPU0，未采用修正。** 第一形式把cfg_a G6完整时间误差从−3.698%改成−16.739%，组件留形状诊断也失败；第二形式移除G6后缺同协议later L价格，未实现或回填全数据参数。必要证据是参考卡上两个新长K几何的后续L、源覆盖对照及匹配ends/dual桥接；[交付与660进程方案](../../../../../../results/gh200_resource_campaign/access_rules/20261011-long-k-event-bounded/README.md)。用户已批准整理后执行一个校准作业；以下保留原合同，新的执行范围见[后续测量](#measurement-next)。

### 起点与问题

任务 A 已以“无可冻结候选”结束，GPU 作业为 0。60 点时钟合并拟合使 cfg_b G6 完整时间绝对误差从 35.46% 降到 19.52%，但 cfg_a 从 3.70% 升到 13.85%；组件留形状诊断也失败。规定的首轮 cluster 填充项对 P2 与 G6 三配置恒为零，不再重试。[任务 A 交付](../../../../../../results/gh200_resource_campaign/access_rules/20261011-V10-taskA/README.md)与[绑定计划快照](../../../../../../results/gh200_resource_campaign/access_rules/20261011-V10-taskA/A-clock-v2/source/PLAN.md)保留原采用规则和失败版本。

cfg_a G6 的冻结频率与完整时间均低估，固定其它组件时提高频率会使预测时间非增，无法同时改善两个误差。完整包络的缺口不能预先归为局部周期不足：first/later L 并非一致低估，代表 CTA 的结束时刻相对实测最晚 CTA 的遗憾中位约 5.07%。这些诊断作用域不同，不能直接相加，也不授予新的局部观察资格。

本轮区分两个解释：

- **局部误差：** 服务或事件时间不足。预期在对齐作用域后，局部残差能解释完整时间缺口，并随静态工作量或执行组织变化。
- **组合误差：** CTA 调度、结束包络或 plain 转换有偏差。预期局部残差不足以解释缺口，误差主要随最后完成者或局部到完整时间的映射变化。

以 cfg_a G6 为入口，用 G6 三配置及固定 29 条开发条件检查推广；最多检验两种事先写定、有静态依据的最小修正。不添加仅对 G6 生效的常数、条件编号分支或实测状态输入，不自动开展 stage、行距、边界新形式或跨卡研究。

### 预算、检查点与交付

时间上限 8 小时，GPU 作业为 0。达到终点即提前结束；启动时记录起止时间与代码/计划身份。

| 时间预算 | 工作 | 交付 |
|---|---|---|
| 0–1.5 小时 | 重建频率、各段时间、CTA 工作分配、结束包络与 plain 转换 | 可复算的误差归因表，区分可比较量与条件诊断 |
| 1.5–3.5 小时 | 用现有证据区分两个解释，检查参数来源 | 归因结论、反例与候选形式 |
| 3.5–6 小时 | 实现并检验最多两种最小修正 | 候选代码、参数来源和新增组件留形状诊断 |
| 6–7 小时 | 独立重放单项及组合评分 | 固定比较表、分项、关键 CTA 与覆盖统计 |
| 7–8 小时 | 收尾 | 一个明确终点及复放入口 |

**归因检查点必须先写后实现。** 归因完成时、最迟在 3.5 小时处，记录支持哪类解释、反例是什么、准备检验哪至多两种形式、参数如何取得及各自预期。记录完成后可继续本合同内的实现，不需要再次等待用户确认；证据不足时直接转到必要测量终点。

**参数无法独立确定时提前结束。** 若新参数只能由 G6 一个形状定价，移除该形状后没有其它数据或静态约束确定它，就交付必要测量方案，不用全数据参数填补留出折。只有一个长 K 形状或属于外推，本身不构成失败判定。

### 支持、评分与采用规则

- **预测边界不变。** 只读取第 1 节允许的静态条件与参考卡冻结参数。实测频率或 trace 可用于归因，必须标为条件诊断，不进入正式预测输入。V09 只作开发数据。
- **比较集合固定。** 保留 V09 的 29 个可评分条件、其中 7 个拟范围外条件的数值诊断，以及原 cfg_c G2 拒绝记录；缺值或候选无法计算不能靠删行绕过。
- **支持范围不因拟合结果增删。** 非 128 B 对齐 A/B 行距、非默认 stage（cfg_a/b 为 6、cfg_c 为 4）与原供给不可辨识项仍不支持。7 个范围外条件为 A+16B 三个、B+32/80/112 三个和 stage4 一个；其余 22 个也须逐项通过校准覆盖与原拒绝规则，不能自动授予支持。
- **组件留形状诊断。** 按 M×N 排除该形状全部配置、模式与 K，仅重新拟合本轮改动的组件；未改组件沿用 r2。每折写明参数来源、可估计性与外推，不能称完整模型独立留出。
- **目标项。** G6 三配置的频率与完整时间误差均须下降；修正直接影响的分项或关键 CTA，先在归因检查点写定局部指标、比较集合与容许误差，再拟合，不以完整时间收益掩盖局部失败。
- **其他条件退化限制。** 完整时间绝对误差中位数与最大值不增加；任一条件绝对误差增加不超过 2 个百分点；拟支持范围内原误差 ≤10% 的条件不得变为 >10%。2 个百分点是工程上限，不是噪声界。
- **完整报告。** 同时报告频率、时间、换算周期、首段、预填、first/later L、输出、尾段及关键 CTA；分项先在窗口取绝对误差再聚合，保留符号和最坏窗口。组合候选执行相同检查，不满足就不采用。

V10 后续只检验参考卡、受限支持范围内的完整时间。分项、关键 CTA、全组范围与跨卡联合要求保持 [EXECUTION](EXECUTION.md#status) 的原状态，不因本阶段通过而视为完成。V10 冻结范围及成绩永久保留，后续开发收窄范围不能改写成绩。

### 终点

1. **得到候选。** 交付代码、参数来源、支持范围、覆盖统计、全部开发检查和 V10 留出表草案，然后停止。支持范围窄到失去实际用途时如实报告，不冻结；冻结与采样按第 3 节确认顺序执行。
2. **缺一个必要测量。** 写明缺少的量、两个解释的预期、测量怎样改变采用决定，以及条件、配对、卡和 GPU 作业数，然后停止，另经用户确认执行。
3. **没有可冻结候选。** 交付反证、失败版本与适用边界，然后停止。

若本轮以终点 2 或 3 结束，暂停主线，不自动开第四轮 V09 离线开发。下一步由用户选择批准补测或暂时搁置主线、继续机制任务。时间上限届满时保存已完成与未完成部分及阻碍，不把未完成检查记为通过。

## 3. 之后的顺序与工作规则

<a id="order"></a>

### 顺序

1. **主线或机制达到各自终点后停止。** 一个任务结束不自动扩展另一个任务；主线得到候选后才进入以下 V10 确认顺序。
2. **用户确认候选与 V10 留出表草案，并确认是否需要参照或校准作业。** 只用已有数据就能冻结时，可以在 CPU 上直接冻结；需要新校准时，由校准作业完成校准、拟合与冻结。
3. **回传最终预测文件与冻结清单的 SHA，由用户确认这一版本。** 确认只对这一版本有效，重新拟合或修改预测都须重新确认。
4. **留出作业。** 重新取得参考卡，先通过参照门槛，再采样并独立评分。
5. **V10 之后主线暂停一轮。** 达标表示本阶段在该支持范围内完成；分项、关键 CTA 与跨卡目标的状态另计。未达标则保留冻结范围与失败成绩，记录失败机制，不立即开 V11。
6. **m11 可按已批准合同与主线并行，不以 V10 完成为前提。** m11 结束后不自动启动其他储备；后续建议顺序为依赖就绪与发射（m01、m05），再做 RF（m02–m04），先检查 SASS 操作数和 reuse 位是否可控。具体下一项按结果与研究用途决定。
7. **跨卡验证在 V10 之后单独安排。** 新卡先跑第 5 节的共同参照；"只重标定时间换算"与"重新拟合服务参数"的结果分开报告。
8. **计数器权限由用户联系 ROMEO 管理员**，见 [EXECUTION](EXECUTION.md#counter-access)。取得后优先用于行距的流量归因。

### 工作规则

- **最多并行一个主线任务和一个机制任务。** 各自写明时间上限、GPU 预算、交付物、检查点与终点；达到终点就停止，不自动补位或扩展。两者从同一经审查提交出发，各用独立 worktree、分支与结果目录。
- **公共维护与启动。** 主集成串行维护 PLAN/RULES/EXECUTION、共享 runner 和最终冻结/评分；机制执行者只改专属模型、probe、runner 模式与 R03/EXP-09 扩展。启动前按归属分别提交任务 A 代码、已审查文档与原 R09 修改，不用 `git add -A`；保存旧结果与源码身份。时间、供给对话本轮保持暂停，分工与实际启动时间写入 EXECUTION。
- **合同内检查不重复等待确认。** 已批准的两解释与候选检查按各自合同执行；新的机制子研究、观察协议验证或超出预算的作业，先写明要区分的假设、预期与作业数，再经用户确认。主线归因检查点仅需留档。
- **汇报。** 主线在归因检查点和终点汇报；机制冻结前把合同和预测写入记录，中途只在失败或需用户决策时汇报，终点交付完整结果。GPU 排队计入八小时上限；资源不可用时保留未完成状态，不声称留出通过。
- **以终点判断完成。** 新提交、新实验或训练集残差下降，本身都不代表任务完成。
- **文献只服务于当前选择。** 每篇写一页笔记，回答四个问题：
  1. 预测什么对象，需要哪些事先可得的输入？
  2. 如何表达资源竞争、流水重叠与状态变化？
  3. 参数如何取得，哪些量无法分别识别？
  4. 可借用哪条规则，用哪个现有反例检验？

  论文中的硬件常数不直接迁到 GH200。不先做综述。
- **实验页开头保持当前结论与作业索引。** 页面过长时，把推导移到对应 reanalysis 目录的 README。

## 4. 研究范围与共同模型接口

覆盖 GH200 / SM90a 单 GPU 的计算路径：指令与寄存器服务、warp 调度、资源驻留、异步运输与计算、存储层次、跨 SM 共享、CTA/cluster 工作分配，以及周期到完整时间的换算。基线为 CUDA 12.9.41、CUTLASS 3.9.2；编译器版本、输入精度和执行组织作为规则条件记录。其他架构的论文用于提出候选解释，不直接提供 GH200 常数。图形流水线、多 GPU NVLink、Grace–Hopper C2C 与统一内存迁移不在范围内。

这里有两个相互连接的目标：

- **组合预测**，即当前主线：把经过局部验证的规则接入事件模型，预测实际 GEMM 的供给、主循环、输出、关键 CTA 和完整时间。总时间接近不能掩盖分项错误。
- **独立机制模型**，即第 6 节的储备：给定指令、地址、布局、参与线程与前序状态，预测服务时间、消费者可用时刻、资源释放时刻和竞争变化。检验标准是在未见过的组织上预测正确，不以先改善 GEMM 为前提。

<a id="model-interface"></a>

### 共同的模型接口

沿用 [model/interfaces](../../../model/interfaces.md) 的操作与事件定义。每条规则应说明：

1. 输入条件：指令及实际 SASS 操作数、访问尺寸和地址、参与范围、缓存/在途/寄存器状态。
2. 需求如何形成：指令数、字节覆盖、事务或服务批次；测不到内部事务时保留可观测的请求单位。
3. 使用哪个共享资源、占用多少、何时释放；共享范围可能是 warp、子分区、CTA、SM、cluster 或整卡。
4. eligible、issue、complete、visible(consumer)、release(object) 中哪些事件可预测，哪些只测到外部窗口。
5. 参数范围、不能区分的候选解释，以及未参与拟合的组织方式上的误差。

对有限资源使用占用约束：在时刻 t 尚未释放的对象需求总和不能超过容量。对共享服务使用各路径的需求与服务率关系。依赖允许的最早开始、资源可用和实际发射都必须满足；仅在资源和执行顺序已确定时，才能简化为一个 max 递推。只有带宽是相同作用域、相同需求口径下的有效服务率上界时，字节除以带宽才构成下界；用经验带宽得到的是条件估计。两者都不能代替启动、排空、返回与依赖等待。

现有聚合主循环 L、供给 S、输出 E 可以继续作比较基线。某一阶段改用显式组件后，必须去掉该阶段已包含的聚合代价，避免重复收费。计量单位按服务来源保留：计算用 SM cycle，供给或输出若在纳秒上更稳定，先分别建模再换到共同时间轴。输入改变时不能预设周期不变而只修频率，也不把实测频率当成留出预测的输入。

## 5. 实验共用条件

**沿用原实验。** EXP-05–20、R00–R19、B01 与 V 系列沿用原编号；EXP-04、R04、R07、R17 已按维护位置并入其他页面，原页保留跳转。

- **文档：** 结果追加到原实验页的扩展小节，写明日期、适用条件、旧结果与新增证据的关系，不另建重复的实验页。
- **代码：** 优先给原 runner、配置和 probe 增加模式或参数，保持原模式可复现。冻结源码副本只读。
- **数据：** 原数据先离线复用；缺少对照时补测到以原实验编号命名的新 run-id，新运行单独保存源码与结果。
- **归属：** 跨机制问题按原实验职责拆分，相互引用，不重复保存一份结论。
- **合并：** 合并的是维护位置，不把不同协议的数值合成一条规则。

**测量与计时：**

- **同期配对。** 基线和变体在同一分配、同一卡、同批次交错运行；旧 run 可作趋势参考，不能替代同期基线。记录 GPU UUID、编译工具、SASS、资源与实际运行条件。
- **指令片段要可数。** 指令服务先用短、可数、结果可检查的片段，固定动态指令数、依赖链、循环与计时代码，报告 ptxas 寄存器、SMEM、spill 和实际 SASS 差异。
- **正确性检查单独执行。** 使用能区分寄存器、线程和 tile 的非均匀数据，不放入目标窗口。始终保留 ISA 要求的同步与依赖控制；不能从错误阈值推导物理就绪时刻。
- **两种时钟各有用途。** clock64 只在同一 SM 内相减；globaltimer 用于跨 SM。短窗口先测本机计时粒度与固定开销；plain、少量端点记录和细粒度打点分别比较。声称测量 visible/complete 的结束时钟，必须受实际消费者或对应 ISA 完成等待约束，并核对最终 SASS。
- **差异在噪声内要如实写。** 每个最小对照先做小批次，依据波动扩大重复次数，保留中位数、离散程度和原始样本。差异未超过同期噪声时，报告"在此精度内未分辨"。
- **合法性。** 对齐、参与线程、地址生存期和同步遵守 [PTX 8.8](https://docs.nvidia.com/cuda/archive/12.9.1/parallel-thread-execution/index.html) 与 [tensor-map API](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-driver-api/group__CUDA__TENSOR__MEMORY.html)；ldmatrix、stmatrix、WGMMA、setmaxnreg 按各自规定的 warp/warpgroup 一致参与。
- **缓存状态是条件，不是结论。** 记录实际访问序列：初始化、预热、轮换、计时前探针及输出写入都可能改变状态。"工作集小于 L2"是实验条件，不是命中的证明。

**限制与参照：**

- **计数器。** [2026-09-30 诊断](../../../../../../microbench/gh200_l0/results/20260930-counter-access/README.md)记录了 RmProfilingAdminOnly=1，普通与独占作业都不能使用 NCU。没有计数器时，只建立条件时间模型，不同时拟合无法区分的"流量放大"与"带宽下降"。取得后仍要确认指标覆盖目标路径并能隔离其他流量。
- **跨卡共同参照。** 每张参与校准或验证的卡，先跑一小组共同参照：负载下的调用内频率、对齐行距下的每 SM 供给、大工作集读请求速率、event 与内核包络之差。旧数据能否换算，须有同协议的桥接验证；缺少匹配条件的旧数据不进入同一拟合。
- **输入数值。** GEMM 探针默认输入是 `probes/r00_common.hpp` 中 17 级二进分数的正确性见证，不是任意数据。涉及功耗、频率或完整时间的结论都要注明输入条件。

### m11 第一轮合同：普通 SMEM 访问模型

**交付对象。** 给定实际 SASS 指令、合法 lane 到地址的映射、访问宽度、活跃线程与执行组织，预测模型中的服务需求/批次和条件时间。限定单 CTA、普通 LDS/STS、每 lane 32/64/128 bit；宽度须由实际 SASS 确认。依赖链与独立访问分别声明，报告 warp 数与循环/消费开销。ldmatrix/stmatrix、TMA/WGMMA 和多 CTA 竞争不在本轮范围；不把标量规则直接迁给矩阵指令。

**两个解释。** 一是地址映射改变服务需求，预期控制指令数与依赖后，时间仍随同 bank 不同地址或广播组织系统变化；二是发射、依赖或消费链主导窗口，预期同一映射改变独立流/消费者组织就显著改变时间。先写预期，再做对照。没有计数器或独立证据时，服务批次是待检验的推导，不称实测内部事务；只能辨识条件时间时如实限制模型。

**预算（2026-10-12 人类修订）。** 截止延长到 2026-10-12 巴黎时间 18:00（UTC 16:00），累计上限改为 3 个 GPU 提交。原开始时间与失败作业 740708 保留，该失败计为第一次提交；先在 CPU 上用 CUDA 12.9 完成最终 SASS 检查，再提交第二个开发/校准作业，完成校准与全量冻结后用第三个作业做独立留出。编译失败、重试或申请后取消的已提交作业也计入上限，不自动追加第四个。直接人类答复及旧预算/截止见[修订授权记录](../../../../../../results/gh200_resource_campaign/access_rules/20261011-parallel-bounded-preparation/smem-amendment-20261012.json)；旧启动、计划和失败快照不改写。可用非参考卡的 GH200；本轮校准与留出使用同一 GPU UUID、同一协议，记录实际 SMID、编译身份、资源与 SASS。参数只在本轮卡上成立，不授予跨卡资格。

**开发与冻结顺序。**

1. 离线复用 [R03](R03-access-demand.md) 与 [EXP-09](../EXP-09-smem.md)，核对原 probe、窗口、工作量、SASS 与正确性。开发作业先用兼容原窗口的对照复现 4 B stride=k 的约 128/k B/cycle 趋势及广播约 89 B/cycle 的原条件结果，保留原广播离散程度。旧绝对数值不是跨卡常数；无法复现时记录协议/卡/发射与消费差异，不带着未解释差异继续拟合。
2. 新计时窗口明确初始化、同步、循环、依赖与结束消费者，核对动态目标指令数；正确性在计时外检查。将新窗口与旧窗口分列，新探针不要求机械得到 89 B/cycle。测同 SM 的计时粒度、空窗口与固定开销，使用不同重复长度分离固定项与每指令服务，保持实际依赖，不能把纯循环差当硬件服务。
3. 控制映射与执行组织，建立一个地址需求模型及一套条件服务参数。读覆盖同址广播与同 bank 不同地址；写用合法且结果可确定的地址，不引入未定义的同址写竞争。按观测能力记录不支持与无法辨识项，不从峰值推断唯一端口结构。
4. 第三个（留出）作业前冻结源码/二进制、参数、协议、支持范围、全部留出地址及预测、随机 seed、指标与 SHA。随机留出采用预列生成规则下的新映射，不只重排已见布局的 lane 编号；采样后不回调同一轮参数。
5. 留出另含一段真实 CUTLASS epilogue 的受支持 LDS/STS 地址序列：绑定源码、SASS 与提取映射，在隔离 probe 重放，不声称预测了完整 epilogue。若实际序列属于 STSM 等范围外指令，明确报告该覆盖缺口，不以普通 STS 替代后宣称原序列通过。

**误差与资格。** 时间绝对相对误差中位数 ≤5%、最大 ≤10%，是事先选定的工程目标；正确性、指令身份、全部预列条件与协议检查必须同时满足。按第 7 节同时报告绝对周期误差的中位数/最大值、误差符号、计时粒度、固定开销与离散程度，并列窗口总周期与每条目标指令周期；绝对周期的分辨率和局部容许误差在开发校准后、留出采样前写定。短窗口误差不可分辨时先在开发阶段增加重复长度；不能在看过留出后放宽阈值或剔除失败。计时无法区分内部机制时，不把时间拟合通过等同于服务批次数实测或物理参数唯一识别。

**终点。** 留出通过则交付可执行模型、参数、适用卡/指令/窗口及成绩；形式被反例否定或某量只靠计时无法辨识，则交付反证、能够支持的条件规则与缺少的证据并停止，不改称通过。达到修订截止或提交上限而资源不可用或检查未完成时交付源码、冻结/准备状态与明确缺项，保留未完成状态。任一终点不自动启动矩阵、多 CTA 或下一机制研究，也不自动接入主线。

## 7. 验证规则

### 每条机制规则先有自己的留出

"换一个点"不一定能检验机制。留出优先改变组织：新寄存器映射、新复用或写入序列、新 ready warp 集合、新请求打包、新访问顺序、新竞争比例或新输出并发。先预列条件与预测，再采样；冻结后不利用这些结果回调同一轮预测。旧数据可作开发或回归，不能改称新的留出。每个实验在冻结前按其分辨率写定容许误差，同时报告相对误差、绝对周期/时间误差与计时粒度；"已测""已建立条件规则""已通过新组织验证""已用于组合预测"是不同状态，不能相互替代。

### 组合验证检查误差是否抵消

中间层组合由 [V01](V01-validation.md) 承担，沿用其单 CTA 的 TMA、WGMMA、输出组合与 EXP-19/20 的框架；原冻结批次保留，新批次单独冻结。完整 GEMM 由 V10 起的新轮次验证。各层都要同时比较：

- 初始供给、稳态迭代、最后一次主循环与输出的时间及偏差方向。
- 每个 CTA 的工作数、预测终点与实测终点；最大局部周期的 CTA、最晚全局退出的 CTA 及二者差距。
- 全局包络、CUDA event 完整时间，以及二者之间已解释和未解释的部分。
- 频率误差与换算周期误差分别报告；总时间达标不覆盖局部失败。

### V10 留出的覆盖组织

V10 的留出条件全部在本轮采用候选声明的支持范围内选取，采用新的 M×N 形状；冻结、确认与采样的顺序见[第 3 节](#order)。具体 M/N/K 在候选确定后、采样前写定并冻结。

| 留出层 | 必须覆盖的变化 | 选例方法 |
|---|---|---|
| 基础几何 | square、tall-skinny、short-wide；不足、接近、超出一整波 | 至少六个新的 M×N 基形；同基形只改边界不算新几何 |
| K 与运行窗口 | 支持范围内未训练过的 K，覆盖短、中、长窗口 | 标明是插值还是范围端点 |
| 地址 | 128 B 对齐的新行距 | 不重复校准中的同一个行距与工作集组合 |
| 边界与调度 | partial、整 tile、整 cluster 越界，swizzle 1/8 | 只选校准覆盖过的边界方向 |
| 输出与关键 CTA | 单 tile、多 tile、输出并发变化、尾波 | 核对最后完成者，不只看平均 CTA |
| 配置 | cfg_a/b/c 的默认组织 | 每个配置都有新形状 |
| 输入数值 | dyadic 与新 seed 的随机有限 FP16 | 随机输入用容差在计时调用外单独检查 |
| 范围外条件 | 非 128 B 对齐行距、非默认 stage、范围外 K 各取少量 | 照常测量和报告，标为不支持，不计入成绩 |

完整时间目标仍是：支持范围内全组绝对相对误差中位数 ≤5%，最大 ≤10%。测后的数值错误、超时、无法给出预测或精度失败，都保留在原预列组中，不能剔除后称全组通过。供给、输出与关键 CTA 按各自观测定义和冻结前写定的局部标准判断，不被完整时间成绩覆盖。
