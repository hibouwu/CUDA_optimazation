# m11：普通 LDS/STS 的地址与执行组织

完整 warp 的 bank 地址集合、重复次数和返回字节相同，lane 排列仍可使窗口周期接近四倍。旧全 warp 需求和原子组需求标量都不足以描述全部布局；宽广播和依赖执行尚无合格候选，独立留出未执行。[R03 当前结论](R03-access-demand.md#m11-current)与[EXP-09](../EXP-09-smem.md)维护实测关系。

## 原任务的测量和验证要求

第一轮修订后的截止为 2026-10-12 巴黎时间 18:00，累计上限 3 个提交，失败 740708 计入。历史实际使用 2 次；新的 lane 对照按[单独的测量安排](MEASUREMENT-20261012.md)计数，不能混用预算。旧启动、失败和授权记录保留在[原记录](../../../../../../results/gh200_resource_campaign/access_rules/20261011-parallel-bounded-preparation/smem-amendment-20261012.json)。两项任务都已结束。

- CPU 上先用 CUDA 12.9.41 检查最终 SASS：循环内目标 LDS/STS 的数量、宽度、依赖、计时消费者和资源须正确，无 spill；正确性在计时外检查，同址写不得引入未定义竞争。
- 校准和留出用同一 GPU UUID、同一协议，记录实际 SMID。原 stride 和广播数值只作条件对照，不能当跨卡常数。
- 区分地址需求变化与发射／依赖／消费链变化；先写预期，再测最少对照。计时只能支持条件时间关系时，服务批次仍是推导，不能称实测内部事务。
- 使用空窗口、不同重复长度和同步／消费控制，区分固定项与每指令成本。源码中的同步未必形成显式 SASS；以实际二进制为准，不能把复合控制窗口定价成单独同步指令。
- 相对误差中位数 ≤5%、最大 ≤10%，且满足原逐组绝对周期容差、正确性、全部预列条件与协议检查。并列窗口总周期、每条指令周期、误差符号、计时粒度、固定开销和离散程度。
- 冻结前确定源码／二进制、参数、支持范围、协议、全部新地址及预测、seed、指标与 SHA。留出采用新布局，采样后不回调参数、不放宽阈值、不剔除失败。
- 留出还须包含一段受支持的真实 CUTLASS LDS/STS 访问序列，在隔离探针重放。实际为 STSM 等范围外指令时报告缺口，不能用普通 STS 替代后称原序列通过。
- 留出通过、形式被反证或不可辨识，任一终点出现即停止。预算或时间耗尽时报告缺项，不自动扩展到矩阵、多 CTA、跨卡或下一机制。

## 下一步先在已有反例上推导

原模型已经按访问宽度划分 128 B lane 子组，并在组内统计冲突。8 B 密集对照连原子组需求都相同，时间仍差 47.381%；16 B 密集对照相差 84.640%。重新使用原子组冲突数不会解决这两个反例。[原模型](../../../../../../microbench/gh200_resource_campaign/access_rules/r03_lds_sts_model.py)与[密集布局反例](../../../../../../results/gh200_resource_campaign/access_rules/20261012-m11-lane-contrast/run-20261012T110219Z/README.md)可直接复核。

新的假设须明确每一阶段包含哪些 lane 和字、广播如何合并，再给上述反例写出静态预测。若仍把两点算成相同需求，就停止该形式，不先拟合。依赖控制也须解释；时间比例不能唯一确定内部 wavefront 或端口数。

本次文档整理不启动新推导或测量。未使用的条件留出预算仍有前提，不转作下一次开发作业。
