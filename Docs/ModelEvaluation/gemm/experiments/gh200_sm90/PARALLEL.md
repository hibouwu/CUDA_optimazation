# GH200 执行与审查分工

实验范围、协议和完成标准统一见 [PLAN.md](PLAN.md)。本文件只维护角色、并行边界和模型使用；任务进度、具体对话 ID 与原工作线交接见[协调记录](../../../../../results/gh200_resource_campaign/20261001-resource-suite-v2/parallel/threads.json)和[总状态](../../../../../results/gh200_resource_campaign/20261001-resource-suite-v2/implementation_status.json)。

## 当前角色

| 角色 | 对话 | 职责 |
|---|---|---|
| 主执行 | GH200 微基准验收与集成 | 实现、运行、GPU 调度、数据收集、分析、文档、公共接入和最终交付。 |
| 独立审查 | 主对话问题 | 读取准确受审版本，核证据与结论，在指定审查目录写反馈和验收结果。 |

主执行负责派发必要材料、修复并取得复核，常规通过后继续；用户已授权自动派发，无需在对话之间搬运材料。审查者须未参与该阶段实现；若有冲突，另选未实施者，必要时使用一个临时审查子代理。

## 并行边界

- 同时只有一个主执行者和一个按需审查者，同一产物不重复派发；审查结束即空闲。
- 主执行拥有探针、公共运行时、总状态和 GPU 提交的写入权；审查对话只在指定审查目录写结论，不修改受审源码、不提交 GPU、不另开执行线或子代理。
- 审查与不依赖其结论的 CPU 准备可以并行；依赖的测量在准入满足后开始，受控 GPU 测量保持串行。
- 每次传准确版本、必要文件与具体问题，复用适用已有审查，修复后只核受影响部分。
- 原 compute_onchip、tma_cluster、combinations 的成果继续复用；原对话保持交接后空闲，不自行开新作业。

## 模型使用

| 任务 | 默认模型与推理强度 | 使用条件 |
|---|---|---|
| 主执行、探针接入与结果解释 | GPT-6.1 Sol / medium | 连续推进一个实验家族 |
| 明确的文档、链接、字段提取与清单核对 | GPT-6 Luna / low | 主对话能直接完成时不另开代理；确需委派时限定输入与产物 |
| CUDA 布局、异步同步、计量与独立 C 审查 | GPT-6.1 Sol / high | 关注受影响代码、实际证据及科学结论 |
| Sol 仍无法解决的复杂问题 | GPT-6 Astra / high，必要时 xhigh | 仅升级具体难点，解决后恢复默认，不反复用高档模型检查无变化材料 |

用户授权主代理按任务选择可用模型；模型切换不降低实验接受标准。每次只读取必要上下文，既有脚本完成重算和批量检查，代理只判断差异与结论，不新增调度或费用统计系统。其他对话和临时代理的模型按可用工具指定；当前主对话若无切换接口，实际模型需在应用的模型选择器设置，不能将文档策略冒称已切换。上述选择采用[官方模型指导](https://developers.openai.com/api/docs/guides/model-selection)。
