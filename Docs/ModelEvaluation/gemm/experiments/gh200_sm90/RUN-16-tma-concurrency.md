# S16：TMA 并发与缓冲批量测量方案

固定每请求 16 KiB，测量软件 stage 数 S 与每个 stage item 请求数 R 的组合如何改变完成服务。软件并发窗口不解释为物理 TMA 队列深度。

## 固定配置

两个方向、S∈{1,2,4}、R∈{1,2,4}、单 CTA / 全 GPU，共 36 名义坐标。动态 SMEM 为 `SR×16384 + 8S + 32 B`，资源分类以本次设备查询为准。

旧 GH200 条件下 32 点满足必要容量，S=4/R=4 的四点超限；最大合法代表已有短数值证据。其余 31 个合法点和四个容量检查已列明，不重新做已适用的最大点证据。

## 一次运行

提交前完成正式 host 路径：保留设备 loop，关闭逐迭代 capture，增加有界预热、自身校准和完整末态输出。S/R 的完成 token、复用与排空不能因减少 capture 而改变。

一次编译、一次设备查询，先自动筛容量和 occupancy。连续验证最大、复用边界，再覆盖剩余有限短矩阵；通过冻结规则后连续正式采样。资源超限项保存查询依据和零启动终态，正常项逐配置十进程，未稳定项内部追加最多三批。

所有点共享不可变源码和二进制，逐点保存原始值及进程记录；不沿用原每点完整源码快照造成的 32 GB 展开方式。完整值证据可逐点在节点本地校验并无损封包，不删减必要元素。

## 工作量与分析

完成 N 个 item、B 个 CTA 的逻辑量为 `B×N×R×16384 B`。S 影响流水与资源，不直接乘入工作量。G2S 的字节完成和消费者离开、S2G 的源复用和全写完成分别计量。

同范围、同方向分别画 S/R 对完成速率的影响，同时报告实际 N、驻留上限和资源。对比串行窗口与较大窗口的变化；不把加速自动归因于隐藏的硬件队列。
