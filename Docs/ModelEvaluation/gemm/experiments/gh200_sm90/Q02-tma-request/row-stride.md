# 行距响应：单 CTA 定位与多 CTA 探针

53个目录（10-17、10-18、10-22），其中约27轮有GPU测量。问题来自完整 cfg_b：A16、B80、B112 的 plain 实测分别慢 28.9%、18.1%、18.6%，B32 为 −0.8%，组合模型对四者都预测 0。

## 结论

**多 CTA 探针与现用模型**
- 132 CTA、Q4 探针：B32 接近零，B80/B112 约 +4.3%–5.4%（20261017-Q02-tma-stride-002）。
- 现用源服务在全部 local 命中时，base/B32/B80 的请求时间线逐值相同，行距响应为 0（source-isolation、plain-release、resident-sector）。

**单 CTA 定位**
- Q4（4 组在途）：B80 只多一次性约 295 cycle，与长度无关，冻结长度判别支持（752028）；A16 的 363–513 cycle 全部出现在首次预填，之后为 0。
- Q1（1 组在途）：B80 增量为 294 + 165·(G−1) cycle，冻结留出 G16/G64 误差 3.08%／1.00%（752094）。Q1/G32 下 B32/B80/B112 分别 +2002/5398/5530 cycle，A16 +6802 cycle，两个按覆盖比例的形式均被反证。
- 把每组 full 等待入口推迟 8192 cycle 后，A16 响应变为 0，可隐藏形式获支持（752191）。
- A16 响应与 K 步长（R=1.006）、描述符外层分解（R=1）、源次序排列（R=1.002）无关。
- A-only 与双 B 的响应不能简单相加（MA≈0.90，MB≈1.31）。

**CPU 闭式必要界排除的固定形式**
- 同一展开图上的非负线性覆盖价；本 CTA 3/6/9 信用；源后补齐 FIFO；静态 home 价格；单边前段；固定返回边与完成尾；公共尾重分配；统一共享吞吐；同版控制分配。

**开发相容的工作形式**
- 字节基价 + 额外覆盖价（excess-coverage，λ、β32、β128、h、K 五个参数）在Q1的16项开发约束内最大误差4.375%；固定参数连续到Q4时，首次预填增量预测677.08、实测513cycle，误差31.98%，该连续形式停止，没有独立留出。

**对完整模型的含义**
- 单 CTA 下，行距代价可被重叠隐藏：Q4 只剩首次预填中的一次性增量，推迟等待入口后为 0；Q1 每组持续增加约 165 cycle。这些单 CTA 观测不能直接解释完整 GEMM 中 18%–29% 的响应。
- 10/15 的[地址几何核对](../Q03-source-service/source-state-candidates.md)已经给出：单条请求的 32/64/128 B 覆盖相同时，738203 的 B32 first_L 慢 18.4%，G5 B32 只慢 0.2%；同一形状 AlongM 与 AlongN 两种光栅下分别为 +23%–30% 与约 0。
- 完整 GEMM 的行距响应取决于哪些 CTA 同时读取重叠的源行，须在保留真实工作排列的多 CTA 条件下研究。本组规则没有接入 GEMM。
