# GEMM 负载下的输入共享、路由与投递

22 个目录（10-15 至 10-23）：在多 CTA 探针与真实 G3 回放上，检验输入请求的共享范围、信用、仲裁、源行订阅与合并、逐接收者应答及 GPC 投递容量。均由 Q14 移入。

## 结论

- 固定源多重集合、只改 CTA→源映射：Q1 主周期响应 +24.8%，三类预测均失配，Q4 控制不成立，信息不足（747595）。
- 10-15 的 CPU 筛查排除：双粒度源信用、按请求大小分道、固定轮转额度、统一提价、地址无关的回传信用；地址无关规则对行距给零响应，地址须参与服务。
- 10-22／23 的 G3 回放，各固定版本或参数点都停止，没有一项被接受：
  - 在途源行订阅（三遍未求解）、有限同址 sector 合并、有限读取订阅、只标定源读取价：两段 L 的行距增长为 0 或浮点舍入量；
  - 全局源行与两域副本：未过两段 L 增长 >1000 cycle 的必要门；
  - 每 CTA 副本的 GPC 投递 FIFO（固定上界价格）：两段 L 增量仅 96／37 cycle，三遍未测；同价格的工作守恒下界超出原 10% 上限；
  - 地址路由输入：四个 L 中第三项误差 11.16%，未过 10% 门，六个验证条件未求解；
  - 读共享网络：A16 物理读取增加 20.5%，但后续 full 均提前就绪，两 L 误差 −34.4%／−24.6%，预定后续干预未求解；
  - 逐接收者应答网络：有限拟合达到上限，本参数版本停止；
  - 原读取价与逐接收者完整读取的固定组合与纯 TMA 证据不兼容，未排除重新定价后的结构族。
- 以上是参数点或固定版本的停止，不构成结构反证。
- 尚未接受任何形式；源复用的直接干预见 [gemm-source-reuse](gemm-source-reuse.md)。
