# GEMM 中的跨 CTA 源复用

10 个目录（10-15、10-22）：多 CTA 探针上的源共享开发、cfg_b 匹配源订阅冻结判别、d226 A 源交换，以及真实 G3 的等值 A 源折叠（001–004）与回放。

## 结论

- 同源被多个 CTA 读取时窗口明显缩短：746797 中 Q1/Q4 未打点周期约缩短 19.54%／28.58%。独立固定收费失配，旧在途合并也不能同时解释绝对窗口与降幅；保留“共享关系存在”这一事实。
- cfg_b 匹配源订阅的四个版本在冻结判别 746586 中全部被反证，ns/cycle 最大误差 45.14%／44.47%。
- 请求服务与在途源服务串联的 CPU 开发最大误差 28.20%，停止扩参，不接入 GEMM。
- 等值 A 源折叠：002 的桥接只有 trial0 通过，003 邻接交换无组过桥，均信息不足；004 同二进制下第一输出响应比保持，第二输出 [1.32, 1.48] 超出两个冻结类别，出现地址重用增加而行距增长反增的反例，物理归因未定。同二进制负对照见 [plain-repeat](../Q10-time-mapping/plain-repeat.md)。a044 复核中 002 的桥接由失败变为通过。
- d226 的调用历史与工作放置见 [Q01 work-placement](../Q01-scheduling/work-placement.md)；现行源服务假设与反例见 [TMA-GEMM-HYPOTHESES](../../../model/mechanism/hardware_rules/TMA-GEMM-HYPOTHESES.md)。
