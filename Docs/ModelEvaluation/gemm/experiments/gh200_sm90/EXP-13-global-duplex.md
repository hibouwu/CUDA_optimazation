# EXP-13：全局访问与独立读写组合

A 草案，等待独立审查；没有实现或测量结果。合同见 [global_duplex.json](../../../../../microbench/gh200_resource_campaign/contracts/global_duplex.json)。

## 实验问题

给定工作集与请求读写比例，比较纯读、纯写、依赖复制和独立读写的服务速率。主指标为请求读加写的 GB/s/GPU；分别保留读、写字节。依赖复制用读入值产生写出值，独立组合的写入值只由目的地址和 seed 决定，两者有不同的数据依赖。

## 有限矩阵与最小例子

每种工作集下测 `.ca` 读、`.cg` 读、`.wb` 写、`.cg` 读后依赖复制，以及读写比 1:1、2:1、4:1、1:2、1:4 的独立组合。独立组合的 1:0 端点复用同条件 `.cg` 纯读，0:1 端点复用同条件纯写；显式保留别名，不重复采样。两档工作集共 18 个实际配置。

每 CTA 256 线程，grid 使用实际 occupancy 上限与每 SM 最多 4 CTA 的较小值。每线程每个请求为一个 uint4，处理全部四个 word。设每个活动数组实际分配为 A 字节，16 轮，则独立 2:1 的请求量为读 `32A`、写 `16A`、总量 `48A`。若 A=251,658,240 B，总请求为 12,079,595,520 B，必须用 64 位计数。实际 A 由运行网格对齐决定，例子不替代原始字段。

## 工作集和地址

读取设备实际 L2 容量 L：小档每个活动数组请求 `floor(L/4)` 字节，大档每个活动数组请求 `4L` 字节，再向上对齐到 `blocks×256×16`。读写同时存在时分配两个不同数组，记录聚合占用；纯读或纯写只分配一个。小档聚合实际占用若因对齐达到 L，则拒绝该配置，不静默更改条件。大档每数组至少为 4L；启动前检查可用内存。

设全网格线程数 T、数组 uint4 数 V（V 是 T 的倍数）。线程 t 在组 j 中的第 i 个读地址为 `((j×r+i)×T+t) mod V`，写地址相应使用 w。每轮 j 走过 V/T 个组，因此每轮恰好读 r 遍、写 w 遍。每个地址模 T 恒为 t，循环绕回也不会让两个线程写同一位置。

源 word 为 `uint32(17×word_index+seed)`，独立写出 word 为 `uint32(29×word_index+seed)`；复制输出必须逐 word 等于源。消费者累计读入的全部 word，避免只使用 uint4 的第一个分量。

## 计时、校验与使用边界

入口记录时间后通过 CTA gate，再执行全部轮次；所有读结果通过结果依赖完成检查，所有含写配置在 device fence 与 CTA 排空之后才记录终点。整卡时间是 globaltimer 网格包络；clock64 不跨 SM 相减。初始化、poison 和 host 校验在计时范围外。

整个 18 点家族先完成 1/2 轮短检查，逐 CTA 核对完整读取 checksum，并逐元素检查全部目的数组；正式每进程继续数值检查。实际 SASS 要证明访问宽度、cache form、动态读写比例、循环位置、独立写的数据来源及复制的依赖关系。完成上述检查和独立 B 审查后，才进入公共十进程、有界预热和最多三批协议。

小于 L2 或使用 `.cg` 都不能单独证明缓存驻留。本实验不把请求字节解释为物理 HBM 流量，也不声称是冷缓存。S04 的 `global_duplex_128m` 保留为历史依赖复制基线；本家族不与其不同工作集和计时条件混合统计。
