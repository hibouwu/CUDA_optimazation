# 源状态：工作集、先前写入、次序与两域

14 个目录（10-14、10-15）：在多 CTA 探针和 cfg_b 上检验源数据状态对搬运时间的影响，另含原 12 条件的地址几何核对。

## 结论

**冻结判别获支持**
- 实际访问工作集：24/48 MiB 对照下周期下降 49.37%（746486）。
- 先前独立 global 写入：D16/D0 的周期 +106.42%，频率几乎不变（746495）。
- 位置与推进状态，而不是固定源地址（746504）。
- cfg_b 暖机次序的近期状态：GPC2/3 早窗口 −41.30%／−39.53%（746588）。
- 两个存储域 GPC{0,4,5,6}/{1,2,3,7}，每域 66 SM，三次留出全部通过（746596）。
- 局部副本容量：GPC2/3 为 −9.38%／0，GPC5 仍失配（746641）。

**未达分辨率**
- CTA 起步次序（差 11–15 cycle）；暖机与本次时序；同分配历史；虚拟/物理地址交叉；A/B 源偏移（+2.05 个百分点，低于 4 个百分点判据）。

**地址几何核对**
- 单条请求的覆盖解释不了行距响应：覆盖同为 256/160/112 时，738203 的 B32 first_L 慢 18.369%，G5 B32 慢 0.192%。
- 同形状 AlongM 与 AlongN 两种光栅的覆盖计数完全相同，B32 响应却分别为 +23%–30% 与约 0。

**模型现状**
- `ProgramGemmSource` 的两域缓存、LRU、pending fill 与每 GPC 两槽服务均为假设，仍有行距、stage 与跨度反例。见 [TMA-GEMM-HYPOTHESES](../../../model/mechanism/hardware_rules/TMA-GEMM-HYPOTHESES.md) 与 [L2-SERVICE](../../../model/mechanism/hardware_rules/L2-SERVICE.md)。
- 将未完成填充单列于容量外、ready时才插入的固定形式也未通过：132源暖机后全命中，66／132源响应退化为0，停止该形式；轮次与反例见[源组织](../Q02-tma-request/source-organization.md)。
- 保留占位、只增加完成时MRU更新的形式，在FIFO／132源上仍全miss且全部请求与结束时刻保持；首项失败即停止，不继续扩展LRU更新，见[源组织](../Q02-tma-request/source-organization.md)。
