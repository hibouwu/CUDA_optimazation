# S18：配额条件与辅助指令（实验约定草稿）

## 实验问题与对应参数

核对线程、实际寄存器和 SMEM 使用量如何限制一个 kernel 的可启动条件，并测量代表性 local 访问、地址运算、转换及原子更新服务。对应 L0 辅助操作、L1 容量和分配约束。请求的 live 变量数与编译器寄存器分配数分别记录；occupancy API 给出容量上限，不据此宣称测得实际同时驻留 CTA 数。

本草稿包含 28 个有限坐标，机器可读范围见 `contracts/auxiliary_scope_v1.draft.json`。代表目标编译及独立 A 审查仍待完成；不得按本草稿开始校准或正式采样。

## 最小例子

128 线程、4 条独立地址加法流，每流每轮一条 `add.u64`，运行 5 轮：请求量为 `128 × 4 × 5 = 2560` 次线程操作。若计时为 C 个 `clock64` 周期，则报告 `2560/C operation/clock64_cycle/CTA`。一条 PTX 操作可能降低为多条 SASS，必须另列实际机器指令序列，不能把 2560 直接称为 SASS 指令数。

## 配置矩阵

| 类别 | 有限坐标 | 控制条件与结果 |
|---|---|---|
| 线程配额 | 64/128/256/512 线程 | 32 个请求 live u32、无动态 SMEM；4 点 |
| 寄存器压力 | 128 线程、64/128 个请求 live u32 | 与基准 32 对照；2 点。编译生成数和 spill 必须实查 |
| SMEM 配额 | 128 线程、32/64/128 KiB 动态 SMEM | 同一 32-live 计算循环；3 点。每次实际访问所分配区域并保存校验，opt-in 失败在启动前终结 |
| carveout | 128 线程、32 KiB SMEM、偏好 0/100 | 与 default 对照；2 点，记录 API 成功及函数属性，不声称偏好等于实际 L1 分区 |
| local / spill | 每线程 32/128 个 u32 | explicit-local 与寄存器压力诱发 spill 分开；4 点，spill 必须看到编译报告及实际循环中的 spill 指令 |
| 地址与转换 | `add.u64`、`mad.wide.u32`、`cvt.rn.f16.f32`、`cvt.f32.f16` | 每条形式 1/4 流，128 线程、单 CTA；8 点 |
| 原子 | shared/global 的 u32 加 1 | CTA 全线程同址与每线程独立地址；4 点，不扫描其他原子形式 |
| 寄存器再分配 | 128 线程，一整个 warpgroup | 代表 `dec32 → CTA同步 → inc64 → CTA同步`；1 点，只验证合法性与完整输出 |

carveout 是驱动可调整的偏好，因此把请求条件与实际可观测属性分开。[CUDA 编程指南](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-c-programming-guide/index.html)、[Hopper 调优指南](https://docs.nvidia.com/cuda/archive/12.9.1/hopper-tuning-guide/index.html)。

## 计时与计量

配额和 `setmaxnreg` 点首先输出能力、函数属性、实际编译寄存器数、local 字节、spill load/store 与合法完成证据，不自动导出服务标量。资源配额代表点可以附相同计算循环的条件化时间；不能将其反演为通用调度或驻留公式。

地址及转换循环用非均匀初值、数据依赖和保存每流最终值防止外提。单流为依赖链，4 流为每线程四条独立链；结果仍含循环及发射开销。转换采用完整往返时必须计两次转换，不把往返时间除二冒充单向延迟。B1 将分别规定两种转换的完整 loop 和外部依赖，B2 按实际 SASS 最终确定是否能作为所声明单向服务；无法保持目标循环时退回修改，不能按标签输出性能。

local 请求按实际循环每线程的读/写次数和 4 B 字宽计逻辑字节；缓存与物理流量未知。诱发 spill 的坐标是请求条件，若没有生成 spill，则标明未实现目标条件并在 GPU 扩测前修复，不能作为成功的 spill 实验。

原子更新结束后 CTA 同步，计时终点必须位于全部更新完成之后；global 输出经 kernel 完成回读。同址最终值为 `initial + threads × iterations`，独立地址为 `initial_i + iterations`；采用 u32 模 2^32 参考。原子返回值若保存，用完整排序集合验证，不预设线程执行顺序。读出或未读出返回值的 lowering（ATOM/RED 等）必须区分并写入受审约定，不混成一条参数。

## 正确性与审查

短检查先按 `(iterations,seed)=(1,0),(2,3),(5,UINT32_MAX)` 三次配对启动。所有 lane、流、local 元素、SMEM 校验与最终原子数组保全，由独立 CPU 参考重算；溢出语义明确为 u32/u64 模运算。转换输入采用有限、可识别且可由独立位级参考核对的值，不用统一常数。

`setmaxnreg` 只在实际 `sm_90a` 编译和初始寄存器所有权条件被证明后运行。初始每线程最大拥有量必须满足 dec32 的前提，并能支持随后 inc64；不能仅凭请求编译选项推定。四个 warp 执行相同指令，连续再分配之间显式 CTA 同步；增加后若使用新寄存器必须先初始化。本坐标不测争用再分配成本。若无法证明初始 64 所有权，先修实现或约定再审，不把它当作 GH200 不支持。[PTX ISA 8.8：setmaxnreg](https://docs.nvidia.com/cuda/archive/12.9.1/parallel-thread-execution/index.html#miscellaneous-instructions-setmaxnreg)。

B1 明确独立参考及 loop 语义，B2 核对每个实际特化的循环、寄存器、local/spill 与同步；全部适用坐标短检查通过后才校准。formal 保留现有十进程、预热、有界复测和全部样本协议。
