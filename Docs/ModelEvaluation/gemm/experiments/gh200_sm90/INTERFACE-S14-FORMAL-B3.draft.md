# S14 正式运行准入草案

状态：供独立 A 审查；尚未注册正式 adapter，也未授权 pilot、预热或采样。限于现有 24 个普通 1D bulk 配置，沿用 `tma_bulk_formal_host_v1.draft.json` 的工作量、计时边界、32-slot ring 和长度规则。

## 两组证据的职责

| 证据 | 正式准入用途 |
|---|---|
| 原 84 次启动及其已审压缩运输桥 | 保存原非均匀短验证和 12 次源缓冲释放诊断；不能替代新执行分支 |
| 新 `capture=false` 的 24 个进程、72 次启动 | 证明正式入口实际使用的机器码、最终 tile／完整 ring、guard、完成计数和 stamp；必须有独立全量 B3 审查 |

新分支每配置固定 `(iterations, seed) = (1,0)、(2,3)、(33,UINT32_MAX)`。一个进程的入口 seed 为 3，内部三对输入另按已审 profile 验证。不能把内部 seed 误写成三次都为 3，不能把原 84 次启动与这 72 次合并成同一个 profile。

## 归档与身份

直接复用收集到的 `gh200-s14-formal-short-files-v1.tar.xz`，不重新编码原始数据。其物理成员保留 `repo/` 前缀；解析器必须显式绑定该前缀与规范 run 路径，不能通过 basename 猜测文件。外部 index 和 closure 记录全部成员长度与 SHA256，并绑定收集收据；独立复核仍须从原 manifest 和实物重建预期闭包，不能只相信 construction 的通过字样。

新分支的 B3 审查应直接绑定 coverage、全部原 manifest、raw、输出、receipt、编译依赖、SASS 和资源，以及独立数值重算代码。覆盖矩阵必须恰好为 24 个配置和 72 次启动；正确性数量从各配置的真实 blocks、payload 和方向重新计算。

新运行冻结原 84 证据的已审 archive/index/closure/桥，以及新分支的 archive/index/closure/B3 审查与所需代码。快照中保留完整压缩原始证据，通过已审只读事务访问有限元数据，不展开多个全量副本，也不执行归档中任意指定的 Python 模块。全解码哈希验证与数值资格分开：前者不能自行产生后者。

## 编译与执行条件

正式运行启动 pilot 前，核对新短验证的 source 和本地头文件依赖、完整目标机器码、ptxas 静态资源、实际 CUDA／驱动／运行库及 GPU UUID。24 个配置的目标必须与新短验证对应；不能仅凭原探针的设备函数相同推定等价。

occupancy 与 grid 只在以上条件一致时复用新短验证记录，标为条件化复用，不声称再次查询。全 GPU 使用 `SM数 × min(4, occupancy)`；单 CTA 使用 1 个 block。时间戳不得跨 SM 相减 `clock64`，全 GPU 时间沿用网格 globaltimer 包络。

正式 observation 必须通过 `tma_bulk_formal_v1.validate_trial` 的完整检查：`capture_enabled=false`、完整请求计数、零 timeout、真实资源、分配大小、输出检查范围和输入约定。运输一次 Q 字节只计 Q；正式计量不能加上短验证输出转储字节或把读写两端计成 2Q。

## 准入顺序与负例

1. 独立新分支 B3 通过、原源释放证据和压缩运输桥有效。
2. 有限 S14 adapter、冻结、加载、恢复及离线重放接入通过独立 source-B；S12/S13 的原有限规则保持。
3. 校准、计时基础与冻结长度经完整 B 审查后，执行原十进程和有界预热协议。

source-B 至少拒绝：缺一个新配置、把旧 84 资格替代新 72、错误方向或内部 seed、损坏输出或闭包、同名文件的错误 namespace、目标机器码／资源／运行条件变化、未签压缩桥、失败或未清理进程、没有完整 B 就进入正式采样。换目录离线检查应成功；归档中的文件变化必须失败。

本草案不授性能资格。正式 C 审查、报告、图表和结构化条件参数仍按原计划完成。
