# 空窗口计时约定修订草案

状态：待独立 A 审查，尚未改变现有合同、接受规则或正式测量资格。

## 实际发现

ROMEO 作业 730156 的 S04 `preflight-c2` 中，单 CTA 空窗口记录到：

| 字段 | 原始值 |
|---|---:|
| begin_ns | 1790838389952521376 |
| end_ns | 1790838389952521376 |
| begin_cycle | 1205937031242820 |
| end_cycle | 1205937031242845 |
| SM ID | 124 |

同一 CTA 的本地周期差为25，而两次globaltimer读数相同。当前协议要求所有CTA的globaltimer严格增加，因此正确地拒绝了该记录。不能把0 ns作为真实耗时，也不能从这一条记录推断定时器的固定分辨率。

反汇编保留了clock/globaltimer读数及中间CTA barrier，尚未发现计时读取被删掉。该轮原有12个访存配置通过最小运行检查；整轮因空窗口未通过，不能称S04-B完成。失败归档不改写。

[PTX ISA 8.8的globaltimer说明](https://docs.nvidia.com/cuda/archive/12.9.1/parallel-thread-execution/index.html#special-registers-globaltimer-globaltimer-lo-globaltimer-hi)给出纳秒计时单位，并说明行为依目标而定；单位本身不保证任意短区间都产生不同读数。

## 建议修订

只修订无被计工作量的控制窗口，普通FLOP/OP/访存测量仍要求正时间和原有数值约束。

1. 单CTA空窗口的主指标改为本地clock64差，单位cycles/window。globaltimer起止仍原样记录，允许相等；相等明确标为该窗口未获得可区分的globaltimer读数，不绘制成0 ns延迟。
2. 多CTA空窗口允许单个CTA的globaltimer相等，但仍要求各CTA本地周期为正、全网格globaltimer包络为正。整卡指标继续使用网格包络，不跨SM相减clock64。
3. 单CTA空窗口的预热收敛按本地周期序列判定。保留实际 `warmup_samples_ns`（包括0），新增明确的 `warmup_basis` 和 `warmup_samples_cycles`；不得把周期数伪装为纳秒或按未测频率转换。
4. 审查器根据冻结case的空窗口模型和scope允许上述例外，且独立核对被计工作量与读写字节均为0。非空case、负时间、非正周期以及跨SM周期指标仍拒绝。
5. 空窗口仍不导出吞吐参数，不从正式kernel区间中自动扣除。报告说明它包含计时读取与控制同步，并非裸barrier延迟。

每进程8–30次预热、尾5窗口CV≤2%、10外部进程及最多3批的规则保持。此修订改变计时接受域与主指标，须新合同版本、新run、源码和审查器共同冻结；不能续写旧run，也不能由主代理代签独立审查。
