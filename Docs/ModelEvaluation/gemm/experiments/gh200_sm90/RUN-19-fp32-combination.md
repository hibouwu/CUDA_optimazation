# S19：FP32 计算与搬运组合批量测量方案

固定一个 128 线程 CTA、32×32×32 FP32 tile，直接比较计算、搬运、串行和重叠服务。实验不寻找最优 tile，也不实施完整 GEMM。

## 固定配置与对照

| 条件 | 取值 |
|---|---|
| mode | compute、transport、serial、overlap、output |
| 输入 stage | 1/2/4 |
| K-tile | 1/2/4/8/16/32；64 是不参加拟合的检查点 |
| 短输入 | 原 periodic/tagged、1/3 序列与必要边界 seed |

保留原 378 个短配置；已有四点按条件复用，其余 374 点由内部循环连续覆盖。正式拟合坐标是 5×3×6=90，另 15 个 K64 检查点；这些数量不等同于短检查数。

## 一次运行

复用已目标编译、SASS 和代表实测通过的 S19 实现。提交前把完整原短列表接成一个自动循环，将校准、预热、正式采样及报告接齐。不再由人依次提交六批短检查。

短 trace 用于全值及生命周期验证；正式关闭 trace。按原 periodic 正式输入约定固定可比的重复序列数，校准只使用 K≤32，所有对照的长度规则一致。K64 以相同约定执行，不用于选择长度或拟合。每配置十进程，正式窗口包含启动、首轮预取、循环、末尾排空及对应 output 处理。

冻结源码和二进制只保存一份。原短接口逐 run 复制约 19 MB 源码造成全矩阵约 7.9 GB 存储预算；新批量实现改为共享不可变依赖、逐点完整 raw，只审受影响的引用和重放逻辑，不为统一旧格式重做旧四点。

## 指标与结果

每序列计算工作量为 `65536×Ktiles FLOP`，仅用于实际含计算的模式；transport 的 FLOP 为零，报告自己的完成时间和字节量。主要比较同一 CTA 的 `cycles/sequence`，再对计算模式给出 FLOP/cycle。

各 mode/stage 分别检验 `cycles/sequence = 启动项 + 每 tile 增量×Ktiles`，给出原始曲线、误差条、残差和 K64 预测误差。线性不成立就报告不成立。对相同 K 的 serial/overlap 比较，不能先假定组合时间是相加或取最大值。
