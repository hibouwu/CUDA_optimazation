# GH200 资源与组合微基准计划

本文件统一目标、实验范围、运行规则和完成标准。执行与审查分工见 [PARALLEL.md](PARALLEL.md)，剩余六个实验的具体配置及入口见 [RUN-REMAINING.md](RUN-REMAINING.md)，当前进度见[总状态](../../../../../results/gh200_resource_campaign/20261001-resource-suite-v2/implementation_status.json)。suite：`20261001-resource-suite-v2`。

## 目标与范围

完成 GH200 资源与受控组合微基准，逐实验交付条件参数、结果表、图、可复现脚本和中文教学说明。参数对应现有 L0–L4 建模接口；旧三批计算配置完成来源映射和重测要求。保留必要完整证据和独立审查，复用已有有效结果。

本轮不实施完整 GEMM、完整预测器、最优 tile 搜索、稀疏、Batched/Grouped 或 Distributed；GH200 不引入 Thor 的 TMEM/TCGen05。资源采用下列有限矩阵，不穷举全部指令和形状。权限阻塞与按有界协议仍不稳定的结果可作为明确缺口；实现、数值、计量或恢复错误须修复，不能标为完成。

计算去重键包含完整指令形式、输入与累加类型、形状、操作数来源和布局、threads/chains/batch/wait、计时与排空边界、执行范围及输入条件。旧长短循环与动态校准分别映射，不能只按 62 个基本组合合并。

FP8/INT8 不扫描混合编码、饱和形式或全部形状；非均匀输入须能区分行列/lane，长循环避免溢出。TMA 2D 从连续 none 开始，再增加合法 padding/SW128 子集，不扫描所有维度组合。`.param/.const` 和描述符计入实际探针，不独立扫描；`setmaxnreg` 只验证合法性和资源条件；cluster 上限采用设备查询与 occupancy API。

组合 K-tile 数为 {1,2,4,8,16,32}，64 为未参与拟合的检查点。S20 使用 TMA→WGMMA→输出。只报告限定条件下的启动项、每 tile 增量及拟合误差，允许拟合不成立，不声称最优 tile 或完整 GEMM 预测。


## 按实验连续执行

每个实验一个执行入口；正常条件下，一次 GPU 作业连续完成该实验。存储组、精度、stage 和普通配置由脚本内部展开。

1. **提交前准备完整版本。** 就绪配置、源码、参考、目标编译/SASS、独立源码准入和统计报告入口。用适用真实归档贯通初始化、冻结、二进制与校准导入、资源核验后的实际命令、换目录读取和收集；CPU 只替代不能离线执行的硬件/Slurm 查询。
2. **分配内自动完成测量。** 查询当前设备和资源，先检查最大、边界配置，再连续覆盖原有限短矩阵、自身校准、预热和正式采样。已有适用证据直接引用；冻结规则中的检查通过后自动继续，不逐点等待人工签录。短 trace/诊断与正式性能路径保持区别。
3. **采样后释放 GPU。** CPU 重算、归档传输、图表和教学说明随后完成；最终独立结果审查通过后发布。异常、规则改变或缺证据由未实施者判断，复核围绕受影响部分。
4. **中断时保全再接续。** 余时或真实配额不足保存检查点。未知提交、进程或发布状态先查原 handle，观察超时不当作终态；恢复仅处理已核的未完成项，不盲目重跑、不混并不同设备性能条件。

A/B/C 分别记录约定、实现验证、测量交付的独立资格；代码/数值、计时、稳定性、计数器和归档分别说明状态。它们不增加逐配置人工阶段。主执行修复问题并取得复核，不覆盖审查者意见；常规通过后继续。

基础设施只修阻断当前实验的具体问题。普通提交、传输和换目录复用已有入口；实质执行、计量或恢复逻辑变化才增量独审。不把新框架、统一历史格式或无关代码整理设为测量前置。

## 测量协议

| 项目 | 约定 |
|---|---|
| 设备与工具链 | ROMEO 有效单 GPU Slurm 分配；默认 CUDA 12.9、`sm_90a`。现场核设备、工具、函数资源、occupancy 与网格。 |
| 分配 | 默认 `short`、三小时、单节点单 GPU；同分配串行完成准备好的配置，完成即释放。`instant` 用于短诊断，不是前置。核账户/QoS、节点和时限，不固定历史节点。 |
| 串行与身份 | GPU UUID 锁与 suite/output 锁分开；正确性、计时、NCU 共用受控 GPU 锁，锁不证明系统独占。源码变化不能续写原 run。 |
| 样本 | 每配置十个独立进程，固定种子打乱顺序；十进程不需要十次分配。 |
| 预热与稳定性 | 8–30 窗口，末五窗口 CV≤2%；正式 CV>5% 复测。最多三批，保留全部批次与合并统计，不挑最好结果，不据此宣称长期热稳态。 |
| 超时 | 默认进程 120 秒、编译 180 秒；旧家族更短冻结限时继续有效。只清理本任务进程组；清理无法确认则停止该设备采集。 |
| 时钟与工作量 | 同 CTA/同物理 SM 的 clock64 与整卡 globaltimer 分开；禁止跨 SM 相减 clock64。FLOP、整数 OP、逻辑 payload 与物理流量分开，明确就绪、计算完成、复用与完整输出完成事件。 |
| 计数器 | NCU 与正式计时分开；每个新设备/驱动/权限环境检查一次，拒绝后不逐点重复，只限制依赖计数器的结论。 |
| 时间与容量 | 提交前预算完整实验：部署、依赖、来源副本、输出、收集峰值、最多三批和已有预留；不只预算第一组，不将压缩估计当可靠上界。 |

GPU 分配内不临时开发工具或写文档。确有必要人工在线审查时，提交前确定未实施者和完整入口，每处最多 600 秒，预算覆盖传输、完整重算、签署和安装；超时保全退出，先离线修复，不重复提交赌等待成功。协议变化使用新 run 并说明影响，不自动混并旧样本。

## 证据复用与保存

| 变化 | 优先处理 | 需要重新执行 GPU 的条件 |
|---|---|---|
| 文档、图表、统计或参考 | 在必要完整原输出上离线重算与复核 | 原字段不足，或证明探针需改 |
| 读取、传输、封包、收集 | 查原作业与进程终态，保留 partial/命令/异常，恢复同一工件 | 原运行失败或必要数据丢失 |
| kernel、布局、同步、缓冲、计时 | 限定受影响配置，重查编译、短正确性与计量 | 相关测量依据已失效 |
| 设备、工具链、节点、UUID | 核能力、二进制、依赖、资源与条件的适用性 | 约定不允许复用或缺必要证据 |

作业号、路径或 UUID 改变本身不使数值证明失效；机器码相同也不独自证明条件等价。校准和性能样本保留自己的设备、时钟温度、缓存、资源及协议，不继承旧观测。每次 GPU 重测写明失效依据、影响范围与离线不能解决的原因。

完整必要源码、配置、参考、审查、绘图及数值/生命周期输出按准确 SHA 和权限保全；未提交文件不能只标 Git HEAD，成功布尔值或 error_count 不替代约定完整输出。使用不可变副本、相对引用和无损归档，减少重复复制。回收副本须先证明完整保全、准确路径与进程条件。

- [源码](../../../../../microbench/gh200_resource_campaign/README.md)沿用 contracts/probes/common/runners/auditors/tests 和 plan/run/status/resume/audit/report 入口；旧 gh200_l0、v1、schema_version=1 的含义与归档保持。
- [实验入口](README.md)维护当前说明、覆盖和来源；硬件事实及合格参数引用放硬件文档，组合条件放实验说明，不混入 problem.md 或通用模型。
- 新归档使用 `results/gh200_resource_campaign/<suite>/<family>/<run>/`；旧 raw、summary、COMPLETE、源码和签录不回写。替代判定另存，不自动提交、推送或强制加入被忽略结果。

## 交付与完成标准

每个实验正文说明测量问题、参数、最小例子、有限矩阵、计时计量、结果表与图、适用范围和复现命令。至少用一条真实 raw 手算，图注明单位、范围、误差条与来源。主导航指向有效说明；完整日志、哈希与历史流程留归档。读者能找到参数并直接复现，不依赖聊天记录或临时文件。

进度以完成独立 C 的家族、已发布条件参数和结论为主；短检查、候选包与审查数量不计为正式参数或剩余工时。实际进度统一维护在总状态，各实验说明具体结果与限制。

最终须同时满足：

1. 全部声明范围有产物及独立审查，原配置完整映射。
2. 每个执行案例有准确终态，成功、否决、不稳定、不支持、权限阻塞分列；错误未解决不标完成。
3. 仅经审查有效参数可导出，附条件与证据；排除项不导出为合格标量。
4. 按 run ID/身份恢复，归档换目录重算统计、审查和图表；历史完整，链接及图表来源通过检查。
5. 参数、表、图、脚本、中文教学、两套组合算例和硬件引用齐全；S21/S22 最终报告分别列完成、仍缺证据和未纳入范围。

要求实际成立前目标保持未完成；常规通过后自动继续，只有范围改变或必须由用户解决的外部事项请求决策。
