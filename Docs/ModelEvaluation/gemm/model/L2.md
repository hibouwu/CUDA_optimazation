# L2：协作流水线（Collective）

[层级总览](../README.md#模型层级) · [统一接口](interfaces.md)

## 系统边界

描述一组协作线程执行所分配工作 tile 的数据搬运、计算与同步，协作范围由方案指定为 CTA 或 cluster。mainloop 遍历分配给该任务的 K 范围；epilogue 作为独立阶段描述，由 [L3](L3.md) 组合两者并安排整个 kernel 的任务。

| 阶段 | 输入与输出边界 | 本层描述的关系 |
|---|---|---|
| mainloop | 所需 GMEM 输入与初始累加状态满足约定条件 → 分配 K 范围的累加结果就绪 | 分块供给、片上计算、同步、启动与排空 |
| epilogue | 累加结果及所需 C/标量就绪 → 当前输出 tile 在约定位置可用 | 结果处理、转换、搬运与存储复用 |

输入布局与数值要求遵循 [problem.md](../problem.md#2-输入与输出要求)。默认 epilogue 输出位于 GMEM；融合时另行声明片上输出接口。完成不等于强制将全部缓存刷新至物理外存。

## 建模接口

- 输入：工作 tile 及其 K 范围、精度与布局、线程分工、缓冲配置、输入到达和初始缓冲状态，以及 [L1](L1.md) 的片上服务和给定竞争条件下的全局搬运服务。
- 输出：计算与各通路需求、存储占用、输入就绪/结果完成/缓冲释放的事件关系，以及给定服务条件下的完成延迟与持续处理间隔。

本层向 L1 提供分块输入就绪事件，并接收计算完成与缓冲释放事件；向 L3 提供可组合的阶段需求和状态。L3 统一处理多个任务的缓存复用和共享资源竞争，并将相应服务条件反馈给本层。不能把孤立 collective 的固定耗时直接用于任意并发情形。

## 资源与需求

### 计算资源引用

计算、搬运、同步和辅助操作引用 [L0](L0.md)，工作块的片上执行、容量与驻留约束引用 [L1](L1.md)。本层组织操作与工作块的执行顺序，可直接调用 L0 的搬运服务，不要求所有操作都经由 L1。

### 存储与缓存容量

输入、累加与结果缓冲引用 [L1](L1.md#存储与缓存容量)。矩阵和工作区按实际生存期占用全局存储；请求量与实际外存流量分别计量，后者受缓存状态、访问轨迹和竞争影响。

GPU L2 cache、外存及可选 CPU–GPU 通路的容量与服务参数见 [Thor L2](../hardware/thor_sm110/L2.md) 或 [GH200 L2](../hardware/gh200_sm90/L2.md)。这些参数按硬件 L2 归档，不表示每个 collective 可以独占全 GPU 资源。

### 带宽与数据搬运

| 访问路径 | 阶段需要给定的需求 | 共享约束 |
|---|---|---|
| 普通 global load/store | 线程地址、读写方向、访问宽度与缓存策略 | 发射、合并后的事务，以及实际经过的缓存/外存服务 |
| 异步复制或 TMA（若支持） | payload、形状、stride、对齐及完成机制 | 所选路径的在途限制、片上端和全局端服务 |
| 跨 CTA / SM 访问（若使用） | 协作范围、流量和同步依赖 | 按目标架构合法通路及共享范围约束 |

操作与完成事件引用 [L0 数据搬运操作](L0.md#数据搬运操作)，计账遵循 [统一接口](interfaces.md#5-计时与层间边界)。只计入方案实际使用的通路。

### 流水线状态与同步约束

| 状态或机制 | 资源与条件来源 | 本层使用关系 |
|---|---|---|
| 输入缓冲 | [L1 存储与缓存容量](L1.md#存储与缓存容量) | 生产者取得可复用空间，消费者等待数据就绪；消费完成后才能复用 |
| 累加与结果缓冲 | L0 完成条件及 L1 分配约束 | 初始累加、计算完成、结果取走与存储可复用分别建模 |
| CTA / cluster 同步 | L1 同步约束及实际协作通路 | 参与范围、到达条件和等待；协作范围由方案给定 |
| K 分块推进 | 已有指令发射和搬运服务 | 坐标更新、依赖和缓冲状态推进；额外等待由就绪关系推导 |

## 时间模型

阶段事件使用[统一接口](interfaces.md#4-事件与组合)。单/双缓冲在固定联合服务条件下的递推与闭式结果见 [FP32 示例](../schemes/fp32_simt_tiled.md#4-l0-到-l2供给计算与缓冲复用)；这些执行假设不作为所有 collective 的默认规则。

待推导：mainloop 与 epilogue 各自的需求、启动、稳态和排空关系，以及供给不足、缓冲不足和同步造成的等待。输出不仅是一个 tile 时间，还须保留供 L3 组合的完成与释放事件；跨输出 tile 的执行顺序和重叠由 L3 指定。

同一取数或计算若已包含在 L0/L1 服务中，不再次计时。硬件文件中的整卡带宽仍是共享资源约束，不表示每个 collective 可独占该带宽。

## 待完善关系

需明确哪些阶段服务可以重叠、哪些共用同一执行或搬运资源；共享服务条件变化时，阶段完成时间应随之重新求解。分块、缓冲数、访问次序和同步方式由方案给定。

## 接口依据

[CUTLASS Collective API](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/gemm_api_3x.html#collective-api) 用于对照阶段职责；具体实现的事件图在方案模型定义。
