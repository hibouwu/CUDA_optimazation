# L0：基础操作服务

[层级总览](../README.md#模型层级) · [统一接口](interfaces.md)

## 系统边界

给定输入、参与线程、存储状态与服务条件，描述计算、数据搬运、同步和辅助操作从可发出到约定完成事件的服务。操作原语是模型的基本构件，不等同于 `atomicAdd` 的原子性，也不预设为一条 SASS 指令。

## 建模接口

- 输入：操作类型、精度与形状、次数、线程/数据映射、源与目标位置、前置事件、缓存与并发条件，以及关联硬件资源。
- 输出：各资源需求、完成延迟、启动间隔、在途限制和发出/完成/可见/可复用事件；注明计数单位、thread/warp/CTA/SM/GPU 范围及时间口径。

计算、搬运和同步使用同一套[事件约定](interfaces.md#4-事件与组合)。例如 FMA 的结果可用、TMA 的数据就绪、源缓冲可复用和 barrier 释放不是同一个事件；事件是否重合由具体操作语义决定。参数未知时保留符号及适用条件。

## 资源与需求

### 计算资源

| 操作类别 | 必须给定的条件 | 服务参数 |
|---|---|---|
| FMA 等计算操作 | 精度、标量/向量形式、依赖链、参与线程 | 完成延迟、启动间隔、工作量与资源需求 |
| MMA 等协同计算 | 精度、形状、操作数位置与布局、参与范围 | 完成与可见条件、启动间隔、在途和依赖限制 |

合法指令、参与范围和服务数值由目标硬件给定，见 [Thor L0](../hardware/thor_sm110/L0.md) 与 [GH200 L0](../hardware/gh200_sm90/L0.md)。整卡产品算力不能直接用作单条指令或单 CTA 的服务参数。

### 数据搬运操作

| 操作 | 路径与输入 | 服务边界及参数 |
|---|---|---|
| `ld.global` / `st.global` | GMEM 与寄存器；访问宽度、对齐、线程地址和缓存策略 | 发射、事务需求及对应消费者可用/存储完成条件；逻辑字节不直接等于外存流量 |
| `ld.shared` / `st.shared` | SMEM 与寄存器；线程映射、宽度、布局 | 完成延迟、启动间隔、广播与 bank 冲突条件；实际服务参数引用 L1 |
| `cp.async` | GMEM → SMEM；线程级异步复制 | 发出、分组与完成等待分别描述；线程可见性与 CTA 合作所需同步须满足所选语义 |
| TMA | 所选 bulk/tensor 搬运形式、方向、形状、stride 与完成机制 | 请求发出与数据可用分别建模，记录各路径需求、在途条件及缓冲释放依据；不假定固定每请求延迟 |
| 专用存储搬运（仅目标支持时） | 所选 `tcgen05.ld` / `tcgen05.st` / `tcgen05.cp` 形式与合法端点 | 按指令确认参与范围、方向、形状和完成条件；不与 MMA 自身取数或其他通路混用服务率 |

仅使用目标架构支持的指令形式。各操作引用同一物理资源的参数；参数按片上路径或全局路径保存在硬件 L1/L2 文件中，不因操作数量而复制带宽。

### 同步与完成通知操作

| 操作 | 输入条件 | 本层输出与上层责任 |
|---|---|---|
| CTA / warp barrier | 参与线程与到达事件 | 状态及发射/通知成本；最后参与者尚未到达导致的等待由组合模型推导 |
| `mbarrier` | 所选指令要求的参与/事务状态及异步完成事件 | 状态更新与满足条件的事件；不能用发出时刻替代完成 |
| 异步 copy/MMA 提交与等待 | 指令组、在途限制、依赖的完成事件 | 描述合法完成语义及控制需求；轮询或等待的实际指令需求按方案另计 |
| fence（按需） | 指定作用范围与访存顺序 | 规定顺序/可见性关系，不自动表示所有异步操作完成 |

### 辅助计算与控制操作

| 操作类别 | 需要描述的需求 | 共享与依赖条件 |
|---|---|---|
| 地址与索引计算 | 整数运算、指针更新、地址转换次数 | 与后续访存的依赖及实际发射资源 |
| 类型转换与结果处理 | 转换、缩放、谓词和所选输出运算 | 指定数值语义、操作数与输出位置 |
| 循环与分支控制 | 循环计数、分支、谓词及路径选择 | 展开与分歧如何改变指令需求；不预先指定固定加速系数 |

仅为选定执行组织需要的操作补参数，不要求枚举全部 ISA。辅助操作与 FMA、访存是否共享执行资源须有依据，不能一律假定完全独立。

### 操作数与累加存储需求

本层记录操作的存储需求，包括寄存器操作数、搬运端点及同步状态；分配与驻留关系见 [L1](L1.md#存储与缓存容量)，容量数值由目标硬件给定。

| 存储位置 | 本层使用对象 | 需求参数 |
|---|---|---|
| 寄存器 | 计算操作数、累加状态、搬运临时值与控制变量 | 所需寄存器、独立累加链及值的生存期 |
| SMEM | 计算输入、搬运端点与输出暂存 | 数据块大小、布局和可复用条件 |
| 专用存储（如目标支持的 TMEM） | 累加器或其他合法操作数 | 累加状态与操作数占用、可复用时刻 |
| GMEM | 搬运源/目标及辅助数据 | 请求范围与布局；容量引用 L2，资源占用由方案记录 |
| 同步状态 | barrier、事务计数及相位等 | 按实际存储位置计量，跟踪初始化与可复用条件 |

### 数据供给需求

| 供给路径 | 方向 | 需求与边界 |
|---|---|---|
| 寄存器操作数供给 | 寄存器 → 计算指令 | 按指令形式记录操作数需求、供给条件 |
| SMEM 操作数供给 | SMEM → 所选 MMA 指令 | 记录每次计算取数需求，不等同于线程 SMEM load 带宽 |
| TMEM 操作数与累加访问（仅目标支持时） | TMEM ↔ 所选 TCGen05 计算指令 | 按指令形式记录读写需求；不等同于 `tcgen05.ld` 读回 |

计算指令自身的取数若已包含在所用 L0 服务中，上层不再叠加同一次访问的服务时间。FMA 之前显式执行的 SMEM load 等独立操作仍需计入。按[整段或分段计账规则](interfaces.md#5-计时与层间边界)给每段成本指定一次归属。

### 发射与依赖约束

| 约束对象 | 需要描述的量 | 组合时的条件 |
|---|---|---|
| 指令发射 | 发射开销、持续启动间隔 | 注明 warp、warpgroup、SM 或整卡统计范围 |
| 累加依赖 | 依赖链延迟、独立链数量 | 区分依赖链与独立指令流 |
| 异步计算 | 允许的在途计算、完成事件与等待条件 | 只在所选指令路径使用时计入；未核实的限制保留待确定 |

## 时间模型

采用[统一接口的事件递推](interfaces.md#4-事件与组合)，由就绪、发射、在途限制和完成条件组合操作。固定条件下的独立同类操作可使用延迟与启动间隔描述；依赖链、混合指令和共享路径必须加入相应约束。

同步原语本身的执行成本与等待时间分开。TMA/普通访存选择整段服务或分段资源模型中的一种，不把整段经验延迟与其内部缓存/外存时间重复相加。一个可手算的有限模型见 [FP32 分块 GEMM](../schemes/fp32_simt_tiled.md)。

## 待完善关系

各操作的条件化服务需按工作单位、完成延迟、启动间隔、在途容量与依赖限制描述。混合指令的共享关系与联合服务规则仍待完善；参数未知时保留符号，不能从独立吞吐量推出所有延迟和并发能力。

## 接口依据

[PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/) 与 [CUTLASS Atom API](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/gemm_api_3x.html#atom-api)；具体操作形式按目标架构核实。
