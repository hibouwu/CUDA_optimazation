# 多 CTA 的 TMA 共享服务

更新：2026-10-13。状态：任务设计，未新增测量。验收与通用证据原则见[GOALS](../../../GOALS.md)。

## 1. 现象

研究对象是GEMM中多CTA供给受限、stage响应和CTA推进不一致。已有V09的stage差异、R05-D的共享/独立源对照、R13的多CTA与局部端点记录可作为开发证据，索引见[TMA历史盘点](TMA-HISTORY-REUSE.md)。S16单CTA结果用于检查探针控制成本，不承担跨SM共享范围的结论。

### 存储资源与搬运边界

原总PLAN的搬运边界在本任务维护，首轮限定如下：

| 对象 | 本轮具体条件 | 记录或对照 |
|---|---|---|
| 源分配 | 目标GH200本地 `cudaMalloc`，由GPU HBM支撑，指令源为 `.global` | GPU UUID、分配大小、每CTA地址集合与整卡地址并集 |
| 缓存准备 | 分别使用预热复用与弱复用协议 | 工作集、复访距离、预热序列、可用L2/HBM观测；无流量证据时按准备协议命名结果 |
| 目标搬运 | 首轮16 KiB的1D bulk global→shared单目的请求 | 对齐、每CTA请求总量、发出组织；tensor-map 匹配对照使用 cfg_b 实际的 A/B 加载描述符：A 128×64、B 64×128，FP16 各 16 KiB，描述符与 TMA swizzle 以构建查询为准，不混用参数 |
| 目的存储 | 发起CTA驻留SM上的本地SMEM，按最大并发请求数预留固定数据槽及barrier区域 | 活动槽改变时物理分配和barrier区域固定，记录寄存器与实际驻留 |
| 控制与消费 | 完成等待、数据可读、固定消费者及槽释放 | 使用核对过的控制实现，分开记录等待与释放端点 |
| 排除的路径 | SMEM→global输出、DSM、多播、Grace CPU LPDDR、host/managed、peer GPU | 不进入本轮参数与条件矩阵 |

资源依据见[GH200存储与搬运](../../../hardware/gh200_sm90/L2.md)和[片上资源](../../../hardware/gh200_sm90/L1.md)。共享小源与独立大源同时改变地址并集和CTA间复用，不能只凭两者差值归因为HBM服务；在每种源协议内比较并发响应，并保留源集合变化。

## 2. 假设

| 候选 | 状态与响应预测 | 区分所需证据 |
|---|---|---|
| 每CTA局部准入限制占主导 | 增加每CTA独立请求数先改善局部等待再平台化；低全局负载时改变其他CTA数量影响较小 | 低CTA数下的请求并发扫描，以及加入背景CTA的响应 |
| SM范围共享服务占主导 | 同SM内多个CTA更容易相互干扰；相近请求总量分散到不同SM后响应不同 | 同SM与跨SM的实际放置、重叠窗口与配对结果 |
| 跨SM共享供给占主导 | 增加实际活动SM/CTA后整卡吞吐趋于饱和、单CTA等待增加；源复用协议改变饱和位置或程度 | 多CTA曲线、SMID及活动重叠、各CTA推进分布、cycle/ns双口径 |

这些候选可以共存，首轮目标是确定需要哪些共享状态，而非为整条路径选一个唯一瓶颈。容量回收先比较ready相关与消费释放相关规则，只在两者预测可分时增加消费者延迟对照。

## 3. 实验验证

主轴为 **实际并发CTA数 × 每CTA请求并发组织**。设计的CTA数先取1、4、16、64、132，每CTA软件允许的独立未完成请求数先取1、2、4；数量取值是扫描条件，不预先当作实测硬件在途量。

1. 先将R05-D、R13和已有多CTA记录映射到这两个轴，保留设备、源协议、指令和资源条件，能回答的问题不重测。
2. 新探针每CTA固定载荷、控制实现及物理槽。记录SMID和活动窗口；启动数或 `--sm-count` 不能直接填入“实际并发”列。覆盖多个SM但无法控制同SM放置时，只约束跨SM响应，不宣称已定位SM内仲裁。
3. 先做稀疏矩阵；同SM/跨SM对照、拐点加点与独立干预留出只选候选分歧最大者。每组明确固定每CTA工作量还是固定总工作量，并分别计账。
4. 每个源协议内记录总地址并集、每CTA复访和跨CTA共享关系；避免让并发数与缓存服务情形无记录地同时变化。频率线提供诊断口径，cycle与ns同时保留。
5. 输出整卡逻辑吞吐、每CTA周期/等待、推进离散度及支持域。将候选接入目标GEMM图，检查其是否能解释供给、stage及CTA间差异；没有改变这些判断的微小残差不自动扩展研究。

### 本轮预算与终点

| 项 | 规划上限或收口条件 |
|---|---|
| 首轮开发条件 | 最多两种源协议×5个CTA数×3个并发组织，共30条件；历史证据可替代的条件不新增 |
| 区分与留出 | 最多8个额外条件，在同SM/跨SM、拐点、消费者延迟和独立留出之间按候选分歧分配；不做完整笛卡尔积 |
| 重复与运行预算 | 重复进程数、先导测量规模、GPU分钟上限和编译修复次数在冻结的执行清单中一次写定；当前仅登记条件上限，尚未进入实机执行 |
| 终点 | 一轮开发加一次冻结干预检验后，交付共享范围约束、保留/排除的规则、对GEMM判断的影响；若放置或观察不能辨识则列缺失条件并结束本轮 |

## 4. 结论

待测。当前决定是将多CTA研究升为TMA主线，单CTA探针保留作控制与端点检查。S16是否完全归因不阻塞本题准备；新规则需要的控制实现须先核对。结果按本题的实际观测更新，不将现有全卡退化统一归因于L2或HBM。
