# GEMM 数学建模审查

审查日期：2026-09-30。当前阶段为问题定义与通用数学建模，具体优化方案尚未选定；实现与实验准备不作为本阶段的缺口。

## 当前范围与暂缓项

当前基础问题及资源覆盖审查以**单 GPU 的 Single GEMM**为范围。

| 问题类型 | 当前状态 | 本阶段处理 |
|---|---|---|
| Batched / Grouped | 暂不考虑 | 批量寻址、问题间调度与负载均衡留待后续，不列入当前补全任务 |
| Distributed GEMM | 暂不实现 | 跨 GPU 拓扑、通信资源与分布式执行留待后续，不作为当前单 GPU 模型的缺口 |

[problem.md](problem.md) 中相关定义域、工作量和计时边界继续保留；暂缓状态不代表已支持或已完成建模。

## 审查结果

L0–L4 的范围划分和分类资源表可以保留。现已扩展 L0 的基础操作类别，建立[统一接口](model/interfaces.md)，并给出[FP32 CUDA Core 的最小时间模型](schemes/fp32_simt_tiled.md)。该例在显式执行与联合服务假设下闭合，不表示已完成任意 kernel 的性能预测。

| 优先级 | 建模问题 | 当前判断与后续完善 |
|---|---|---|
| 高 | 问题及性能指标是否明确 | 已有计算定义、输入输出布局与精度维度、有效工作量、完成时间和参考周期口径；数值误差要求仍需由问题本身确定 |
| 高 | 层级边界和服务单位是否明确 | L0 覆盖计算、搬运、同步和辅助操作；统一就绪、发出、完成、可见与释放事件。L1 保留片上工作块，完整 K 供给与缓冲推进由 L2 组织 |
| 高 | 配置能否转为操作与资源需求 | 已给出 FP32 分块组织的映射、指令计数与分配需求；其他线程映射、优化组织和边界处理仍需分别推导 |
| 高 | 通用模型是否混入某个方案的选择 | 具体分块、缓冲数和任务映射应为可取的配置或外部输入；通用层不固定某个实现的取值与事件图 |
| 高 | 同一资源是否只约束一次 | 已约定资源 ID、容量区间、服务份额和整段/分段计账；实际路径的共享关系与联合服务参数仍需依据 |
| 高 | 时间关系能否由模型推出 | FP32 示例已闭合单/双缓冲递推、固定配额调度与 FLOP/cycle；一般共享资源仲裁、交错执行和缓存状态模型仍待推导 |
| 中 | 工作量与流量口径是否分开 | 有效计算量、执行需求、逻辑数据量和各通路流量分别定义；实际执行需求和流量可以依赖配置及缓存状态，不提前固定为某个方案的数值 |
| 中 | 模型假设与适用范围是否明确 | 给出缓存初态、可用并行度、资源共享与同步范围等假设；吞吐限制、时间下界和具体时间预测分开表达 |
| 中 | 参数、单位与证据是否一致 | 每个参数标明每指令、CTA、SM 或整卡范围及时间单位；规格、条件上限、经验服务和教学假设分别保留 |
| 中 | 是否已形成通用配置选择器 | 示例可以在限定候选中比较周期；尚需定义更完整可行域、参数适用域与预测不确定性，不能称为实际硬件全局最优 |

问题中的精度和允许误差属于当前建模范围。参考后端、校验程序、重复计时及缓存控制的具体做法属于后续实现与实验工作；缺少这些程序不表示当前数学模型因此有误。

## 结构整理状态

通用定义已集中到 `model/`，硬件目录保留参数与架构约束，方案统一放在 `schemes/`。Thor 的重复入口已合并，硬件 L4 的通用内容已归入 [model/L4.md](model/L4.md)；空候选和无结果的预测、比较骨架已收敛。资源容量与服务计账以 [统一接口](model/interfaces.md)为准，本文件不重复定义公式。

## 后续推导事项

1. 确定问题实例的数值误差要求；它由问题本身给定，再判断目标硬件与方案能否满足。
2. 完善 [L0](model/L0.md) 的工作单位、完成延迟、启动间隔、在途及依赖限制，并补齐硬件服务参数的适用域。
3. 完善 [L1](model/L1.md) 的交错执行、分配与驻留，以及共享服务下的 CTA / SM 组合关系。
4. 完善 [L2](model/L2.md) 的供给、缓冲复用、启动与排空，以及 mainloop / epilogue 的事件接口。
5. 完善 [L3](model/L3.md) 的任务分配、跨任务缓存复用、多 SM 共享服务和尾波影响。
6. 为 [L4](model/L4.md) 给定算子图和融合边界，再实例化数据传递与任务调度。

以 [FP32 示例](schemes/fp32_simt_tiled.md)为起点，在明确变量、约束和假设的条件下检查串行、充分并行、单任务及资源不足等情形。未知数值保留符号；本阶段不要求先写 kernel 或运行实验。

[tc5a](schemes/tc5a.md) 的输入适配、缓冲、worker 分配和 benchmark 条件保留在独立候选文件，不列入当前通用建模的优先事项。
