## 源码错误恢复与属性语义

原解析器会将类型名误读成CUTE_ALIGNAS，或将字段对齐表达式误读成成员；FP8 Blockwise文件还出现了三处结构体闭合错误，使104条后续记录需要scope review。原始CUDA源码本身没有因此被判为错误。

修复为语法解析提供临时GNU属性拼写，但正式数据保留原宏、表达式、物理字节范围、两条真实条件定义、include来源链及实际声明owner。10处类型属性与6处字段属性分别归属；`Alignment`、`SmemAlignmentA/B`保留为表达式，不固定成128或默认值16。

独立检查先从824份原文建立16处使用清单，再检查适配结果。Host Clang的正反例说明：移除字段属性后，外层alignof仍可能不变，而字段偏移和sizeof已经改变。因此没有把CUTE_ALIGNAS当作可直接擦除的普通注解。条件轴是__CUDACC__，不是__CUDA_ARCH__；CUDA分支的预处理检查与Host布局编译分别记录，没有宣称GPU运行或全部CUDA布局已验证。

## 完整文件工作包与接入反例

两文件保留16个物理声明出现位置：namespace两处、函数模板一处、aligned_struct主模板及九个偏特化、array_aligned主模板、宏的两个条件定义。namespace和宏定义可以分别共享实体身份，但不能合并掉不同物理位置。工作包另有100项源码构造义务、18项参数义务和72条关系。

独立stage审查发现初版五个放行缺口：丢条件分支、错owner回引用、丢函数属性、错namespace限定名、以重复namespace位置补足数量。修复后按精确selector多重集、独立身份、参数默认值和完整属性合同核对，14项正常与破坏测试通过。当前16处声明和10处工作包属性均关联canonical记录，生效的人工身份覆盖为0。详情见[接入与静态图审查](cute-alignment-stage-and-svg-review.md)。

类型表示契约与资源生命周期分开。接入后曾发现前端假设所有契约都含事件数组，导致无运行事件的类型契约页面报错；现已明确区分type_representation与value_predicate，不为类型约束伪造资源或时间序列。
