# Dense图集产物实现与验收边界

本记录说明生成器的实现及已做检查，不替代独立源码审查或实际浏览器验收。

## 从数据到离线视图

`build_atlas.py`读取同一组模块JSON，关联固定声明账本，并对所选签名作原文字节回切。明确的局部lambda和`pipeline_init_wait`作用域校正使用有源范围的人工补充；不借用不正确的全局实体ID。

配置实例与模板声明分开。实例页/实例note显示完整的实际类型表达式，模板API显示完整源码声明；不把一个已实例化类型伪造成新的源码声明，也不重复用泛型声明冒充具体绑定。

每条关系都有独立PlantUML和SVG。导航按来源API拆成至多两条出边的panel，原view的全部edge ID仍逐项保留。完整关系列表和API页提供相同源码实体的跨part角色链接；资源绑定不同的节点和调用点不因此合并。

全部824个库文件都生成独立的离线源码页。辅助例子、编译输入、类型输出和日志另行复制、散列并标为aux，不计入824分母。空日志给出明确的空文件页面，不伪造日志内容。

站点只载入本地CSS、JS和SVG，不使用CDN、服务端API或运行时fetch。SVG尺寸在构建时写入数据，页面无需访问跨文件的`object.contentDocument`。站内导航使用hash路由，避免依赖file文档的History API重写权限。

## 已发现并修复的展示问题

- 初版导航宽达3–5千像素。改成按来源API分组后，已测当前panel最大宽度低于800像素；不是把文字缩成不可读尺寸。
- 初版Host边把证据范围323–328的起点323当作调用点。现在分别保存范围证据和从原始表达式精确定位的callsite328。
- 初版配置实例重复显示泛型声明，目标Builder又缺少完整声明。现在二者各自显示实际类型表达式与真实偏特化完整源码。
- PlantUML对位于代码块第一列的`__device__`发生格式误读。源码note统一作纯排版缩进，所有原始token保留；`audit_atlas.py`检查SVG文本中存在完整签名/配置表达式。
- 独立审查发现长路径及标识符被从词中间断开。标签现按namespace、路径与参数分隔处换行；类型标题不再重复整段偏特化约束，完整声明仍保留一次。函数先显示操作名，再保留限定名。完整限定名也始终在API页提供。
- 调用点不能用行号元组作为唯一身份：同一行可以有多个相同表达式。现在用原文字节范围区分，校验作者指定的位置，保留context/caller；错误的作者范围不会被生成器悄悄替换。新增同一行重复调用和错误字节范围负例。

## 检查与限制

使用`rsvg-convert -b white`查看了Host initialize、Builder选择和TMEM free的原尺寸PNG。签名、源码路径、单一端点及调用点标记可辨，没有观察到裁切。PNG在`audits/dense-visual/`，对应具体生成版本；后续数据变化仍须重生成、复核。

`audit_atlas.py`检查文件分母、边端点、panel逐边对账、SVG完整签名文本、PlantUML错误、离线链接与源码行锚点，以及构建输入散列。`test_atlas_runtime.js`使用最小DOM double检查路由、检索、接口页、证据页与全文件导航。这些均不启动浏览器。

实际浏览器验证仍未完成。当前file页面访问被浏览器安全策略拒绝；随后的本地HTTP预览也被权限审核拒绝。没有用其他浏览器、间接页面加载或其他绕过方式继续。静态图片、代码单元测试与检查脚本不能被写成1366×768、1920×1080的实际交互验收通过。

最终模块使用验收需要在合规路径下获得真实界面观察，当前目标仍保持进行中。

## 向全库模块扩展

`data/module-registry.json`将824个文件分到20个唯一主归属模块。归属只决定导航和后续分工，不代表API代际、关系或协议覆盖；配置路径与文件归属分别存储。所有40个`.inl`均在清单内。

图集已接入模块目录与逐文件入口：文件页可进入固定源码以及当前已记录节点，模块页可检查已有跨模块关系。API检索同时支持记录中的配置目标、架构名称提示和模块类别。DOM单元测试覆盖这些行为，但不冒充实际浏览器验收。

资源契约目前有可追溯文字和逐关系图，专门的时序／状态分图尚未全部制作。此项仍在模块验收清单中，不能因已有事件列表而宣称完成。
