## 从源码反向检查的关键问题

此处是当前实现者的源码自查，不冒称独立评审者已完成使用验收。

1. **五步是否在中途换成另一种 GEMM？** 对照已保存示例的尺寸、α/β 与 Arguments，以及模块里的数据类型、Tile/Cluster和编译配置。页面始终显示同一配置；更换形状或目标的变异测试被拒绝。
2. **是否给 initialize 虚构了能力检查？** `gemm_universal_adapter.h:312` 起先做 workspace 初始化，再转换 Params，并处理属性设置错误；主线把 can_implement 放在调用方独立步骤，未添内部调用。
3. **是否把参数转换说成矩阵搬运？** `sm100_gemm_tma_warpspecialized.hpp:255` 起分别划分 workspace 并调用三个转换接口。主线明确转换不是执行 GEMM，也不是深拷贝全部矩阵。
4. **是否把 Host 直接连成 Device functor？** 保留 CUDA launch 的 `launches` 边与 `device_kernel→operator()` 的设备侧 `calls` 边，两者不混成同类同步调用。
5. **省略内部流水线后是否丢掉可读/复用条件？** Mainloop 的 `consumer_wait`、MMA 发起及后续输入释放仍有固定源码入口。主线要求同一资源、stage/phase 与参与范围对应，明确发起不等于完成。
6. **是否把输出源缓冲读完当成 Host 结果可见？** `copy_sm90_tma.hpp:1251` 的 `wait_group.read` 与应用 `cudaStreamSynchronize` 后复制 D 分开解释。本例 β=0.5，C 不能被当作不参与运算。
7. **是否把 update 当成完整初始化，或把错误返回当成资源已安全？** 主线保留 update 不调用 initialize_workspace、错误返回不证明设备停止、释放许可不等于 free 三条区别。示例的错误检查代码也不被当作全部异步清理情况已经验证的证据。
8. **是否用部分覆盖冒充方案或全库通过？** Scheduler 全分支、描述符内部与 Fusion 路径的缺口在相应步骤可见；额外场景仅作条件性追问，GPU及独立使用验收均明确未完成。
