## 核对的具体关系

三个接收右值Tensor的重载都把有名字的形参作为左值表达式转发。相应左值重载保留独立节点、完整签名与调用位置；未将同名函数合成一个接口。

`fill.hpp:60`的`decltype(fill(tensor.data(), value))`及其内部`tensor.data()`是不求值表达式，实际函数体调用在62行。84行只有一个物理分派位置，对应`prefer<1>`可行与替换失败后`prefer<0>`的两个条件候选，不能解释为先后调用两次。

`axpby`在元素循环前计算一次`isBetaZero`。89行两个`x(i)`和两个`y(i)`的位置分别保留；零beta与非零beta分支不同，写入引用与旧值读取不同。没有擅自规定同一个乘加表达式中独立操作数的求值先后。

`clear`调用的是`fill(tensor, T{})`，不是字节清零。三个文件没有声明具体Engine存储空间，也没有barrier或异步完成协议，因此未虚构SMEM、TMEM或全局同步事件。

## 反例、修复与回归

- 初稿将全部`evaluates`关系统一标为`symbolic`。两个`int i`的递增和固定`prefer<1>{}`、`Int<0>{}`并不依赖模板决议。已改为`source_proven`；for/if明确标为源码控制容器，其内部依赖表达式另记，不制造“未解析容器API”。
- 初稿只在语法义务中解释`CUTE_GCC_UNREACHABLE`，没有保留展开关系。`config.hpp:93–99`存在条件builtin、空展开与预定义覆盖三种情况，现已分别入图，并说明其词法位置在两个return分支之后；属性/pragma宏没有混成运行调用。
- 原图集匹配器使用行号元组去重，可能合并同一行的相同调用。现按源文件和精确字节范围区分，保留作者的context/caller，并拒绝错位原文。该公共规则另经独立审查，见[module-and-callsite-review.md](module-and-callsite-review.md)。
- 新契约引用既可以是API节点，也可以是关系ID。原页面只识别节点，关系会显示成不可点击的ID；原“事件顺序”列表还会使互斥候选看起来依次发生。现统一解析节点/关系引用，并将事件索引与有明确源码依据的先后说明分开。专用时序／状态分图仍是待办，没有用这一页面修复冒充完成。
