## 接口解释与参数分类

说明范围是已发布数据中全部 `api`、`type`、`external` 节点，共 316 个，其中 212 个可调用接口节点、79 个类型节点、25 个外部或概念边界。资源和硬件事件不因出现在图中就被当成可调用 API。

各接口有单独的所属层级、职责和执行说明。396 个真实函数形参、956 个模板参数出现位置、2 个宏文本参数逐项解释；模板出现计数包含不同方法共享的外层模板，不是独立模板参数的全库数量。

分类依据是参数在声明中的位置与类型语义：

- 模板参数在编译期确定；方法自己的模板参数与所属类型的模板参数分别显示。
- 普通函数形参是调用输入。`constexpr` 允许满足条件的调用进行常量求值，不强制每次都在编译期执行；`static` 和 `const` 也不是编译期参数标记。
- Shape、Layout、Tensor 等对象的类型信息与其动态值分别解释；不能认定函数实参中的所有信息都动态。
- `prefer<N>` 和 AutoCarveout 标签通过类型传递静态选择信息。
- 宏形参是预处理文本，不是运行时值或 C++ 模板参数。
- 未收录完整声明的外部接口明确保留这一边界，不把缺少参数列表解释成零参数。

参数解释来自分域核对的可编辑资料 `data/interface-notes/`。生成器发现缺少任一已有形参解释时会失败，不用通用占位填满计数。

## 发现与修复

1. 原参数账本把 `device_kernel` 的单个 `params` 拆成两项。展示层依据 `include/cutlass/device_kernel.h:118` 校正为一个参数，保留原数量、原文与校正原因，不改写底层提取账本。
2. 交叉审查发现部分 Adapter `execution` 说明复用了含 Arguments/stream 的句子。现分别说明 `update()` 没有 stream，两个 stream 重载使用已准备的 `params_`，不重新接收 Arguments。
3. PipelineTmaStore 的 Stages 说明曾套用具有 full/empty 屏障数组的 Pipeline 解释。其 bulk-group 等待机制与 mbarrier 数组分开说明，不能泛化到同名模板参数。

## 验证边界

总图的 23 项模型/源码/连线检查、接口说明的 12 项参数分类/覆盖检查，以及页面的 DOM-double 回归分别执行。源图、模板、解释资料与发布产物的散列在 `data/presentation-build-report.json` 对账；它作为独立展示层覆盖记录，不覆盖原源码构建来源。全站产物检查也包含新图和新说明的本地源码链接。

SVG 已静态渲染检查。没有启动真实浏览器，也没有绕过此前对 file URL 和 HTTP 预览的限制，因此不宣称已验证 1366×768 或 1920×1080 的实际交互和投屏。没有新增 GPU 执行、数值或性能验证。
