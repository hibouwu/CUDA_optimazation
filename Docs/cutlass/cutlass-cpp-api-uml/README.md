原全库目标已重新开启，当前优先服务现场方案验证。打开 [原图集入口](site/index.html) 先沿同一次 Dense GEMM 阅读问题范围、参数资源、工作分配、结果完成、复用失败五步；每步说明必要职责、交接条件和现场核对方式。`GemmUniversal` 接口总览、逐参数说明、独立调用点和源码仍保留为按需查阅的后续层次。[会议材料](meeting/index.html)另提供提问顺序和空白记录模板。

主线使用已保存示例中的 M=256、N=256、K=128、L=1，计算 D=AB+0.5C。主线的五步是审查顺序，不是所有组件的串行执行时间线；不能据源码或静态编译推断已通过 GPU 运行。主线内容保存在 `data/main-path-spec.json`，展示刷新会核对配置、引用与固定源码位置。[主线检查点](audits/main-path-review.md)分别记录机械检查、自查和仍未完成的独立使用验收。

主线的工作分配部分已接入选中Scheduler的任务描述、坐标、完整K、下一任务和Epilogue交接。两个fetch重载与两个Epilogue判定重载分别显示；当前分支的fixup为原样返回状态的空操作，不误写成必须归约或等待。[来源与未完成范围](audits/scheduler-handoff-review.md)保留CLC内部协议及其他调度分支的后续义务。

## 什么算一个接口

源码实体包括命名空间、类型、函数及每个重载、构造/析构、运算符、主模板及各个特化、别名、枚举及枚举值、成员、常量与影响接口的宏。函数内局部变量不是独立库 API；在状态或所有权关系中作为带位置的数据对象记录。

**身份与位置分开。** 每个声明/定义出现位置先独立记录；只有语义相同的实体才连接到同一身份。重载、限定符、模板参数形态、特化条件、匿名作用域及内部链接作用域不得因短名相同而合并。宏生成 API 同时保留定义位置、调用/展开位置及有效条件。

数据中分别使用 `entity_id`、`declaration_occurrence_id`、`variant_id`。实体相同但参数名或声明位置不同，不自动生成新实体；前置声明与定义只有在作用域、签名及模板身份匹配时才能归并，并保留归并证据。条件实现保留独立 variant。静态调用点独立使用 `callsite_id`，保存有效分支和实参到已知形参的绑定；目标尚依赖参数时记录已知绑定及精确缺口，不虚构形参。

实体必须保存完整限定名、签名、参数名及默认值、返回类型、模板条件、可见性、Host/Device/static/constexpr 等属性，以及仓库相对路径、字节区间和行号。跨文件的声明、定义和调用位置分别显示。

## 图中的线表示什么

关系种类分别记录：`includes`、`declares`、`member_of`、`inherits`、`aliases`、`specializes`、`type_uses`、`template_binds`、`has_attribute`、`macro_uses`、`expands_to`、`calls`、`reads`、`writes`、`launches`、`signals`、`waits_for`、`permits_reuse`。

- 每个调用点都有独立身份：源 API、目标或依赖表达式、关系类型、源码位置、有效条件。不同 API 不合并到一条边，同名重载不合并。
- Include 关系只连接文件；类型绑定不表示运行调用；异步提交不表示硬件完成；Host launch 不表示直接调用设备 functor。
- 声明属性连接到所属类型或字段；宏展开分别保存定义条件、参数绑定与展开后拼写。宏不是C++类成员，不给它标注public/private。源码字符串中的双引号按原义显示，不替换成字符字面量的单引号。
- 库外实体标为 `external`，仍保留能确定的限定名和来源，不猜成库内同名函数。
- `symbolic` 表示源码能确定的依赖表达式，必须带模板依赖/条件和原始表达式；`configured` 表示特定编译配置下确认的目标；`direct` 表示已经确定的非依赖关系。
- `extraction_error` 表示真正的提取失败；不得改名为 `symbolic`、从分母删除或在完成报告中隐藏。

目录导航分类不等于 API 代际。`.h/.hpp`、`threadblock` 路径、架构年代和“是否使用 CuTe”均不能作为代际判断的充分条件；混合文件可以具有多个经核对的接口标签。

### 不能用计数掩盖的缺口

独立保留原始候选账本：声明区间、宏调用/展开候选、预处理区域、静态调用表达式、类型引用和异步原语位置。每项必须映射到实体、关系或有源码依据的非API分类。文件数、生成实体数和导出边数不能互相替代，生成器不能自行删掉候选来缩小分母。

可接受的 `symbolic` 关系必须包含 callee/类型原始表达式、实参及其映射、可见候选或名称查找路径、依赖参数和约束、确定具体目标还缺的绑定。仅写 dependent/unknown 不是完整记录。宏只有定义或候选而没有生成实体时仍为未完成；每个宏生成接口需要定义、展开调用点和展开序号。`#if 0` 中的源码实体仍登记并标明恒假条件，不当作当前可运行接口。

异步协议记录至少包括资源身份、stage/index/phase、参与角色及条件、提交主体、完成主体、事务单位与计数、等待谓词和允许读取/复用条件。没有相关字段时给出具体“不适用”依据，不能省略；测试专用完成分支必须与正常路径分开。

后续门禁必须能拒绝：删宏生成operator、合并call重载、吞掉一个条件分支调用、将提取失败改为symbolic、删除异步phase、破坏相对源码链接。这些破坏测试只说明检查能发现相应缺陷，不替代全库对账。

每个实体有独立离线入口，边能跳到精确目标实体或显式外部/参数端点；从入口自动遍历全部文件、实体、关系与源码锚点，失效链接必须为零，并分别检查可读性、可追溯性和协议完整性。

## 按模块推进与全局完成条件

当前采用“全库统一建账、按模块贯通、最终全量汇合”。824文件的固定分母保持不变，阶段1到4按模块及必要依赖分别推进；已核实模块不再等待其他模块的声明缺口全部清零。尚不能确定的跨模块端点保留未完成记录，模块通过不等于全库通过。

[模块登记表](data/module-registry.json)将824个文件分配到20个唯一主归属模块。Dense等配置路径是跨模块阅读视图，不参与文件归属。所有40个`.inl`、内部`detail`和冷门接口均保留；模块划分规则、反例和后续扩展边界见[模块审查](audits/module-boundary-review.md)。网页提供模块目录、逐文件入口与相关关系，文件列表不再只通向源码页。

首先贯通Dense FP16、2SM、`sm_110a`的一条代表路径，验证源码身份、类型选择、调用、硬件协作与离线阅读方式。这是设计验收样本，不是覆盖证明。解析工具围绕固定快照实际出现的语法实现，不追求通用C++分析器；额外反例只有在影响该快照可信度时才形成必做回查。

0. 固定快照及824文件全集；独立从Git对象逐文件核对路径、内容、数量、模式和分类规则。
1. 全量源码实体及声明出现位置；未激活分支和宏生成接口仍进入清单，影响声明覆盖的提取缺口为零。
2. 全量源码关系；重载、特化、条件和调用点独立，困难样本的正反核对通过，真实提取缺口为零。
3. 跨层和异步协议；每项协议的参与者、数据、提交/完成/等待/复用事件有源码依据，不用一条Thor路径替代其他协议。
4. 离线HTML、SVG、PlantUML和源码浏览；全部实体和关系可达，无合并边、裁切签名或缺失跨图端点。
5. 重生成对账及独立使用任务；全部阶段缺陷关闭后才结束持久目标。

每个模块实行“制作→独立反例→修复→回归→使用验收”。声明、关系与有依据的非API分类分别记账；已证明属于调用的候选进入关系义务，不重复阻断声明。公共规则变化、模块完成及最终汇合执行相应全量回归；不重复建设未变化的阶段0快照。不以免责声明缩小最终目标，也不把有限实例的编译结果推广为全库或全部运行时行为证明。

## 构建入口

当前离线设计样本入口为 [site/index.html](site/index.html)。图集可在不访问CDN或服务端API的情况下读取；实际浏览器视口验收尚未完成，限制与未完成项见[进度](PROGRESS.md)。PlantUML源码与SVG由同一份模块数据生成，每条关系单独出图，导航只负责定位。

接口页同时提供离线源码行号与固定提交的GitHub原文链接。后者明确标注“联网”，不参与离线内容加载；没有网络时仍使用随图集打包的固定源码。共享namespace的不同物理声明位置分别列出，不因实体身份相同而丢掉文件入口。

侧栏“协议偏序与状态图”现提供Dense TMEM生命周期。不同API/CTA事件有独立身份和锚点；量词化先后、历史事实推导及配对参与判定分别表示。事件图同时保留PlantUML与DOT布局输入，SVG使用明确的行连接点；这不改变同一组源码约束。[模型与生成说明](audits/tmem-protocol-implementation.md)列明独立审查与未完成项。

```bash
.venv/bin/python scripts/build_module_registry.py
.venv/bin/python scripts/build_atlas.py
.venv/bin/python scripts/refresh_presentation.py
.venv/bin/python scripts/audit_atlas.py
node tests/test_atlas_runtime.js
```

最后一项是使用DOM double的代码单元测试，不代表启动过浏览器。PlantUML中的完整源码使用[官方代码文本语法](https://plantuml.com/creole#code)，渲染不依赖在线PlantUML服务。

仅修改当前展示时，单独运行 `scripts/refresh_presentation.py` 即可。它基于已经发布的 `data/atlas.json` 生成总图与语义过程图，不重新提取声明，也不改写原关系数据。模板、原图数据及新增产物的校验值分别记在 `data/presentation-build-report.json`，不能用展示更新冒充源码覆盖进展。完整构建之后也要执行这一展示刷新步骤。[本次展示审查](audits/overview-presentation-review.md)记录了范围与验收边界。
