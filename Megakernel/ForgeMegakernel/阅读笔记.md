# ForgeMegakernel：如何检查 agent 生成的 megakernel

核查日期：2026-09-21。原文固定为 [arXiv:2609.12379v1](https://arxiv.org/abs/2609.12379v1)，本地保存了 [PDF](sources/2609.12379v1.pdf)、[HTML](sources/2609.12379v1.html) 和 [来源清单](sources/manifest.json)。页码按 14 页 PDF 计数。

**最值得借鉴的是独立于生成者的检查机制。通过这些检查仍是有限测试证据，不能升级成对任意输入和硬件的正确性证明。**

## 方法的阅读入口

先读 §4.1、表 1，再读 §4.2、算法 1。作者用阶段要求指导 agent 建立 kernel 结构，由独立检查器检验数值、访存与精度。性能相关重点是每 SM 指令流、依赖计数器和共享内存缓冲池；中间数值检查利用 KV cache。

可以用这个自拟例子理解检查器：同一 batch 中请求 A 在位置 20，请求 B 在位置 80，kernel 错把两者都按位置 20 处理，那么“所有请求长度相同”的测试永远碰不到错误。测试必须主动制造不同长度并检查每条请求的位置语义。把不允许读取的 KV 区域改成噪声，也可以观察输出是否错误地依赖这些区域。

这解释了为什么增加测试维度有价值，也解释了边界：有限测试能排除被触发的错误，不能枚举全部错误程序。

## 精度检查能证明什么

§4.2 式 (6) 计算候选误差在额外舍入方向上的投影。设契约参考为 A，窄精度参考为 A′，方向 d=A′−A：

\[
\alpha=\frac{\langle K-A,d\rangle}{\langle d,d\rangle}.
\]

作者以 α≤0.5 为该项通过条件。下面是本次独立构造的数学边界检查：

- A=(0,0)，A′=(1,0)，因此 d=(1,0)。
- K=(0,100)，则 α=0，会通过这一项。
- 但 K 与 A 的距离为 100，不能由 α 推出整体误差很小。

脚本实际计算了这个例子。它说明**单个方向的投影不是误差范数上界，也不能仅凭输出推断全部内部运算宽度**。这不是完整 oracle 的绕过：论文还有其他数值、结构和功能检查。反过来，其他误差未必与 d 正交，所以归约次序变化不影响 α 也需要额外条件，不能作为普遍数学事实。

## 三个需要继续验证的边界

**MBU 分子是模型，不是自动测得的硬件事实。** 式 (2)–(3) 用估计字节量和峰值带宽归一化时间。应用到新模型时，要检查权重是否重复读取、KV 长度增长、缓存命中和写流量。理论字节量与硬件计数器覆盖的流量若不一致，比例可能失去原来的意义。大 batch 或其他模型也未必处于相同的带宽受限区域。

**两点差分计时需要解释上下文变化。** 原文用生成 80 与 16 token 的总时间差除以 64。对自回归 decode，它更自然地表示额外那段生成的平均边际时间；KV 长度增长时，不能不加说明地当作固定上下文 S 的一次 step 延迟。复现应保留逐步上下文、实际生成数和原始重复测量，检查字节量采用的长度。

**准确率接近不等于统计等价。** 表 2 使用 200 道题，一题对应 0.5 个百分点，1.5 个百分点只差三题。要验证“不劣于基线”或“差异来自噪声”，需要逐题配对结果、重复运行和明确的统计方法；汇总准确率不足以完成这一步。
