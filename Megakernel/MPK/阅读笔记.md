# MPK：从算子图到 GPU 内部的任务调度

核查日期：2026-09-21。原文固定为 [arXiv:2512.22219v2](https://arxiv.org/abs/2512.22219v2)，本地保存了 [PDF](sources/2512.22219v2.pdf)、[HTML](sources/2512.22219v2.html) 和 [来源清单](sources/manifest.json)。下文页码按本地 PDF 的 18 页版本计数。

**MPK 值得研究的核心是任务之间的依赖如何进入 GPU 调度过程。性能数字需要连同工作负载和计时定义一起读；目前检查了部分冻结源码，没有编译或运行 MPK。**

## 先抓住它解决的问题

设一个矩阵乘法产生两个输出块，后续通信分别发送这两个块。如果整个矩阵乘法结束后才启动通信，先完成的输出块也得等待。更细的依赖应当是“块 0 完成，允许发送块 0；块 1 完成，允许发送块 1”。这是理解 MPK 的自拟简化例子，不是论文实验数据。

MPK 用 task 表示工作，用 event 表示完成条件；编译器构造细粒度图，GPU 内部的 worker 和 scheduler 推进执行。它还通过共享内存分页支持任务间预取。详见原文 §3–5、图 4–8，PDF 第 4–9 页。

建议按这个顺序阅读：

1. 图 4：同一程序采用不同依赖粒度，会放出哪些并行机会？
2. 图 5–6：事件合并、规范化和线性化，如何把图变成设备端容易读取的描述符？
3. 图 7–8：提前安排任务和就绪后派发任务，各自节省什么，又可能在哪里等待？

## 怎样读实验结果

原文 §6.2–6.3 使用 A100、H100、B200，BF16，离线批处理，输入 64 token、输出 1024 token；其单 batch 加速范围为 1.0–1.7 倍。多 GPU 结果另见 §6.5，不能与单卡范围混用。

阅读时应区分：单条请求的逐 token 等待时间、整个 batch 的总吞吐，以及是否包含 prefill/调度/采样。batch 增大时，吞吐可以提高，但单条请求的等待时间未必同幅下降。

## 冻结复现脚本中的口径问题

以下检查限于指定提交的 H100 包装脚本和 Qwen3 Hopper demo，不能据此认定论文原始图表使用了错误数据。

**第一处：batch 分母不一致。**

- [run_sglang.sh](sources/artifact_snapshot/artifact_evaluation/H100/run_sglang.sh) 第 80–83 行：总时间 / `((input_len + output_len) * batch_size)`。
- [demo_hopper.py](sources/artifact_snapshot/demo/qwen3/demo_hopper.py) 第 734–735 行：总时间 / `(step.max() + 1)`，没有除以 batch size。
- [run_tgx.sh](sources/artifact_snapshot/artifact_evaluation/H100/run_tgx.sh) 直接解析 demo 打印值并保存。

假设两边都用 1088 ms 完成 batch=8、每条长度为 1088 的任务，这两种公式分别得到 0.125 ms 和 1 ms。这个 8 倍来自定义，没有执行速度差异。该自拟算例已经通过 [CPU 核查脚本](../verification/check_claims.py) 重算。

**第二处：声明的输入长度未被显式传入 demo。** 包装脚本保存 `prompt_len=64`，并把 64+1024 当作最大序列长度传入；demo 第 146–180 行实际使用文本提示和 tokenizer 产生输入。仅设置最大序列长度，不能证明实际输入恰好为 64 token。复现时必须保存实际 token 数。

**第三处：安装脚本不等于冻结环境。** [setup.sh](sources/artifact_snapshot/artifact_evaluation/setup.sh) 第 144–168 行对 Ampere/Hopper 选择 PyTorch 2.6.0/cu124，对部分新架构选择 2.7.0/cu128；`transformers`、`vllm`、`sglang` 的安装没有完整版本锁定。附录描述的环境不能仅靠今天重新执行脚本恢复。

## 下一步怎样真正验证

先固定一个模型、batch=1、实际 prompt token 数和输出长度，统一 prefill/采样计时范围，记录原始总时间和输出 token 数，再自行计算指标。输出正确后扩到 batch=8，以主动暴露分母问题。

GPU 执行前还需确认任务实现与目标架构兼容。本次没有运行安装脚本、修改上游代码或下载模型权重。论文的速度仍是作者实验结果。
