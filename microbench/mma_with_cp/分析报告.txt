使用路径真实性审查
1. 普通 dense GEMM 主路径主要是 SS：TMA/其它 loader 把 A/B 放到 SMEM，tcgen05.mma 直接消费 A/B SMEM descriptor，accumulator 写 TMEM。
2. SS MMA Mainloop K2/K4/K8/K16 是本报告最接近 CUTLASS/CuTe dense GEMM mainloop 的 sweep：同一 K tile 内连发多条 K-block SS MMA，再等待一次完成后才认为 SMEM stage 可复用。
3. TS CP+MMA Mainloop A2 K2/K4/K8/K16 是 TS A-from-TMEM 的专项 mainloop-like sweep：每个 K-block 发 cp(next A panel)+mma(current A panel) 并等待，保证下一条 TS MMA 消费的 TMEM A 已完成。它比 TS MMA-only 更真实，但仍不代表普通 dense GEMM 默认路径。
4. TS A-from-TMEM 是合法硬件路径，但更适合 FMHA、mixed-input GEMM 或其它需要 TMEM A 暂存/复用的专项算子；本文 TS CP+MMA 系列不应被解读为普通 dense GEMM 默认路径。
5. SS/TS MMA-only 是 forced-wait 诊断微基准：每条 MMA 后立即 commit+wait，故意破坏异步流水，只暴露单指令 completion/latency 成本；它不是峰值测试，也不是高性能 GEMM mainloop。

说明
1. cp suffix 和 effective bytes/cp 来自脚本配置；低精度 packed copy 的有效字节口径需要结合最终 SASS/NCU 再确认。
2. Serial A1 在每轮 cp 和 MMA 后都等待完成；Overlap A2 先预填一个 A slot，再由同一 issuer 交错发 cp(next) 和 mma(current)。
3. SS MMA Mainloop K2/K4/K8/K16 模拟 CUTLASS/CuTe 常见主循环边界：同一 issuer 连发多个 K-block MMA，再等待一次 MMA 完成后才认为 SMEM tile 可复用；cycles/MMA 用来观察等待成本摊薄是否进入平台期。
4. TS CP+MMA Mainloop A2 K2/K4/K8/K16 每个 K-block 都发 cp(next A panel)+mma(current A panel) 并等待；它测的是 TS A-from-TMEM 路径的稳态 K-group 成本，不是 SS dense GEMM 主路径。
5. Warp Split A2 使用 threadIdx.x==0 发 cp(next)、threadIdx.x==32 发 mma(current)，每轮等待两个 issuer 的 commit 完成。
6. SS/TS MMA-only 按每条 MMA 后 commit+wait 的 forced-wait completion 口径计时，目的是破坏异步流水并测单指令完成边界；删除 grouped/4Warp slice 后，所有 MMA TFLOP/s 都按完整 shape atom 统计。
7. TFLOP/s 只按 MMA 数学计算量计算；cp-only 使用 bytes/cycle 和 cycles/cp。
8. 生成源码中的 TS/cp PTX 语法依赖 CUDA 13.x tcgen05 支持，首次运行后需要以 cuobjdump 和 NCU 计数器校验。
