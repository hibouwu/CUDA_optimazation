Case semantics
- SS same baseline: one issuer sends 16 SS MMA instructions, then waits once.
- SS same noise: the same issuer sends N unrelated tcgen05.cp writes into unused A slots before each SS MMA.
- SS split control: threadIdx.x==32 sends SS MMA; threadIdx.x==0 only participates in commit. This isolates split-issuer wait overhead.
- SS split noise: threadIdx.x==0 sends the unrelated cp noise while threadIdx.x==32 sends SS MMA.
- TS same baseline: one issuer sends cp(next A slot) plus TS MMA(current A slot), then waits.
- TS same noise: the same issuer sends extra copies into the next A slot before TS MMA.
- TS split control: threadIdx.x==0 sends the required cp(next), threadIdx.x==32 sends TS MMA(current).
- TS split noise: threadIdx.x==0 sends required cp plus extra cp writes to next A while threadIdx.x==32 sends TS MMA.

Important interpretation note
This is a resource interference test, not a production GEMM mainloop. SS noise writes to TMEM slots that SS MMA does not consume. TS extra noise writes the next A slot, so it measures extra producer-side TMEM write pressure while the current A slot is read by TS MMA.
