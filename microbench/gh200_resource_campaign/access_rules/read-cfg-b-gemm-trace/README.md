# cfg_b 插桩 GEMM 与调用内时钟：阅读目录

这里只放指向上级真实文件的相对软链接，把这套探针的代码集中到一处，方便连续阅读。修改代码请改原文件，运行命令也照旧。新增或改名模块后补上链接；`find . -xtype l` 可以列出失效的链接。测试文件不放进这里。

理解某个具体实验时，先读该族 README 的逐轮表，再进入对应的实验模块和探针源码；底座工具按调用处查阅。

## 测什么

在完整 CUTLASS GEMM（cfg_a/b/c）上测 plain 完整时间和 dual 插桩时间线：每个 CTA 的工作坐标、各 tile 的阶段戳、首输出、等待累计等。R07/R09 测同一 kernel 的启动开销与调用内时钟。V09、C1 和 Q14 的 G3 实验都建立在这套探针上。

- `r18.cu`：物理网格匹配的完整 GEMM 探针，显式 lda/ldb/ldd、warm 协议、dyadic 精确抽样检查，记录实际工作坐标。它 include `gaps_common.hpp`（显式 stride 与 padding）、`v06_trace.hpp`（dual trace）和 `r09_plain_prefix_host.hpp`（plain 前序）；`r18_trace.hpp`、`r18_first_output.hpp` 是插桩头。
- `r09_plain_prefix.cu`／`.h`：共用的 plain 前序模块（common-sw1-16）。
- `r00_cutlass.cu`：固定的 CUTLASS kernel 类型。`r07_probe.cu`（启动开销拆分、负载下时钟）和 `r09_probe.cu`（调用内时钟与阶段拆分）基于同一 kernel。`r09_probe.cu` include 的 `r09_trace.hpp` 由 `r09_run.py` 的 `TRACE_HEADER` 给出，`make_overlay()` 在构建时把它写入构建目录，阅读时直接看 `r09_run.py`。

## 阅读顺序

1. 骨架：`case_inputs.py`（按 r18 默认规则解析一个 case）→ `v06_run.py`（prepare→build→setup→calib→freeze→heldout 的通用 runner，44 个模块使用）→ `run_r18.py`（R18/R19 采样）→ `analyze_r18.py`（独立数值重放与逐 CTA tile／事件分析，62 个模块使用）→ `run_v08.py`。
2. 时钟：真正读钟（`clock64`／`globaltimer`）与控制依赖的实现在 `r09_clock_stamp.cuh` 和 `cfg_c_gt_bracket.cuh`；runner 为 `r07_run`／`r07_analyze`、`r09_run`，以及 guarded 时钟观察 `prepare_r09_guarded_clock`／`decode_r09_clock_observer` 与 plain 前序审计 `r09_plain_prefix_audit`。
3. 插桩变体：`prepare_*` 从冻结源码派生观察构建，`decode_*` 是对应的严格解码器。包括首输出、R13 累计等待与等待反馈、cfg_c GT 包围与 producer tail，以及 CUTLASS 阶段边界。

大型分析（`analyze_r10`、`analyze_r13_supply`、`analyze_r15` 等）和模型代码（`supply_model`、`v08_model`、`cfg_b_composition`）以这里的解码结果为输入，不在本目录。

## 现行代码与历史快照

各轮次目录的 `source/` 保存当轮的源码版本（有些轮次只做了准备，没有执行），本目录链接的是现行版本，二者不一定相同。本目录用于阅读现行实现。重建或重跑历史测量时使用当轮快照，旧路径入口需要时使用兼容视图（`flat_layout_view.py`）。已有数据的 CPU 重评分按各族 README 中经过验证的入口执行。

表中“主要使用示例”先列直接研究该模块的实验族，再按各轮记录（plan、README、脚本等，不含回传数据）提到该模块的轮次数补足，最多列四个族，用来提示依赖关系，不等于实验归属的完整判断；`cfg-b-composition` 的组合交付包引用了大量模块，没有列出。
